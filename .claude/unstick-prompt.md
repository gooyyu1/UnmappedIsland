# 詰まりを解く係のプロンプト

**デーモンは生きているのに盤面が進んでいない**ときに立つ係の本文。投入するのは盤面
（[`board-move.mjs`](../scripts/agent/board-move.mjs) の `CYCLES` の `unstick`）で、**進んでいない
状態が続いたとき**に立つ。渡し方は [`dispatch-chore.sh`](../scripts/agent/dispatch-chore.sh)。

**このPCで走る。** 何が転んだかが残っているのは `~/daemon.log` と `~/.claude/board-state` で、
どちらもクラウドの箱には無い（[`board-design.md`](board-design.md) 2.21）。

**デーモンが落ちているときは立たない。** 落ちた跡から起こすのは起こす係（2.19）で、**この係を
立てるのはデーモン自身**——立っていること自体が「デーモンは生きている」の証拠になっている。
二重に手を出す形にならないのは、この背反による。

題は下の `題:` の行が持つ（[`board-design.md`](board-design.md) 2.9）。

題: 点検 盤面の詰まりを解く

---

````
[デーモン] 盤面が進んでいません。原因を特定して直してください。

まず `CLAUDE.md` と `.claude/board-design.md` を読んでください。

**あなたが立っているということは、デーモンは生きています。** 落ちていれば、あなたを立てる者が
居ません。だから「デーモンが止まっていないか」は調べる必要がありません。

## 何が起きているか

デーモンは周ごとに、盤面から打つべき手を並べて、上から順に**打てた最初の1手**で切り上げます
（`.claude/board-design.md` 2.3）。**あなたが立ったのは、次のどちらかが続いたから**です。

- **盤面を引けない周が続いた**（GitHub か CCR から引けない）
- **打つべき手が在るのに、手綱以外の理由で1つも打てない周が続いた**

**人が手綱で止めている周は、ここに数えられていません**（`scripts/agent/brake.sh` が終了コード3で
名乗ります）。だから「ユーザーが止めているだけでした」という結論にはなりません。

## 調べる先

| 何を | どこ |
| --- | --- |
| 何が転んだか | `~/daemon.log`（新しいほうから。`打てなかった:` と `盤面を引けなかった` の行） |
| いつから進んでいないか | `~/.claude/board-state/taken.json` の `stuck:since` |
| 今の盤面 | `bash scripts/agent/board.sh` |
| デーモンの生死 | `bash scripts/agent/daemon.sh status` |

**転んだ手を、実際に手で打ち直して確かめてください。** ログに残るのは「打てなかった」までで、
理由はそのスクリプトの標準エラーにしか出ていません。`DRY_RUN=1` を付ければ立てずに引数だけ見られます。

```
DRY_RUN=1 bash scripts/agent/dispatch-task.sh <番号> /dev/null
bash scripts/agent/may-dispatch.sh new-task task-<番号>
bash scripts/agent/brake.sh new-task
```

## よくある形

**これは手掛かりであって、当てはめる型ではありません。** 合わなければ自分で追ってください。

- **ブリッジの環境IDが消えている。** PCを開き直すと前のIDは存在しません
  （`scripts/agent/ccr-env.sh`）。`env:bridge` の投入だけが通らない形で出ます。
- **CCRの資格情報が切れている。** `~/.claude/.credentials.json` を貼り直せるのは Claude Code 本体
  だけで、**デーモンにもあなたにもできません**（2.3.1）。この形だと、そもそもあなたが立ちません
  ——立てるのに CCR が要るからです。**引けない周が続いた跡だけが残っている**なら、これが済んだ後
  です。
- **盤面が出した手と、打つスクリプトの食い違い。** 直接 push で片方だけが新しくなると、噛み合わない
  まま毎周転びます。

## 直す

**変更は `main` へ直接 push してください**（出どころ: ユーザーの指示・2026-09-06。
`.claude/decisions/2026-09-06-daemon-watchdog-commits-straight-to-main.md`）。**PRにすると、盤面が
詰まっている間はマージされないので直しが届きません。** 直せるのは `.claude/**`・`scripts/agent/**`
の範囲です。

- **コミットには自分のセッションIDを名乗ってください**（`CLAUDE.md`「コミットには自分の
  セッションIDを名乗る」）。
- **push の前に `npm run lint` / `npm run typecheck` / `npm test` / `npm run format:check` を
  通してください。** `main` を直接壊すと、開いている全部のPRが赤くなります。
- **デーモンを止めないでください。** 走っているデーモンは、`main` が動けば次の周に自分で新しい版へ
  入れ替わります（2.3.2）。どうしても要るときだけ `bash scripts/agent/daemon.sh restart` を打ち、
  打ったことを報告に書いてください。
- **セッションを立て直さないでください。** 投入するのは盤面で、原因が消えれば次の周に自分で打ちます。
  あなたが立てると、同じ仕事に2本立ちます。

## 直せないとき

**ユーザーはこのセッションを見ません。** 訊いて待つことはできないので、次のどちらかで終わります。

- **人にしか直せない**（資格情報・ブリッジを開き直す・手綱の issue が壊れている）→ **issue を1本
  立てて、`判断待ち` と `origin:agent` を付けてください。** 題は `詰まり: <何が止まっているか>`。
  本文には、**リポジトリを開かずに答えられるだけの文脈**（何が転んだか・打った手・返ってきた言葉・
  人に何をしてほしいか）を書いてください。
- **直すのに1セッションぶんの仕事が要る** → **issue を1本立てて `origin:agent` を付ける**
  （`kind:` は付けない。分類は棚卸しの仕事です）。本文は `.claude/parallel-work.md` 3節のタスク
  issue の型に従ってください。

**同じ issue を毎回立てないでください。** 立てる前に、同じ題で始まる open の issue が無いかを
`gh issue list --state open --search '詰まり:'` で確かめ、在れば**本文へ追記するのではなく、
コメントで今回の観測を足すだけ**にしてください。

## 直したかどうかにかかわらず、報告する

最後に、次を書いて終わりです。

- いつから進んでいなかったか
- 何が転んでいたか（打った手と、返ってきた言葉）
- 何をしたか（push したコミット・立てた issue の番号・`restart` を打ったなら打ったこと）
- **直ったことをどう確かめたか。** 転んでいた手を手で打ち直して通ることを見るか、次の周が進むのを
  見るか。**「直したはず」で終わらせないでください。**

## 守ること

- **`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わないこと。** 自動承認ができず、
  呼んだ分がそのままユーザーの手作業になります。
- **PRを作らないこと。** この係の直しは `main` へ直接入ります。
- **盤面の詰まりと関係のない直しをしないこと。** 気づいた別の問題は issue を立てるだけにしてください
  （`origin:agent` を付ける。`kind:` は付けない）。
````
