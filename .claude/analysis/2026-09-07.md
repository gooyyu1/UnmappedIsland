## 傾向

### 書かれた主張を、どの検査も引き受けていない

**主張が置かれているのに、それを守る検査が無いか、在っても実際には働いていない**形。今回の帯で5本。

- **在るが、違う面を見ている** — #1746（`cheapestStackOf` を押さえているのは `stats/terrain.yaml` の
  丸ごと比較だけなので、DPの誤りと世界の変化が同じ形でしか出ない）
- **そもそも無い** — #1785（`WINDOW_DAYS` の「奇数であること」・`middleDay` の「`from` は `to` 以前」が
  どちらもコメントだけの契約で、破れても図が黙って歪むだけ）・#1760（`run()` に足した `env` 引数を
  どの呼び出しも渡していない）
- **在って正しい面を見ているが、走らない・読まれない** — #1784（`describe.runIf(PYTHON !== undefined)`
  なので、python の無い環境では「通った」と「走っていない」が区別できない）・#1748（`UNMENDED` を
  出しても読む者が居ない。かつ `gh pr comment` の失敗側はスタブが常に成功なので、緑のまま壊せる）

**3つ目は、上2つと違って検査そのものは正しい**ので、読み直しても欠陥が見つからない。効くのは「この
検査はいつ走るか」「この出力は誰が読むか」を別に問うことのほう。

### 同じ約束・同じ主張が、別の場所へ写される

今回の帯で3本。**読み手が1つ増えたときに倣う先が1箇所に無い**形。

- #1746・#1775 — 宣言を読み上げる定型が、それぞれ4箇所へ書き下ろされている
  （`(declaration as PassiveDeclaration).read(collector)` が `tickDeltas`・`activityHours`・
  `dailyPhases`・`daylight`、`for (const branch of everyBranchOf(reading)) branch.read(this)` が
  `effectQueries`・`voyageForecast`×2・`activityHours`）。#1792 として切った
- #1751 — 消した `mergedStatuses` と同じ畳み方が、試験（`shownStatuses.test.ts`）の側へ写された

**主張そのものが写される形もある。** 「クラウドのセッションは GitHub の REST が塞がっている」は、
取り決め（`.claude/parallel-work.md`・`board-design.md`・`triage-prompt.md`）・人間向けの全体像
（`docs/ParallelAgents.md`）・実際に投入先を選ぶ実装（`scripts/agent/board-move.mjs` の `CYCLES`）の
**3つの層に9箇所**あり、#1767 の実測が覆した時点で全部が同時に嘘になった。

**この形を数えるときは、層をまたいで引くこと。** 同じ主張は置き場ごとに言い回しが変わる（「塞がって
いて張れません」「書き換えられない」「丸ごと塞がって」）ので、1つの層だけを grep すると足りない数が
出る。**しかも縛りを実際に効かせているのは実装の層**なので、取り決めだけを直しても盤面は古い根拠で
動き続ける。

### 差分の外にある記述のずれが、見つかっても誰にも回らない

`.claude/review-criteria.md`「止めないもの」の**「元から在ったずれ」**が、今回の帯でもスメルの最大の
出どころ（#1786・#1785・#1783・#1779・#1772・#1771・#1770・#1769・#1768・#1761・#1752・#1746）。
止めない判断は正しい（入れても嘘は増えない）が、**気づいた者が直さない仕組みなので、拾う口はここ
しか無い。**

**散らばるとは限らず、1つの文書へ集中する形がある。** `docs/HowWeGotHere.md` へは6本のPRから点が
挙がり、そのまま1件の issue（#1789）の箇条書きになった。集中する条件は「短期間に何度も書き換わる
こと」に見える——この文書を触ったPRは、今回の帯だけで #1786・#1785・#1784・#1783・#1779・#1768・
#1760・#1754 の8本ある。本文の名指しが表・図の現物へ追いつかないまま次の書き換えが載る。
**同じ形が道具の側（`scripts/historyStats.mjs`、#1790）にも出た**ので、分かれ目は文書かコードかでは
ない。

言えない」としてこの線引きを既にレビュアー側へ割り当てているので、仕組みの穴ではなく、レビュアーが

### 数え上げ・列挙が、禁じられているのに繰り返し混入する

`CLAUDE.md`「数え上げを書かない」が明文で禁じているのに、レビューが毎回見つけている。今回の帯で
6本——#1785（試験の閾値 `4 * 2` がパネル数と区切りの数）・#1783（図の段の列挙）・#1769（「2 節の
11 本」）・#1755（「立てた丸太が2つ」）・#1751（「居心地・連れ・孤独」の列挙）・#1746（issue 本文の
系統番号）。

**うち #1755・#1751 は同じ周の中で著者が直している**ので、指摘されれば直る。止まっていないのは
**書く時点**のほうで、`policies.md`「仕組みの作り方」が「キーワード照合は取りこぼしと誤検知が同時に
出てどちらも見えない」と既に書いているので、機械で止める形は採れない。**#1751 では、その数え上げが
実際に嘘になった状態でレビューに掛かっている**（列挙した3つ以外に `travel_delay`・`ignition_ease` が
当たっていた）ので、害が出るまでの距離は短い。
