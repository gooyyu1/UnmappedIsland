**分析係の周ではない。** [issue #1618](https://github.com/gooyyu1/UnmappedIsland/issues/1618) で、
新形式 `[スメル] ` が始まる前に書かれた気づきを1回だけ拾ったもの。以後この形式は現れないので、
**旧形式の読み方は仕組みとして残していない。**

## 傾向

### 兄弟探しが、現物ではなく綴りで引かれる

**この範囲でいちばん多く現れた形。** 「同じ誤りの兄弟」を探す grep が、対象の性質ではなく**その時
書かれていた語形**で引かれるため、同じ誤りの別の言い回しが毎回漏れる。

- PR #1470 — 検索語が「最上段か」を機械で見ず、先に手で絞った4つの段の名前だったので、`in_stage`
  75本のうち71本しか分類されず2本が落ちた
- PR #1463 — 3役揃いの列挙しか拾わない検索語だったので、2役だけを写した4箇所が漏れた
- PR #1466 — 節番号の並記と「同じ／共通」でしか引かず、単一の文法名を挙げる形が漏れた
- PR #1469 — 語形で引いたので、同じ事実を別の側から書いた1行が落ちた
- PR #1492 — 「combinationsの**相手**」という語形に検索語が当たらなかった
- 同じ形が PR #1425・#1427・#1461・#1493・#1508 にも出ている

`CLAUDE.md` 3節は「YAMLの定義誤りなら同じファイル・同じ種類の定義を、コードなら同じ役割を持つ他の
経路を見る」と、**探す対象の性質**は指している。落ちているのは**引き方**のほうで、`grep` で引く以上
検索語は綴りになる、という段が繋がっていない（2026-09-06 時点）。ただし `review-criteria.md`
「止めないもの」が兄弟の残りを止める理由から外したので、**漏れが周回を生むというコストは既に
消えている**——残っているのは、漏れたぶんがスメルとしてここへ流れてくることだけ。

### 数え上げが、数え上げを消して回るPRの中で作られる

この範囲のPRの多くが「数え上げをやめる」を主題にしているのに、その本文が自分で数を書いて外している。

- PR #1461 — `## 自己点検` が「指摘は4件」と書いた下に5件並ぶ
- PR #1467 — 「3件で、すべて反映しています」の下に4件並ぶ
- PR #1463 — 「外のレビュアーからの申し送り2件」の下に1件しかない

現物の側にも残っていた（#1678 として切った）。**数を書ける場所が本文・コメント・コードのどこであれ
同じように腐る**、という形。

### セッションが立てた issue の本文が、そのPRの最終形と食い違ったまま残る

PRが走っている途中で立てた issue は、その後の周で方針が変われば嘘になる。立てたセッションは
**クラウドでは既存 issue の本文を書き換えられない**（`.claude/parallel-work.md`）ので、直せるのは
棚卸し（ブリッジ）だけ。

- PR #1497 — #1478 の「囲いが押し上げるのは `comfort` +20」が、2周目で `company: 1` に変わって嘘に
- PR #1507 — #1338 に写した見立てが、獲得免疫を勘定に入れていない誤りのまま
- PR #1469 — #1446 の題が「5箇所」のまま、本文と担当は9箇所
- PR #1508 — #1514 の前提（`weight` の積）が、積そのものが使われなくなって成り立たない
- PR #1442 — #1393 が、投入前に既にマージ済みの版で直っていた

### 同じ指摘が、周をまたいで何度も再掲される

- PR #1406 — 同じ申し送りが3周続けて（レビュアー自身が「二重に立てないでください」と添えている）
- PR #1425 — 同じ「気になった点」が2周連続
- PR #1492 — 同じ仕組みの話が3周・4周・5周と3回再掲
- PR #1508 — 前の周の「気になった点」3件が、次の周の本文で触れられてもいない

**この形は、この係が在ることで既に解けている。** 今は「直す側は何もしない。マージ後に分析係が
拾う」と決着しており（`.claude/parallel-work.md`「マージ済みのスメルは、分析係が拾う」）、
レビュアーも前の周の指摘を引き継がない（`.claude/review-prompt.md`）。

### セッションが立てた issue が、タスクの型を満たさないまま投入される

- PR #1441 — #1362・#1435・#1436・#1446 のいずれにも `## 完了の条件` が無い
- PR #1455 — #1386 に `## 担当` も `## 完了の条件` も無い
- PR #1463 — #1435・#1458 に `## 完了の条件` が無い
- PR #1508 — #1488 に `## 担当` と `## 完了の条件` が無い

**これも既に解けている。** 配る対象が `kind:task` に限られ、セッションは `kind:` を付けられないので、
型を満たさない issue は必ず棚卸しを通り、棚卸しが投入前に足りない節を足す
（`scripts/agent/board-move.mjs` の `CYCLES` と `.claude/triage-prompt.md`）。

### 盤面の道具どうしが、同じ段取りを写して持つ

新形式の帯（#1524〜#1593）でいちばん多かった形。**スメルの半分近くが `scripts/agent/**` と
`.claude/**` の重複を指している。**

- PR #1573（3周続けて）・#1539 — 投入の3本が投入先を選ぶ分岐を写している（#1680 として切った）
- PR #1528・#1555 — 判定コメントと `## 見た目` の綴りが、ひな形・設計文書・盤面の道具の3箇所にある
- PR #1526 — `DECISIONS_THRESHOLD = 10` が、フック・Copilot の起動・試験の3箇所に別々に置かれている
  （Copilot 側には検査が無いので、片方だけ動かしても気づけない）
- PR #1590 — `HERE` を解くお決まりの3行が11本へ同じ形で並んだ（`.claude/hooks/*.sh` にも残る）
- PR #1547 — `board-move.mjs` の `TASK` はひな形を読ませ、`REVIEW` は中身を埋め込む

**綴りを写す形と、段取りを写す形は別に扱ったほうがよさそう。** 前者は片方だけ変えると黙って外れる
（`reviewVerdictOf` が `通してよい` を名指ししなかった件はこの形だったが、判定をラベルで読むように
変わって解けている）。後者は外れないが、直す人が3箇所を覚えていないといけない。

### 数え上げは、数え上げを消して回るPRの中でも作られ続ける

旧形式の帯で見た形が、新形式の帯にも同じ密度で出ている。

- PR #1526 — `HowWeGotHere.md` の「判定は3値」
- PR #1546 — `Bedding.md` の「地面の上で比べられるのは3つだけ」
- PR #1559 — `parallel-work.md` の「7段」
- PR #1589 — 「告げ方は2つあり、観測口は1つです」が2箇所（**増やす変更が必ずこの2行で
  コンフリクトする**とレビュー自身が書いている）
- PR #1578 — `parseCommon.ts` のモジュール説明が引き手の領域を書き写している
- PR #1580 — `BalanceStats.md` が判定できる葉を列挙で書いている

**この形は消える気配が無い。** 消して回る issue が何本も走った後の帯でこれだけ出ているので、
「書かない」と決めただけでは止まらず、書けてしまう場所の側に手が要る、と読める。
