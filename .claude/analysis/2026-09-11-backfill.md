## 傾向

**この帯で繰り返し現れた形。** 根拠に挙げたPRは、**そのPRのコメントに実際にその中身が在るか**を
当て直してある。

### 主張は置いたが、破れたときに落ちるものが無い

**この帯でいちばん多い形。** 契約・不変条件・決めごとをコメントや宣言のそばに書き、それを守るものを
同じPRで置いていない。書いた時点では本当なので、**破れても誰も気づかない。**

- PR #1721 — `liquid_containers.yaml` の「`pour_into_empty` より先に書く」。順そのものを見る検査が無い
- PR #1694 — ローダー全体の契約「渡した Document は書き換えない」。見張りは同梱ぶんを通す2本だけで、
  同梱は `patch_object_defs` を1つも持たない＝**主張の面を見ていない**
- PR #1709 — `daemon.test.ts` の試験の名前は「走るのは複製で、リポジトリの1本ではない」だが、見て
  いるのは複製が置かれたことだけで、**走っている実体がどちらかは見ていない**
- PR #1681 — `countDecisions` の既定の経路（`archive/` を除く・`.md` だけ数える）を誰も通していない
- PR #1713 — 台帳に指紋が無いレビューを畳む経路に、留める試験が無い
- PR #1740 — `toBeGreaterThan(0)` に添えたコメントが、実際には隣の行が捕まえているものを説明している

**6本のPRに独立して出ている。行き先は3つに割れた**——二次の係が要るのは「何本が今も立っているか」なので、
潰れたものと、立っているが先回りしないものを混ぜない。

- **もう立っていない**のは PR #1681・#1713 のぶん。`countDecisions` は実物のディレクトリを数える検査が
  在り、畳む経路は `board-move.mjs:678` の条件を崩して赤くなるのを見た
- **今も立っていて、手を打つべきもの**が PR #1721・#1694 のぶん。#1974 として切った
- **今も立っているが、直し方に判断の余地があるので先回りしない**のが PR #1709・#1740 のぶん
  （`## 落としたもの` の最後の区分に在る）。`daemon.test.ts` は今も複製が置かれたことしか見ておらず、
  `bashFromTests.test.ts` のコメントの掛かり先も動いていない

**つまり、今も立っているのは6本のうち4本。**
`CLAUDE.md`「置いた主張は、破れたときに落ちるものと対で置く」と、push の手前でそれを問う段
（PR #1901）は**この帯より後に入っている**ので、この帯はその手当てが入る前の状態を見ていることになる。

### 判定が字面の一致で書かれていて、同じものの別の書き方が外れる

対象の性質ではなく、その時そこに書かれていた綴りで引いている。**取りこぼしと誤検知が同時に出て、
どちらも緑のまま。**

- PR #1681 — 二重起票の見張りが、題の前方一致と GitHub の CJK 検索に依る（#1978）
- PR #1699 — 作業ツリーの登録の有無を `grep -Fxq` の**バイト単位の完全一致**で決める
- PR #1740 — `bash` の起こし方を正規表現で引くので、`['-lc', …]` も止め、在り処を変数へ置くと抜ける
- PR #1697 — 止めたい対象をバッククォートだけで名指しする（理由としては「シェルの展開」を挙げて
  いる。#1979）
- PR #1736 — 出どころの印で、囲みの中身を残したことと「隙間に数字を挟めない」が相互作用する

**5本のPRに出ている。当て直しで潰れたものは無く、全部が今も立っている**——PR #1681・#1697 のぶんを
#1978・#1979 として切り、残る PR #1699・#1740・#1736 のぶんは直し方に判断の余地があるので落とした

任せ、既に壊した実績のある操作は機械で止める**と決めているが、ここで挙がっているのは全部**機械で
止める側**で、その中での引き方の粗さが残っている。

### PR本文が、同じ本文の別の節や現物と食い違ったままマージされる

`CLAUDE.md`「PR本文は最後に、実際のdiffから書く」が守られていない形。**マージ後は書き換えられない**
ので、残るのは誤った記録だけになる。

- PR #1705 — 本文の箇条書きが実装の段の順と逆（同じ本文の `## 自己点検` が逆の順を書いている）。
  さらに `## ユーザーへ` が、同じ周の差分が落とした前提のまま
- PR #1691 — 方針を丸ごと差し替えたユーザー本人のコメントが `## ユーザーの指示` 節に無く、本文だけを
  読むと前の周の判定に自分で答えを出したように読める
- PR #1740 — 受け方を変えた理由が、本文とコミット本文の両方で事実と違う（`execFileSync` と
  `spawnSync` で判定は前後一致している）
- PR #1736 — `## 仮決め` が挙げた `typecheck` の赤が、その時点の `origin/main` で既に解消していた

**4本のPRに出ている。4本とも issue にしていない**——立っている／潰れたの別ではなく、**マージ後の本文は
書き換えられず、読み返す者も居ないので直す先そのものが無い**（`## 落としたもの` の「直す先が
リポジトリの中に無い」）。食い違う相手は同じではない——PR #1705 は同じ本文の別の節どうし、
PR #1740 と #1736 は本文と現物、PR #1691 は節そのものの欠け。**共通しているのは、どれも
最終diffと届いた指示を読み直す段で見つかる**こと。

### 差分の外で見つけたずれが、止められずにスメルへ流れてくる

**この帯のスメルの多くが「元から在ったずれ」「この差分が作ったものではない」と自分で断っている**
（PR #1685・#1693・#1695・#1697・#1699・#1700・#1721・#1727・#1732・#1739 ほか）。
`review-criteria.md`「止めないもの」と `board-design.md` 4.5.1「新しく止めてよいのは前の周以降の差分
だけ」がそう決めているので、**設計どおりに流れてきている。**

**傾向として書くのは、それが拾う側の仕事の形を決めているから。** 差分の外のずれは**そのPRのマージ後も
そのまま現物に残る**ので、拾う側は当て直しをしなければ「今も立っているか」を言えない。実際、
`## 落としたもの` の最初の区分——**当て直しで潰れていたもの**——は、どれも後続のPRが別の用で触った
巻き添えで消えている（#1770 が槍の軸を移した、#1849 が窓を期間へ変えた、`watch-routine.sh` が消えた、
など）。**番号だけで並べると、次に読む者が全部を引き直すところから始めることになる。**

**当て直した結果は、「潰れた」と「立っているが手を出さない」に割れる。** 混ぜると、二次の係が
「この形は何本のPRに今も在るか」を数えられない——`## 落としたもの` を区分ごとに分けてあるのは
そのためで、`## 傾向` の各節も行き先を割って書いた。
