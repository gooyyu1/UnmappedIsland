## 傾向

**[`2026-09-06.md`](2026-09-06.md) に既に在る形へは、そちらの節へ観測を足した。** 足した先は
「同じ約束・同じ値が、読む側や別の宣言へ写された」と「差分の外にある記述のずれが、見つかっても
誰にも回らない」の2つ。下は、この帯で初めて見えた形。

**根拠として挙げたPRは、2つとも当て直してある**——**そのPRの判定コメントに実際にその中身が在るか**と、
**そのずれが今も現物に在るか**。片方でも通らなかったものは落とした（**最初の版では、通っていない番号が
いくつも混ざっていた**——出どころのPRが別の話をしているもの、現物では既に直っているもの、対象を
取り違えているもの）。**番号だけで並べると、次に読む者が全部を引き直すところから始めることになる。**
現物では直っているが挙がった事実に意味があるものは、**直っていることを添えて**残した。

### 兄弟探しが、現物ではなく綴りで引かれる

**この範囲でいちばん多く現れた形。** 「同じ誤りの兄弟」を探す grep が、対象の性質ではなく**その時
書かれていた語形**で引かれるため、同じ誤りの別の言い回しが毎回漏れる。

- PR #1470 — 検索語が「最上段か」を機械で見ず、先に手で絞った4つの段の名前だったので、`in_stage`
  75本のうち71本しか分類されず2本が落ちた
- PR #1463 — 3役揃いの列挙しか拾わない検索語だったので、2役だけを写した4箇所が漏れた
- PR #1466 — 節番号の並記と「同じ／共通」でしか引かず、単一の文法名を挙げる形が漏れた
- PR #1469 — 語形で引いたので、同じ事実を別の側から書いた1行が落ちた
- PR #1492 — 「combinationsの**相手**」という語形に検索語が当たらなかった
- 同じ形が PR #1425・#1427・#1461・#1508 にも出ている

**漏れる理由がもう1つある——掛け先。** PR #1493 は `_find` を `docs/` と `sample-pack/` へ掛け、
**倍率を掛ける当の場所である `src/assets/world-codex/` へ掛けていなかった**（レビューが
「`grep -rn "_find" src/assets/world-codex/` を通していれば最初に出た」と書いている）。語形が正しくても
掛け先が外れれば同じだけ落ちるので、**引き方の穴は綴りだけではない。**

`CLAUDE.md` 3節は「YAMLの定義誤りなら同じファイル・同じ種類の定義を、コードなら同じ役割を持つ他の
経路を見る」と、**探す対象の性質**は指している。落ちているのは**引き方**のほうで、`grep` で引く以上
検索語は綴りになり掛け先は手で選ぶ、という段が繋がっていない（2026-09-06 時点）。ただし
`review-criteria.md`
「止めないもの」が兄弟の残りを止める理由から外したので、**漏れが周回を生むというコストは既に
消えている**——残っているのは、漏れたぶんがスメルとしてここへ流れてくることだけ。
