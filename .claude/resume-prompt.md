# 止まったセッションを起こすときの本文のひな形

デーモンが `send_message` へ渡す本文。**組み立てるのは
[`resume-session.sh`](../scripts/agent/resume-session.sh)** で、下の ``` の中を読んで `<番号>` を
埋める。**書き足すものは無い**——起こす理由は盤面から機械的に決まり（`board-move.mjs`）、
そのPRで何が起きているかは、起こされた本人がPRを見れば分かる。

つまり**このファイルを直せば、次に起こすぶんから全部に効く。**

**`## <種類>` の見出しと ``` の行は目印として使っている。** 消すと起こせなくなる。

---

## mend — 直しを待っているPRがある

```
[デーモン] PR #<番号> が直しを待っています。

このPRはあなたが出したものです。次のどれかが起きているので、**PRを見て確かめてください。**

- コンフリクトしている（`main` を取り込み直して解消する）
- CIが赤い（`npm run lint` / `npm run typecheck` / `npm test` / `npm run format:check` の4つ）
- レビューから差し戻された（PRのコメント。`[レビュー] 直しが要る` で始まるもの）
- 積んでいた下のPRが入って、base を `main` へ張り替えられた（PRのコメント。`[デーモン]` で始まる
  もの。**差分にもCIにも下のぶんが残っているので、`origin/main` の上へ載せ直して push する**）

直し方は `CLAUDE.md`「修正作業の進め方」5節——**指摘はその行の直し方ではなく原則として受け取り、
同じ原則に反している箇所を洗い出して一緒に直す。** 意図が読み取れない指摘は、推測で書き換えずに
PRのコメントで質問してください。

直して push したら、そこで終わりです。**CIの結果もレビューも見張らないでください**
（`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わない）。まだ直しが要るなら、
同じようにここへ届きます。
```

## reject — ユーザーが差し戻した

```
[デーモン] PR #<番号> をユーザーが差し戻しました。

**レビューの指摘への対応ではありません。** ユーザーがPRを読み、**このままでは通せない**と判断して
ラベルを外しました。**PRのコメントを読み、何を直してほしいのかを確かめてください**——理由は、
ユーザーがラベルを外す前後に書いたコメントに在ります。

**多いのは、そのPRで自分が決めた仮決めが通らなかった場合です。** そのときやることは、**通らな
かった仮決めに乗って書いた部分を取り下げ、別の決め方でやり直す**こと。指摘された行を直すのとは
範囲が違います——その仮決めを前提にして書いた記述・コードが他にもあるなら、まとめて見直して
ください。やり直した結果は `## 仮決め` 節に書き直します（**前の仮決めを消して、新しいものを
書く**。経緯は残しません）。

理由が見当たらない、あるいは決め直せないなら、PRのコメントで質問してください。

直して push したら、そこで終わりです。**CIの結果もレビューも見張らないでください**
（`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わない）。
```

## look — 画面の証跡が無い

```
[デーモン] PR #<番号> に `## 見た目` の節がありません。

`src/game/**` か `src/assets/**` を触ったPRには、**画面が変わったかどうかを本文で言う**義務が
あります（`CLAUDE.md`「PR本文に置く節」）。**差分を直す必要はありません。**

やることは次のどちらかです。

- **画面が変わるなら**、撮って貼る。撮り方は `.claude/skills/run/SKILL.md`、貼り方は
  `bash scripts/agent/push-screenshot.sh <画像> <名前>`（返ってきたURLを `![<名前>](<URL>)` の形で
  本文へ）。**前後を並べるならURLに `?seed=12345` を付ける**——付けないと島も開始時刻も実行ごとに
  変わるので、2枚の差が変更由来だと言えません。
- **変わらないなら**、「不要」と**その理由の1行**を書く。要否を決めるのは書いた側です。

節を足したら、そこで終わりです。**CIの結果もレビューも見張らないでください。**
```

## review-stall — 判定がまだPRに無い

```
[デーモン] PR #<番号> のレビューの判定が、まだPRに書かれていません。

**まだ読んでいる最中なら、そのまま続けてください。** この合図は手が止まって見えたら届くので、
**立てた直後で最初の手番が始まっていないだけ**のこともあります。

読み終わっているのに書いていないなら、**判定をPRへコメントで書いてください。** それがこの
セッションの唯一の出力で（1行目の綴りと2行目の `読んだ版:` は最初に受け取った指示のとおり）、
書かれるまでそのPRはマージにもレビューにも進みません。

**次に手が止まっていたら、盤面はこのセッションを畳んで、同じPRへ新しいレビューを立てます。**
あなたが読んだところは畳んだ時点で消えるので、途中まででも判定を書くほうが早く進みます。
```

## stall — PRがまだ出ていない

```
[デーモン] issue #<番号> のPRが、まだ出ていません。

あなたの手が止まっています。次のどちらかをしてください。

- **続きがあるなら**、仕上げてPRを出す（本文に置く節は `CLAUDE.md`「PR本文に置く節」）。
- **出せないなら**、issue #<番号> へコメントで返す（道具は
  `.claude/github-access.md`「issue を読む・書く」）。1行目を
  `[返却] <なぜ返すか。1行で>` にして、2行目から下に何を調べてどこで詰まったかを書いてください。
  差分が空のPR・途中で捨てた作業のPRは、開いたままにしないでください（`CLAUDE.md` 7節）。

**次にあなたの手が止まっていたら、盤面が代わりに返します。** そのときのコメントには「起こしても
手が動かなかった」としか書けないので、**あなたが調べたことは誰にも残りません。**
```
