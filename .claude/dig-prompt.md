# 掘り起こしのプロンプト

**完成の定義に照らして、まだ issue になっていない残りを数える**係の本文。投入するのは盤面
（[`board-move.mjs`](../scripts/agent/board-move.mjs) の `CYCLES`）で、**配れる `kind:task` が
無くなった周**に一日一回立つ。渡し方は [`dispatch-chore.sh`](../scripts/agent/dispatch-chore.sh)。

**「仕事を探せ」とは言わない**（[`docs/ParallelAgents.md`](../docs/ParallelAgents.md)「⛏️ 掘り起こし役
— 探すのではなく、数える」）。そう言われたエージェントは必ず何か見つけるので、出力の質が観点の質と
同じになり、観点を毎回考える人が要ることになる。**機械が起こす係なので、その人は居ない。**

**クラウドで走る。** リポジトリへは1行も書かず、PRも出さない——書くのは**新しい issue** と、
**確定待ちの盤（#656）の本文**だけ。

題は下の `題:` の行が持つ（[`board-design.md`](board-design.md) 2.9）。

題: 発掘 完成の定義の残り

---

````
[デーモン] 配れる `kind:task` が尽きました。完成の定義に照らして、残りを数えてください。

まず `CLAUDE.md` と `.claude/parallel-work.md` を読んでください。

**探すのではなく、数える仕事です。**

> **完成の定義に載っているもの － 既に issue になっているもの ＝ 掘り起こすもの。**

**「残り0件」は失敗ではなく、正しい報告です。** 定義に照らした穴は有限なので、残りは減っていきます。
**足りないぶんを埋めるために、定義に載っていないものを持ってこないでください**——「面白さが足りない」
の類は人間と話す役（相談役）の領分で、この係には見つかりません。

## GitHub を触る道具

**まず `command -v gh` を打ってください。** この係はクラウドで立つので、**入っていないほうが普通
です。** 無いときは GitHub の MCP で同じことをします。

| やること | `gh` があるとき | 無いとき |
| --- | --- | --- |
| 開いている issue を読む | `gh issue list --state open --limit 200 --json number,title,labels` | `list_issues`（`state: "OPEN"`・`fields: ["number","title","labels"]`） |
| issue を立てる | `gh issue create --title <題> --body-file <本文> --label origin:agent` | `issue_write`（`method: "create"`・`title`・`body`・`labels: ["origin:agent"]`） |
| #656 の本文を読む | `gh issue view 656 --json body --jq .body` | `issue_read`（`method: "get"`・`issue_number: 656`） |
| #656 の本文を書き換える | `gh issue edit 656 --body-file <本文>` | `issue_write`（`method: "update"`・`issue_number: 656`・`body`） |

`origin:agent` は、人が立てた issue と見分けるための印です（`.claude/parallel-work.md`「自分で立てた
issue には `origin:agent` を付ける」）。**起票のときに一緒に渡してください**——この係はクラウドで
立つので、後からラベルだけを付け直す道がありません（`.claude/board-design.md` 2.16）。
**`kind:` は付けないでください**（分類するのは棚卸しです。同 2.17.1）。

## 数える先

**残りの作業量を答えられるものだけ**を数えます（`.claude/policies.md`「未実装のものの扱い」）。

- **`未決事項`・`今後の検討課題` の節**（`docs/**`）
- **`【未実装】` の印**（`docs/**`・`src/**`）
- **収支の穴。** `stats/balance.yaml` の `chain_gaps`（島のどこにも入手経路が無いものと、それが
  塞いでいる経路）と、`daily_minimum` が1日を賄えていない土地。読み方は
  `docs/diagnostics/BalanceStats.md`。

**`stats/balance.yaml` は読むだけにしてください。** `npm run stats:balance` は表を作り直して書き出す
ので、走らせるとチェックアウトが汚れます。表は `main` への push のたびに workflow が作り直すため、
**生成済みのものが常に最新です。**

**`docs/Someday.md` に在るものは数えません。** あれは「無くても完成を宣言できるもの」を分けた置き場
なので、残りの作業量には入りません。

## 既に issue になっているものを引く

**開いている issue を全部読んでから、差を取ってください。** 題だけで突き合わせると、言い回しの違う
同じ仕事が二重に立ちます。**閉じた issue も、同じ題材が最近閉じていないかは見てください**——直った
ばかりのものをもう一度立てることになります。

**この係が前の周に立てた issue は、まだ `kind:` が付いていません**（分類は棚卸しが一日一回やるので、
翌日まで未整理のまま残ります）。**未整理のものも「既に issue になっているもの」です。** ここを飛ばすと、
盤面が空いている間じゅう毎日同じ issue が積み上がります。

## 出口を振り分ける

**全部を確定待ち（#656）へ積まないでください。** 配れるものが1件も増えず、この係を起こしても盤面が
動きません。

### やると決まっているもの → 新しい issue

`【未実装】` の印と、収支の穴。**やると決まっているのに手が付いていないもの**です。

- 本文は `.claude/parallel-work.md` 3節の**タスク issue の型**に従う（`## 担当`・`## 完了の条件`は
  必ず置く）。**この型で書くのは、棚卸しを通ってそのまま配られるから**です。
- **1セッションで片付く大きさに割ってください。** 「未実装をすべて実装する」は仕事ではありません。
- **どこを読めば始められるかを書く。** 印が付いているファイルと節を、`## 担当` に挙げます。

### やるかどうかから訊くもの → #656

`未決事項`・`今後の検討課題` の節。**未決は「まだ決めていないこと」であって「やると決めたこと」では
ない**ので、そのまま issue にすると乗り気でないものが実装されて戻ってきます
（`.claude/parallel-work.md`「未決は「やるかどうか」から訊く」）。

**#656 の本文の `## 確認待ち` へ、項目として足します。** 書き方はその issue の「使い方」の節に
書いてあります——**チェックを付けるだけで答えになる形**（採否なら太字の1文がそのまま確定する内容、
選択なら子チェックを並べて「入れない」も選択肢に入れる）。**一度に並べる件数の上限も本文に
書いてあるので、既に並んでいる項目を数えて、超えないぶんだけ足してください。**

- **断定文で書く。** 「どうしますか」は書けません（`CLAUDE.md`「確認は issue #656 へ積む」）。
  決めていない箇所には常に仮決めの案があるはずなので、それを太字の1文にします。
- **リポジトリを開かずに答えられるだけの文脈を添える。** ユーザーはスマホから読みます。節への
  リンクは確かめたいとき用で、**リンクを開かないと判断できない項目は出さないでください。**
- **既に並んでいる項目と同じことを訊かない。** 先に全部読んでください。

**本文を書き換えるときは、取ってきた本文をそのまま持って、足すところ以外を1文字も変えないこと。**
`gh issue edit` も MCP の `issue_write` も、**渡した本文で丸ごと置き換えます**——一部だけを送ると
残りが消えます。**あの issue は答えの置き場そのもの**なので、消すと未回答の項目ごと失われます。

**書き換えを断られたら、足せなかった項目を報告に書いて終えてください。** 無理に別の道
（コメントへ書く・新しい issue を立てる）を探さないこと——**答えとして拾われるのは本文の
チェックだけ**（`scripts/agent/checked-items.sh`）なので、どこへ書いても届きません。**次の周が
同じものを数え直す**ので、落ちても取り返せます。

## 順番

1. **数える先を全部読む**（上の「数える先」）。**先に全部読んでから**振り分けてください。
2. **開いている issue を全部読み、差を取る。**
3. **やると決まっているものを issue にする。** 1件ずつ立てます。
4. **やるかどうかから訊くものを #656 へ足す。** 本文の書き換えは**最後に一度だけ**にしてください
   （途中で落ちても、消えるのは自分が足そうとした分だけで済みます）。
5. **報告する。** 数えた残りの件数・立てた issue の番号・#656 へ足した項目を書いてください。
   **残り0件ならそう書いて終わりです**——issue は立てません。

## 守ること

- **リポジトリを1行も書き換えないこと。PRも作りません。** コードも文書も読むだけです。見つけた
  穴を自分で埋めないでください——**埋めるのは、配られたワーカーの仕事**です（報告と反映を同じ役に
  持たせない）。
- **触ってよい既存の issue は #656 の本文だけ。** 他の issue とPRは、本文もラベルもコメントも
  触らないでください。
- **`kind:` のラベルを付けないこと。** 分類は棚卸しがやります。
- **`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わないこと。** 自動承認ができず、
  呼んだ分がそのままユーザーの手作業になります。
- 決まっていない箇所は仮決めして進み、立てた issue の中に書いてください。
````
