# タスクを投入するときの指示のひな形

司令塔が `create_session` へ渡す本文。**手で書き起こさず、この節をそのまま写して `<番号>` を
埋める。** 手で組み立てると必ず何かが落ちる——2026-08-27 に「PRを見張らない」の一文が3本すべてから
抜け、3セッションが `subscribe_pr_activity` と `send_later` を呼んで承認待ちで止まった。

**足すのは末尾の「このタスク固有の補足」だけ。** 上の箇条書きは削らない。禁止は指示文でしか効かない
（`create_session` に道具の拒否リストは無く、渡せる `extra_allowed_tools` は広げる方向だけ）。

---

```
[司令塔] https://github.com/gooyyu1/UnmappedIsland/issues/<番号>

この issue 1件がこのセッションの仕事です。

- 進め方は `CLAUDE.md`、並列作業の取り決めは `.claude/parallel-work.md`。
- **issue の「担当」に挙がっていないファイルは、原則として触らない。** 気づいた別の問題は、直さずに
  新しい issue を立てる。**順序が要ると判断したら `blockedBy` を張ろうとせず、PR本文に「#A は #B の後」
  と書いてください**（このセッションからは GitHub の REST に届かないので張れません。司令塔が張ります）。
  「同じファイルを触る」は依存ではありません。
- **例外は、あなたの変更がその記述・コードを事実でなくしたとき。** 「まだ無いので待つ」が入ったことで
  嘘になった、隣の文が噛み合わなくなった——こうした直しは担当外でも**同じPRで**入れてください。
  判定は「**自分の差分がこの行を嘘にしたか**」だけで、「ついでに気づいた」「直したほうがよさそう」は
  入りません（それは今までどおり issue）。入れたぶんは **PR本文の `## 担当外へ入った直し` 節に、
  1件ずつ「何が嘘になったから直したか」を書く**（無ければ節ごと省く）。
- **生成物は、担当に挙がっていなくても作り直してよい**——`stats/balance.yaml` は
  `npm run stats:balance`、`stats/climate.yaml` は `npm run stats:climate`。鮮度検査があるので、
  作り直さないとCIが落ちます。**手で書き換えないこと。**
- 決まっていない箇所は仮決めして進み、**PR本文の先頭の `## 仮決め` 節に申告する**（無いなら「なし」と
  書く。書かせないと、無かったのか書き忘れたのかが区別できない）。`【確定】` の節に反する変更が要る
  ときだけ、進めずに issue #656 へ積む。
- **見た目が変わる変更なら、PR本文に `## 見た目` 節を作って画面の画像を貼ってください。**
  撮り方は `.claude/skills/run/SKILL.md`、貼り方は
  `bash scripts/agent/push-screenshot.sh <画像> <名前>`（返ってきたURLを `![<名前>](URL)` の形で
  本文へ）。`src/game/**` か `src/assets/**` を触ったのに貼らないなら、同じ節に「不要」と理由を
  1行書いてください。**節ごと無いPRは司令塔が差し戻します。** 変更前後を並べるなら、URLに
  `?seed=12345` を付けて撮ること——付けないと実行ごとに島も開始時刻も変わるので、2枚の差が変更
  由来だと言えません。
- push の直前に `main` を取り込み直し、`npm run lint` / `npm run typecheck` / `npm test` /
  `npm run format:check` の4つを通す。
- 完了条件を満たしたらPRを作り、**本文の先頭に `Closes #<番号>`** と書く。**issue は自分で閉じない。**
- **PRを作ったら報告して終わりです。CIの結果もレビューも見張らないでください。**
  **`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わないこと。** この3つは自動承認が
  できず、呼んだ分がそのままユーザーの手作業になります。待つのは司令塔の仕事で、直しが要れば
  `send_message` で起こしに行きます。

<このタスク固有の補足。**担当が他のセッションと重なっているなら、どのファイルのどこを向こうが
掴んでいるかを名指しする**（重なりは止める理由にならないので、境目を書いて並列に流す）。
直列にした相手、issue 本文が古くなっている箇所なども。無ければ省く>
```
