# タスクを投入するときの指示のひな形

司令塔が `create_session` へ渡す本文。**手で書き起こさず、この節をそのまま写して `<番号>` を
埋める。** 手で組み立てると必ず何かが落ちる——2026-08-27 に「PRを見張らない」の一文が3本すべてから
抜け、3セッションが `subscribe_pr_activity` と `send_later` を呼んで承認待ちで止まった。

**足すのは末尾の「このタスク固有の補足」だけ。** 上の箇条書きは削らない。禁止は指示文でしか効かない
（`create_session` に道具の拒否リストは無く、渡せる `extra_allowed_tools` は広げる方向だけ）。

---

```
[司令塔] https://github.com/gooyyu1/UnmappedIsland/issues/<番号>

この issue 1件がこのセッションの仕事です。

- 進め方は `CLAUDE.md`、並列作業の取り決めは `.claude/parallel-work.md`。
- **issue の「担当」に挙がっていないファイルは触らない。** 気づいた別の問題は、直さずに新しい issue を
  立てる。**順序が要ると判断したら `blockedBy` を張ろうとせず、PR本文に「#A は #B の後」と書いて
  ください**（このセッションからは GitHub の REST に届かないので張れません。司令塔が張ります）。
  「同じファイルを触る」は依存ではありません。
- 決まっていない箇所は仮決めして進み、**PR本文の先頭の `## 仮決め` 節に申告する**（無いなら「なし」と
  書く。書かせないと、無かったのか書き忘れたのかが区別できない）。`【確定】` の節に反する変更が要る
  ときだけ、進めずに issue #656 へ積む。
- push の直前に `main` を取り込み直し、`npm run lint` / `npm run typecheck` / `npm test` /
  `npm run format:check` の4つを通す。
- 完了条件を満たしたらPRを作り、**本文の先頭に `Closes #<番号>`** と書く。**issue は自分で閉じない。**
- **PRを作ったら報告して終わりです。CIの結果もレビューも見張らないでください。**
  **`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わないこと。** この3つは自動承認が
  できず、呼んだ分がそのままユーザーの手作業になります。待つのは司令塔の仕事で、直しが要れば
  `send_message` で起こしに行きます。

<このタスク固有の補足。触ってはいけない隣接ファイル、並行して走っている issue と担当が重ならない
こと、直列にした相手など。無ければ省く>
```
