# 価値観を畳む係のプロンプト

`.claude/decisions/` に溜まった判断の履歴を読み、一般則へ畳む候補を並べた issue を1本起票する係の
本文。投入するのは盤面（[`board-move.mjs`](../scripts/agent/board-move.mjs) の `CYCLES`）で、
`archive/` に入っていない履歴が1件でもあれば週に一度立つ。渡し方は
[`dispatch-chore.sh`](../scripts/agent/dispatch-chore.sh)。

**畳む手順そのものは [`policy-review` skill](skills/policy-review/SKILL.md) が持つ**——束ね方も、
一般則の書式も、行き先も、総量の上限もそちらが唯一の定義。ここに書くのは、**周期の係だけが持つ
事情**——諾否を訊く相手が居ないので、答えを issue のチェックで受けること。

**この係はリポジトリへ1行も書かない。** 反映するのは、ユーザーがチェックを付けて `判断待ち` を
外した後に配られる、別のセッション。**候補を出す仕事と、チェックを読んで書く仕事を1本に混ぜない**
——混ぜると、諾否を待つ間セッションが止まる（[`board-design.md`](board-design.md) 2.15.1）。

**`判断待ち` を付けた状態で起票する**（出どころ: ユーザーの指示・2026-09-06）。ラベルが付いている
間は誰にも配られないので、チェックが埋まる前に反映されることがない。

題は下の `題:` の行が持つ（`board-design.md` 2.9）。

題: 価値観 畳む候補

---

````
[デーモン] `.claude/decisions/` に溜まった判断の履歴を棚卸しし、候補を issue にします。

まず `CLAUDE.md`「価値観の記録」と `.claude/skills/policy-review/SKILL.md` を読んでください。
**束ね方・一般則の書式・行き先・総量の上限は、すべてその skill が持ちます。** ここへ書き写して
いないので、開いて読んでから始めてください。

## GitHub を触る道具

**まず `command -v gh` を打ってください。** この係はクラウドで立つので、**入っていないほうが普通
です。** 無いときは GitHub の MCP で同じことをします。

| やること | `gh` があるとき | 無いとき |
| --- | --- | --- |
| 前の周の issue を探す | `gh issue list --state open --limit 100 --json number,title --search '価値観の棚卸し in:title'` | `search_issues`（`query: "repo:gooyyu1/UnmappedIsland is:issue is:open 価値観の棚卸し in:title"`） |
| issue を立てる | `gh issue create --title <題> --body-file <本文> --label 判断待ち` | `issue_write`（`method: "create"`・`title`・`body`・`labels: ["判断待ち"]`） |

ラベルの綴りに `:` は入らないので、引数が化ける心配はありません。**`--body-file` で渡してください**
——本文はチェックボックスの一覧で長く、シェルの引数に載せると引用符で壊れます。

## 先に、前の周の issue が残っていないか見る

**題が「価値観の棚卸し」で始まる open の issue が1本でもあれば、何もせずに終わってください。**
まだユーザーが答えていないか、答えを反映するセッションが走っている最中です。そこへ2本目を出すと、
同じ履歴に対する候補が2つ並び、**どちらを反映しても残りが嘘になります。**

## やること

1. **`.claude/decisions/*.md` を全部読む**（`archive/` の中は読まなくてよい——処理済みです）。
   **先に全部読んでから**束ね始めてください。1件だけを見て「これは一般則か」は判断できません。
2. skill の手順1〜2で**候補を作る**。候補は3種類あります。
   - **乗せる** — 束から抽出した新しい一般則。行き先も1つ選ぶ。
   - **外す** — 既に在る一般則のうち、もう要らないもの・一般論から再現できるもの。
   - **移す** — 既に在る一般則のうち、置き場が違うもの。移す先を1つ選ぶ。
3. **候補が1件も無ければ、issue を立てずに報告して終わり。** 束にならない孤立した1件しか無い週は
   これが正解です（次にユーザーと話したとき、束になるかもしれないので履歴に残します）。
4. 候補があれば、下の形で issue を1本起票する。**1本だけです**——候補ごとに立てると、ユーザーが
   同じ判断を何度も開くことになります。

## 外すか移すかを先に出す

**`.claude/policies.md` には行数の上限があり**（`tests/docs/policies.test.ts` の `MAX_LINES`）、
**今それに近いところまで埋まっています。** 上限を超える一般則は入れられないので、**乗せる候補と
同じ数以上の外す・移す候補が要ります。** 何行空くのかを、issue の本文に数字で書いてください。

**外す・移すの候補は、乗せる候補と同じ重みで探すこと。** 「今回の履歴から出たもの」だけを見ると
乗せる候補しか出ず、上限に当たって全部が入らなくなります。**既に在る一般則を頭から読み直して
ください**——一般論に照らして当然の判断になっているもの、事例そのものになっているもの、別の
方針文書のほうが在り処として正しいものが対象です。

## 起票する issue

**題は「価値観の棚卸し」で始めてください**（上の重複の検出がこれを見ます）。後ろに日付を添える:
`価値観の棚卸し（2026-09-13）`。

**ラベルは `判断待ち` の1つだけ**（上の表の道具で、立てるときに付けます）。`kind:` は付けないで
ください（分類するのは棚卸しの係です。`.claude/board-design.md` 2.17.1）。

本文は `.claude/parallel-work.md` 3節の**タスク issue の型**に従います（`## 担当`・`## 完了の条件`
は必ず置く）。**この型で書くのは、チェックが埋まった後そのまま配られるから**です——型を外すと、
棚卸しの係が本文を書き換えにかかります。

型に加えて、**候補の一覧をチェックボックスで置いてください。**

```markdown
## 乗せる候補

- [ ] **`.claude/policies.md`「名前の付け方」へ**
  - **場面**: …
    **選ぶ方**: …
    **重視**: …
  - 出どころ: `2026-09-05-xxx.md` / `2026-09-06-yyy.md`

## 外す候補

- [ ] **`.claude/policies.md`「分岐の書き方」の「場面: …」を消す** — 一般論から同じ答えが出る。

## 移す候補

- [ ] **`.claude/policies.md`「文書は、失敗の履歴で作らない」の「場面: …」を
      `docs/DocumentStyle.md` へ** — 文書の書き方の決めごとで、どのセッションも要るものではない。
```

- **1項目1チェックボックス。** 束ねると、ユーザーは一部だけ通す答えを出せません。
- **乗せる候補は、そのまま貼れる形で書く。** 反映するセッションが文面を考え直さずに済みます。
- **出どころの履歴のファイル名を、候補ごとに全部挙げる。** 反映したあと `archive/` へ移すのは
  この一覧です。**挙げ忘れた履歴は残り続け、次の周でまた同じ候補になります。**
- **何行空くのか・何行増えるのかを書く。** ユーザーはリポジトリを開かずに答えます。

`## 担当` に挙げるのは、**候補の行き先に実際に出てくる文書**と `.claude/decisions/**` だけです
（使わない行き先を書かない）。`## 完了の条件` は次の形で。

```markdown
## 完了の条件

- 上の候補のうち、**チェックの付いたものだけ**が反映されている（付いていないものは反映しない）
- 反映した候補の出どころの履歴が `.claude/decisions/archive/` へ `git mv` されている
- **チェックの付かなかった候補の出どころの履歴も `archive/` へ移す。** ただし front matter へ
  `declined: <この issue の番号>` の行を足してから移すこと（見送ったことが残らないと、次の周で
  同じ候補がまた挙がります）
- どの候補にも入らなかった履歴は、`.claude/decisions/` に残す（束になっていないだけなので）
- `npm run lint` / `npm run typecheck` / `npm test` / `npm run format:check` が通る
```

## 守ること

- **リポジトリを1行も書き換えないこと。** 成果は issue 1本だけです。**PRは作りません。**
  `.claude/policies.md` も `.claude/decisions/` も、この係は読むだけです。
- **既存の issue とPRを触らないこと。** コメントも付けません。
- **一般化はここでやり、判定はユーザーに任せる。** 「これは一般則にならない」とあなたが決めて
  落としてよいのは、skill の「残すのは、このリポジトリ特有・ユーザー特有・甲乙つけがたいもの」に
  照らして明らかなものだけです。**迷ったら候補に出してください**——チェックを付けないという答えが
  ユーザーの側にあります。
- **履歴の原文を引くこと。** 候補の根拠は、要約ではなくユーザーの発言そのものです。
- 決まっていない箇所は仮決めして進み、起票した issue の中に書いてください。

報告には、読んだ履歴の件数・出した候補の数（乗せる／外す／移す）・立てた issue の番号を書いて
ください。**候補が無くて立てなかったなら、そう書いてください。**

応答は日本語で。
````
