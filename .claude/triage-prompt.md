# 棚卸しを投入するときの指示のひな形

`board.sh` の `## 未整理` に並んだ issue を、投入できる `task` へ翻訳させるための本文。
`create_session` へ渡すときは**この節をそのまま写して `<番号…>` を埋める**（`dispatch-prompt.md`
と同じで、手で組み立てると必ず何かが落ちる）。

**ブリッジ（`--bridge`）で走らせること。** クラウドのセッションは GitHub の REST が丸ごと塞がって
いて、**既存の issue の本文を書き換えられない**。番号を保ったまま書き換えるのが棚卸しの中心なので、
クラウドでは仕事にならない。

**未整理の全件をまとめて1セッションに渡す。** 1件ずつだと、別々に立った issue が同じ原因である
ことに誰も気づけない——#1042・#1043・#1044 はどれもカードの移動アニメーションの話で、1件ずつ
翻訳すると同じファイルを触る `task` が3本立って衝突する。まとめて見る側に置けば、束ねるのか
分けるのかをその場で決められる。

---

````
[デーモン] 未整理の issue を棚卸しします: #<番号> #<番号> #<番号> …

これらは**ユーザーが自分の言葉で立てた issue** で、まだ投入できる形になっていません。
これを投入できる `task` へ翻訳するのが、このセッションの仕事です。

## やること

1. 全件をまず読む。**先に全部読んでから、1件目に手を付けてください。**
   同じ原因の issue が混ざっていることがあります（症状は別でも、壊れているのは1箇所）。
2. コードを読んで、直す場所の見当を付ける。**再現手順が書いてあるならテストにして実際に失敗させて
   から**（`CLAUDE.md`「再現手順を最初にテストへ落とす」）。**再現しなかったら、その issue は
   翻訳せずに「再現しなかった」と報告してください。**
3. issue を、下の3つの出口のどれかへ振り分ける。
4. 全部終えたら報告して終わり。**PRは作りません。**

## 出口は3つ

**(a) そのまま** — 1セッションで片付く大きさで、直す場所も決まっている。
**同じ番号のまま本文を書き換えて**、`task` の型（`.claude/parallel-work.md` 3節）にする。

**(b) 分解** — 2つ以上のセッションに分かれる、または仕様を決める段と実装する段に分かれる。
**子の issue を新しく立て、元の issue はそのまま残す**（元がゲートになる。
`.claude/parallel-work.md`「束ねる関門は、ゲートの issue を1件立てる」）。

**(c) 束ねる** — 複数の issue が同じ原因。**1件を代表にして本文へまとめ、残りは代表を指す1行だけに
書き換える**（閉じない。閉じるのはマージのときです）。

## 守ること

- **`task` ラベルは付けないでください。** 付けるのはユーザーです——順序（`blockedBy`）を張ってから
  でないと、依存のある issue が「着手可」として先に配られます。
- **ユーザーが書いた原文を消さないこと。** 書き換えた本文の末尾に `## 元の報告` という節を作り、
  **原文をそのまま**残す。翻訳を誤っても、読んだ人が原文と突き合わせて気づけるようにするためです。
- **順序が要ると判断したら、報告に「#A は #B の後」と書く。** 張るのはユーザーです。
  **「同じファイルを触る」は順序の理由になりません。**
- **コードは1行も変えないこと。** 成果物は issue の本文だけです。テストを書いて再現を確かめるのは
  構いませんが、それも捨ててください（残すのは翻訳先の issue に書いた再現手順）。
- 仕様が決まっていない箇所は、**あなたが決めずに「決める」ことを (b) の子 issue にする。**
  **確定の宣言**（節の `【確定】` と、文書単位の `**本書は全体が確定です。**`）に反する判断が要る
  ときだけ、issue #656 へ積む。

## 書き換えた本文の形

**型は [`.claude/parallel-work.md`](./parallel-work.md) 3節が持ちます**——節名も、必ず置く節も、
書かないものも、そちらが唯一の定義です。**ここへ書き写さないので、開いて読んでから書いてください。**
節名は `dispatch-prompt.md`（担当の列挙）と `review-prompt.md`（担当の範囲と完了条件）が名前で引く
ので、揺れると両方が探す先を失います。

棚卸しが足すのは1つだけ。**本文の末尾に `## 元の報告` を置き、ユーザーが書いた原文をそのまま残す**
（上の「守ること」）。

- **見た目が変わる issue には、担当に絵や画面のファイルが入っているかを確かめる。**

## 報告に書くこと

1件1行で、**番号・出口・一言**。最後に、張ってほしい順序（`#A は #B の後`）と、
再現しなかったもの、判断を保留したものを挙げてください。
````
