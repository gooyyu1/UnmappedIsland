# いつか実装したいこと

**無くても完成を宣言できるが、いつか実装したいもの**を集めます。**残りの作業量には数えません。**

無いと完成と言えないものの印は `【未実装: 識別子】` で、実体は `task` ラベルの issue が持ちます
（[`DocumentStyle.md`](./DocumentStyle.md) 4節）。本書が持つのはその外側だけです。両方を1つの印で
扱うと、**あと何が足りないのかを誰も答えられなくなります。**

- **各文書に残すのは印と短い参照だけで、中身はここにしかありません。**
- **見出しの先頭の語が識別子です。** どの文書の印とも対応しない項目、または項目の無い印があると
  `tests/docs/docReferences.test.ts` が落ちます。
- **並び順に意味はありません。** 期限も優先度も持たせません——持たせた時点で残作業の一覧になります。

## 一覧

### 月齢 — 夜の明るさを月齢で周期させる

いまは半月固定で、夜はどの時刻も暗さの底へ均されます（[`ContentSkeleton.md`](./world/ContentSkeleton.md)
8.1.1.1節）。**画面に月齢を出す形が決まっていない**ので入れません。入れると開けた土地の夜が
「歩ける／歩けない」で周期的に切り替わります——森と密林はどのみち歩けないので、効くのは開けた土地だけです。

### 泊まりがけ — 補給を持ち込んで、遠い土地に泊まる

拠点へ戻らずに滞在する行程と、そこへ置く前線の段です（[`ContentSkeleton.md`](./world/ContentSkeleton.md)
4節の系統11）。今の島は端から端まで日帰りで届き、土地ごとに日帰りと泊まりの安いほうを採っても浮くのは
1.5日だけなので（同8.3.1節）、無くても1周回は成立します。

**入れるなら、島を広くするほうが先です。** 泊まりを選ぶ理由は「日帰りでは往復が枠を食い尽くす土地が
ある」ことでしか作れず、それは島の広さの話だからです。**広さを変えないまま行程だけを足すと、
1日半の短縮のために持ち出す量を決めさせることになります**——判断の材料に対して、返るものが釣り合いません。

### アチーブメント — 周回をまたぐ記録を残す

「すべての動物を飼いならす」のような達成を、棚と同じく周回をまたいで永続させます
（[`GameEndings.md`](./concept/GameEndings.md) 7節）。棚が既に周回をまたぐ動機を担っているので、無くても
終幕は成立します。保存先は棚と同じ、セーブの4スロットとは別の領域（[`SaveDataManagement.md`](./engine/SaveDataManagement.md) 棚節）。

### なめし革の帆 — 生皮の帆の上に1段置く

帆は生皮の1種（`sail_speed` +2）だけで、その上は空けてあります（[`Voyage.md`](./world/Voyage.md) 2.1節）。
材料のなめし革はもう作れます（[`SurvivalItems.md`](./world/SurvivalItems.md) 5節）が、+2 でどの積載でも段が
1つ上がり、生皮の帆だけで外洋は渡り切れるので、無くても航海は成立します。+4 を置くと、重く積んだ日ほど
生皮との差が開きます。

### 燻製 — 塩蔵の隣に、煙で保たせる道を置く

保存の道は天日干しと塩蔵の2本で、どちらも生の食べ物を20日へ移します
（[`SurvivalItems.md`](./world/SurvivalItems.md) 9節・10節）。燻し小屋は同じ系統の3本目の設備で、
塩蔵とは重ねて効きます。**航海は4〜6日で、塩蔵の20日がそれを大きく上回る**（[`Voyage.md`](./world/Voyage.md) 3.9.1節）
ので、これ以上保たせる必要はなく、無くても出航できます。

**入れるときは、塩蔵の弱体化か、どちらを選ぶかを分ける条件（腕前・環境）とセットにします**
（[`DesignPrinciples.md`](./concept/DesignPrinciples.md) の「後から足す手段は、既存の手段を残す強さに
抑える」節）。燻製が塩蔵より上なだけなら、塩田を据える理由が消えて手段が1つに戻ります。

### 穀物 — 年単位で保つ食材を作物に足す

畑で採れるのはタロイモと空心菜で（`src/assets/world-codex/farming.yaml`）、いちばん保つ芋でも20日
（[`DurabilitySystem.md`](./engine/DurabilitySystem.md) 3節）。塩蔵が持っていく先も同じ20日なので
（[`SurvivalItems.md`](./world/SurvivalItems.md) 9節）、**今ある保存はどれも20日で頭打ち**です。穀物は
乾かせば桁違いに長く保つ食材で、その上を開けます。要るのは脱穀と製粉の工程で、そこまで足さないと収穫が
そのまま食べ物になりません。20日で回る暮らしは既に成立しており、**それを超える保存を要求する場面は
どこにもありません**（航海でさえ4〜6日、[`Voyage.md`](./world/Voyage.md) 3.9.1節）ので、無くても
完成します。

**入れるときは、既存の食材の弱体化か、どちらを選ぶかを分ける条件（腕前・環境）とセットにします**
（[`DesignPrinciples.md`](./concept/DesignPrinciples.md) の「後から足す手段は、既存の手段を残す強さに
抑える」節）。**保つ日数だけが桁違いに長い食材を足すと、畑は穀物だけになります**——脱穀と製粉の手数を
代償に置くか、育つ土地や季節で芋と分かれるか、どちらかが要ります。

### 明るさ条件の検査 — 条件の書き忘れを見張る

明るさの条件を書かない操作は「暗くてもできる」という意味になり、書き忘れと見分けが付きません
（[`IlluminationSystem.md`](./engine/IlluminationSystem.md) 5節）。操作の一覧を出して、明るさの条件を
持たないものを並べる検査で見張ります。遊びの側は無くても完成するので、診断の道具として後から足します。

### 図鑑の生成型 — 中身入りの容器を図鑑に載せる

「水入りの甕」のように実行時に生成される型は図鑑（`src/codex-viewer`）の一覧に無く、名指しで開く道が
ありません（[`LiquidContainerSystem.md`](./engine/LiquidContainerSystem.md) 1節）。空の容器と液体は別々に
載っているので、無くても図鑑は読めます。載せると、容器と液体の組み合わせが1ページで確かめられます。

### 洞窟内部 — 浅い洞窟の奥へ続く道を開く

浅い洞窟（`shallow_cave`）には入れますが、そこから奥へ続く道がありません。要るのは
`structure_interior` スコープの再帰生成（[`TerrainGeneration.md`](./engine/TerrainGeneration.md) 3.7節）と、
内部への遷移です。雨よけ・拠点・アーティファクトの行き先は浅い洞窟が既に担っているので、奥が無くても
1周回は成立します。開くときは次の2つが同時に要ります。

- **内部の土地にも、着いた時点で分かる違う名前が要ります。** 道のカードは `fixtures` レーンの中で
  並び替えできてしまうため、名前が無いと進んでいるのか戻っているのかが読めません
  （[`DesignPrinciples.md`](./concept/DesignPrinciples.md) の「見分けの付かない場所を作らない」節）。
  現実に即して見分けが付かないままにすると、盤面が読めず判断のしようがなくなります。
- **奥は昼でも真っ暗です**（[`IlluminationSystem.md`](./engine/IlluminationSystem.md) 7節）。浅い洞窟が
  外の明るさを継ぐのに対し、奥は空を継がないので、潜るには必ず光源が要ります——燃料の需要が一段増えます。

### パックの取得元 — ユーザーが選んだアセットパックを入れられるようにする

読むのは同梱の見本パック1つだけで、切り替えは「読む／読まない」しかありません
（[`AssetPack.md`](./engine/AssetPack.md) 2節、[`StartScreen.md`](./ui/StartScreen.md) 画面構成4）。
ローカルのファイル選択（`<input type="file">`）も、URLの入力（外部サーバはCORSが要る）もまだ無く、
`ArrayBuffer` を得る口は `fetch` の側だけです。**見本パック1つで「後から足せる形になっている」ことは
実証済み**——型を足すのも同梱の土地へ patch で差し込むのも通っている——で、遊びは同梱ぶんだけで
完結するので、無くても完成します。

**入れるときは、パックを並べ替えられる画面とセットにします。** 読み込み順は入れる人が並べた順と
決まっている（[`AssetPack.md`](./engine/AssetPack.md) 6.2節）ので、並べる手が無いと規則だけがあって
使えません。**ZIP全体を読んで構わない大きさに収まらなくなったら、中央ディレクトリだけを先に読む形
（HTTPのRange・`File.slice`）へ移します**——今は見本が82KBで、丸ごと読んでいます。

### パックの着脱 — 遊んでいる途中でアセットパックを入れ替える

パックは起動時に1回だけ入って以後不変で、設定を変えてもページを読み込み直すまで効きません
（[`AssetPack.md`](./engine/AssetPack.md) 4節）。絵の在庫表もWorldCodexも起動時に1回組み立てるので、
途中で入れ替えるには両方を作り直すことになります。読み込み直せば同じ状態に行けるので、無くても
完成します。

**入れるときは、開いているセーブとの噛み合いが先に要ります。** セーブは作られたときのパックの並びを
記録し、食い違えば開かない（[`AssetPack.md`](./engine/AssetPack.md) 6.4節）ので、遊んでいる途中で外すと
そのスロットは次から開けなくなります。

### 絵以外の資産 — 音などをアセットパックの在庫表に載せる

ZIPから読むのは定義YAML・絵・表示文字列だけで、他の拡張子は入っていても無視します
（[`AssetPack.md`](./engine/AssetPack.md) 3節）。在庫表は「フォルダの直下を名前→URLで引く」形
（`src/asset-pack/AssetPack.ts`）で絵に固有の作りではなく、ZIPの読み取りは全エントリを保つので、
**今のうちに音を入れたパックを配っておいても、読む側が増えた日にそのまま読めます**。だから無くても
完成します。

**入れるときは、ゲーム本体が音を持つのが先です。** ZIPのトップが `src/assets/` に相当するという規約
（同 3節）で決まるので、同梱ぶんの置き場が決まらないとパック側の位置も決まりません。

## 動かせなかったもの

29文書の未決事項節の約200項目は、大半がここへ移りません。**移す条件は「やるかどうかが決まって
いること」と「入れなくても今の遊びが回ること」の両方**で、片方でも欠けるものは未決事項節に残して
あります。残した理由は次の4通りです。

| 残した理由 | 例 |
| --- | --- |
| **やるかどうかが決まっていない**（大半） | 「解体して部品を回収できるか」「密度の差を効かせるか」 |
| **やると決まっているが、値や形の選択が遊びの内容を変える** | 各スキルのしきい値、怪我の重さ・出血の配分、罠の餌の段 |
| **無いと完成と言えない**（残作業の側） | 欠乏症、槍のレシピ、湧き水から汲む操作、発見物の `volume`/`weight` |
| **未決事項ではなく、本文へ移すべき記述** | 「`weight` の合計が0のときは宣言順で先頭を選ぶ、と実装上決定した」（`GameElementDefinition.md` 17節）、「異種液体の混合は表現できない、が現状の仕様」（`LiquidContainerSystem.md` 9節） |

**3列目は本書の対象外です。** 印を付けて issue にするものですが、要否の判断を通さずに流さない決まりが
あるため（[`.claude/parallel-work.md`](../.claude/parallel-work.md) の「承認の要る未実装を、勝手に
流さない」節）、判断が要るものは issue #656 へ積んでいます。

**4列目は、決着済みなのに未決事項節に残っている記述です。** 本文の書き換えを伴うので、印の付け替えだけを
担当する本作業では動かしていません。
