# スキル一覧

## 概要

本ドキュメントは、ゲームに実際に登場させるスキルの一覧です。スキルがどう伸び、どうレシピを解放するかの
**仕組み**は [`SkillSystem.md`](../engine/SkillSystem.md) が扱います。本書は「どんなスキルを、どの粒度で、
いくつ用意するか」という内容面だけを扱います。

アイテムの内容は [`SurvivalItems.md`](./SurvivalItems.md)・[`Containers.md`](./Containers.md)・
[`Dwellings.md`](./Dwellings.md) を参照してください。

本ドキュメントは検討結果であり、確定仕様書ではありません（`【確定】` の付いた節を除く）。2 節の 11 本は
`src/assets/world-codex/` に投入済みで、どこまで動くかは
[`SkillSystem.md`](../engine/SkillSystem.md) 概要にあります。未決事項は 8 節に整理しています。

## 1. 分類の軸は素材ではなく技術

スキルは、**どの行動同士が習熟を転移させるか**で切ります。「木工」のように素材で括ると、木の器を彫ることと
木の小屋を建てることが同じスキルになりますが、両者は技術をほとんど共有しません。逆に、器を彫ることと
石を打ち欠くことは「削って形を作る」を共有します。

[`SurvivalItems.md`](./SurvivalItems.md) の備考欄にある「柄付け技術」「縫製」「編み」「火で炙って硬化」は、
いずれも素材のカテゴリを横断して繰り返し現れます。これがスキルの単位です。

## 2. 一覧

「系統」は、レシピを解放する**製作**系か、素材・機会へのアクセスを広げる**アクセス**系かの区別です
（アクセス系がどう効くかは 5 節、製作系は 6 節と 7 節）。

**「最初の一歩」の列が、その腕の練習そのものです**（[`SkillSystem.md`](../engine/SkillSystem.md)
3.1 節）——専用の練習アクションは無いので、腕へ時間を投じたいプレイヤーが行うのはこの行動です。
**この列は設計の側の一歩で、その行動が世界に在るかは別です**（どれが無いかは
[`SkillSystem.md`](../engine/SkillSystem.md) 概要）。**腕そのものの立ち上がりは、この列より手前に
来ることがあります**——探索で素材や相手に出くわした時点で伸び始める腕があり、そちらは道具を 1 つも
要りません（同 3.3 節の発見の契機。どの腕にその契機があるかは
`src/assets/world-codex/locations.yaml` の `explore` の `pick`）。

| スキル | 系統 | 最初の一歩 | 主に開けるもの |
| ------ | ---- | ---------- | -------------- |
| **石器** | 製作 | 石を拾って打ち欠く（道具不要） | 石の刃物、斧・ハンマーの頭、石鏃 |
| **繊維・編み** | 製作 | ヤシの葉を素手で編む（道具不要） | 糸、紐、ロープ、肩掛けの袋、編み籠、背負い籠、編んだ葉の衣類、葉を編んだ箱、くくり罠 |
| **木材加工** | 製作 | 石の刃物で太い枝を削る | 木の箱、そり、柄材、板（製材）、火硬化の掘り棒・槍 |
| **指物・接合** | 製作 | 斧で角材を作る | ほぞで組む卓と椅子、本棚、ベッド、高床の骨組み |
| **建築** | 製作 | 枝と葉で雨をしのぐ | 住居の各部品（[`Dwellings.md`](./Dwellings.md)） |
| **皮革** | 製作 | 小動物の皮を剥ぐ | なめし革、皮袋、なめし革の衣類、なめし革の背負い袋 |
| **料理** | 製作 | 下ごしらえ（刻む・串に刺す、2.5 節） | 調理の全般（未設計） |
| **保存** | 製作 | 塩田で採った塩を食べ物にすり込む（2.4 節） | 干物、燻製、塩漬け |
| **火** | アクセス | きりもみ式で枯れ草に火をつける（道具不要） | 着火（＋火硬化、土器の本焼き。保火と高温は炉の側、2.2 節） |
| **狩猟** | アクセス | 尖った石を手に、獣へ打ちかかる（罠を仕掛ける1手には配りません、2.4 節） | 生皮・獣骨・角・肉 |
| **採鉱・製錬** | アクセス | 鉱石を見つける | 青銅（→ 青銅器） |

### 2.1 木材加工と指物を分ける理由

どちらも木を扱いますが、**縛って組む**（木の箱は「木材 + 植物繊維」）のと、**削り合わせて組む**（荷重の
かかるテーブル・本棚はほぞが要る）のは別の技術です。用途で「家具」と括ると素材による分類に逆戻りするため、
接合の方法で切っています。

**台車の車輪は指物ではありません**（`containers.yaml`）。丸太を輪切りにして削り出し、軸を通すだけで、
ほぞは1つも要らないためです。輻を組む車輪を後から置くなら、そちらは指物の側になります。

### 2.2 火と料理を分ける理由

火起こしは摩擦・火口・温度管理という物理的な技術、料理は食材と調理法の知識で、互いに転移しません。また
料理はレシピ数が最も多くなる見込みで、火に含めると「掘り棒を炙ると料理が上達する」という転移になります。

火が担うのは着火と温度であり、開けるレシピは火硬化と本焼きだけです。**このうち、段が動かすのは
着火だけです。**

| 火が担うこと | 決めるのは |
| ------------ | ---------- |
| 乾いた場所で焚き火をつける | **腕**（段が着火の重みへ上乗せを積む、5 節） |
| 種火を保つ | 炉（炉ごとの冷める速さ、[`FireSystem.md`](../engine/FireSystem.md) 6 節） |
| 土器の本焼きに要る高温を出す | 炉（石で囲う、同 5 節） |

保つ長さも高温も炉の側が決めるので、腕は要りません（同 10 節）。**雨の日の屋外は、腕がどれだけ
上がっても開きません**（同 3.1.1 節）——閉じているのは可否で、重みではないためです。

### 2.3 保存を料理から分ける理由【確定】

**干す・燻す・塩漬けは、料理とは別のスキルとして数えます。** 料理は「今日おいしく食べる」、保存は
「乾季まで持たせる」で、目的も覚えることも違います。同じ 1 本にすると、料理を伸ばすだけで保存も付いて
きて、乾季の攻略が 1 本道になります。分ければ、保存を選んだ人がその方向に強くなります。

**出どころ**: [#656](https://github.com/gooyyu1/UnmappedIsland/issues/656)（保存を、料理とは別の腕前として数える）

### 2.4 保存の最初の一歩が、天日干しではなく塩漬けである理由

**天日干しは腕を伸ばしません。** 罠・畑・塩田と同じ「仕掛けて待つ」形で、プレイヤーの操作を1つも
持たないためです——地面へ並べるのも干し場へ掛けるのも枠への出し入れで、干し上がりを起こすのは見えない
タイマーの端です。**タイマーの端には操作者が居ない**ので、そこから腕の持ち主を指せません
（[`GameElementDefinition.md`](../engine/GameElementDefinition.md) 11.5 節「役を書ける場所」——
`on_max`/`on_min` に `agent` は書けません）。腕が伸びるのは手を動かした場面だけなので
（[`SkillSystem.md`](../engine/SkillSystem.md) 3 節）、入口は塩をすり込む操作の側になります
（`src/assets/world-codex/salt.yaml` の `cure`）。

**干し場へ掛けるほうだけを操作にはしません。** 枠へ物を入れる1手には、どの腕も配らないためです
——伸びる量は作業の長さに依らず一律なので（[`SkillSystem.md`](../engine/SkillSystem.md) 3 節）、1手で
済む操作へ配ると最も速い伸ばし方になります（`src/assets/world-codex/characters/player_character.yaml`
の腕前の前書き）。掛けるのだけを例外にすれば、同じ干す行為なのに地面へ並べると伸びず干し場へ掛けると
伸びる、という差も世界に残ります。

**燻製も同じで、腕を伸ばすのは塩漬けのままです。** 燻し小屋も吊るして待つ設備なので、上の 2 つの
理由がそのまま当てはまります（[`SurvivalItems.md`](./SurvivalItems.md) 11 節）。**この腕を読むのは
燻し小屋のほう**（`smoking.yaml` の `smokehouse` の解放条件）なので、燻製から伸ばして燻製を開ける、
という循環にもなりません（[`SkillSystem.md`](../engine/SkillSystem.md) 3.2 節）。

**そのぶん、保存は塩田を据えるまで伸びません。** 塩田は拾える石だけで建ち、腕も道具も要らない
（`salt.yaml` の `salt_pan`）ので、前半に入口が開くという見込み（4 節）は変わりません。ただし
**素手で立ち上がる石器・繊維とは違い、海に面した土地を当てにします。**

### 2.5 料理の入口は、火にかける手ではなく下ごしらえ

**料理の腕は、下ごしらえの操作から伸ばします。** 火にかける手からではありません——天日干し（2.4 節）と
同じで、火にかけた後を進めるのは炉であって人ではないためです。食べ物の `cooking_progress` を毎 tick
押すのは炉の側で（[`FireSystem.md`](../engine/FireSystem.md) 7 節）、プレイヤーが持つのは火にかける1手
だけです。**枠へ物を入れる1手には、どの腕も配りません**（2.4 節）。

**初歩の料理は茹でる・焼くで、その下ごしらえがそのまま上位の料理への練習になります**
（[`SkillSystem.md`](../engine/SkillSystem.md) 3.1 節）。腕が伸びるのは**火にかける手前**——刻む・
串に刺す・皮を剥くといった、**時間を食う人の手**の側です。**保存の入口が干し場へ掛ける手ではなく塩をすり込む
操作になっているのと、同じ形です**（2.4 節）。**入口をどちらに置くかはユーザーが決めましたが、暫定の
まま置いています**——`【確定】` を付けていないので、覆す提案を出してかまいません。

**世界にあるのは、タロイモを刻む手だけです**（`src/assets/world-codex/foods.yaml` の `chop`）。刃物を
当てて刻むと料理の腕が伸び、刻んだ芋は火の通りが速くなります——**払った手間が返るのは火の通りの側**で、
炉が渡す熱への上乗せとして持ちます（[`FireSystem.md`](../engine/FireSystem.md) 7 節の進みを押す側は
炉のまま）。そのかわり切り口から傷むのが速いので、**刻むのは火にかける直前**になります。

**置けたのがこの芋だけなのは、線が 2 本重なるからです。** **返るのが火の通りなので、置ける先は生のままで
火にかける食べ物だけです**——青いヤシの実も海鳥の卵も（`coconut.yaml`・`voyage.yaml`）、刻んで返るものを
持ちません。**そのうち保存の軸を持たないのがこの芋だけです**：軸の値の組は 1 本ずつしか作られないので
（[`GameElementDefinition.md`](../engine/GameElementDefinition.md) 3.5.1 節の、変種の変種は作らない）、
干す・燻す・漬ける先を持つ生肉・死体・ヤシガニを刻むと、その先を丸ごと失います。

**開けるレシピはまだありません**（調理の全般が未設計、2 節）。腕が効くのは下ごしらえ自身の速さだけです
（7 節）。

## 3. 柄付けをスキルにしない理由

「紐で頭部を軸に固定する」技術は [`SurvivalItems.md`](./SurvivalItems.md) の7アイテムに共通しますが、
スキルにはしません。固有の素材も固有の入手経路も持たず、**入力は紐（繊維）・頭部（石器または製錬）・
軸（木材加工）だけ**だからです。

これをスキルにすると、柄付けを使うアイテムが全てグレード2以上であるため、伸ばす手段が自分自身に依存して
永久に開きません（[`SkillSystem.md`](../engine/SkillSystem.md) 3.2 節）。代わりに条件の連言で表します。

```yaml
石の斧: 石器 basic + 繊維・編み basic
槍:     石器 basic + 繊維・編み basic + 木材加工 basic
青銅の斧: 採鉱・製錬 basic + 繊維・編み skilled
```

「刃を作れて、紐も作れるようになったら斧が作れる」が、そのまま柄付け技術の要求を表しています。

**軸が木材加工を要求するのは、拾ってこられない軸だけです。** 斧と突き銛の柄は拾った太い枝（70cm）が
そのまま柄になりますが、槍の2mの軸は落ちていない（[`SurvivalItems.md`](./SurvivalItems.md) 0 節）ので、
若木を切って採った長い棒を削って軸にします。**削り出す工程が入るぶんだけ、連言が1本増えます。**

## 4. 配分

- **必須は石器と繊維・編みだけ。** どちらも道具なしで立ち上がり、他の多くのスキルの前提になります
- **残りは選択。** 1回のプレイで実用域へ届くのは3〜4個の見込みなので、上げきれない分が残り、
  プレイごとに異なる進行になります
- **前半（最初の乾季まで）に入口が開くのは** 石器・繊維・木材加工・火・狩猟・皮革・料理・保存・建築
- **入口が後半に開くのは** 指物・採鉱・製錬。どれも前半で立ち上げた腕の上に積みます

**入口が開く時期と、レシピが厚いのがどちらかは、別の軸です。** 皮革・料理・建築は前半に入口が開きますが、
開けるレシピは後半のほうが厚くなります——乾季を攻略した後に残るのは暮らしを厚くする仕事で、これらが
開けるのはその仕事に要る物だからです。入口が後半に開くほうは、厚みも後半にあります。

**ただし、メンタルの低下への対抗手段そのものは腕を1つも要求しません。** 里心を抑える設え
（[`ContentSkeleton.md`](./ContentSkeleton.md) 3 節の系統12）は解放条件を持たず、いちばん軽い経路は
刃物1本で積めます——**対策が、ほかの系統の進み具合の後ろへ回らないため**
（[`Characters.md`](./Characters.md) ホームシック節）。後半のスキルが開けるのは、ほぞ組みの家具の
ようにまだ世界に無い物のほうです。

## 5. アクセス系は、重みへ積まれる上乗せで効く

アクセス系（火・狩猟・採鉱）はレシピを開けません（2 節）。段の効き方は、**`pick` の重みへ積まれる
上乗せ**です。上乗せは腕の持ち主が持ち（素は 0）、自分では動かず、腕の段の `passives` が `modify` で
押し上げます。使う側は、その重みが読むプロパティの `base`
（[`GameElementDefinition.md`](../engine/GameElementDefinition.md) 6.5 節）に腕を置きます——`base` の
土台には操作の役を書けるので、**火口も土地も自分の側の値を持ったまま、今それを使っている人の腕を
継ぎます**。重みの側は `{prop: ...}` のままで、式は 1 つも書きません。**相手の側の値が素の値だけとは
限りません**——火口は自分の湿り具合でも同じ重みを押し下げます
（[`FireSystem.md`](../engine/FireSystem.md) 3.2.1 節）。腕から見れば、押し下げた後の値を土台にする
だけで変わりません。

| 腕 | 積む先 | 素の値を持つのは |
| -- | ------ | ---------------- |
| **火** | 着火が成功する重み（[`FireSystem.md`](../engine/FireSystem.md) 3.1 節） | 火口（`ignition_chance`） |
| **狩猟**（出くわす） | 探索と見張りで獲物に出くわす重み（[`ExplorationSystem.md`](../engine/ExplorationSystem.md) 2.1 節） | 土地（`<動物>_find`）と海区（`shoal_find`・`seabird_find`） |
| **狩猟**（当てる） | 打ちかかった一撃が当たる重み（[`HuntingSystem.md`](../engine/HuntingSystem.md) 1.2 節）と、突き漁で獲れる重み（[`Voyage.md`](Voyage.md) 3.9.2 節） | 武器（`heavy_blow`・`light_blow`・`thrust`）と、筏・魚の群れ（`catch_chance`） |

刻みは上乗せごとに違います。

| 段 | novice | basic | skilled | expert |
| -- | ------ | ----- | ------- | ------ |
| 火（`ignition_ease`） | 0 | +20 | +50 | +120 |
| 狩猟・出くわす（`quarry_sense`） | 0 | +1 | +2 | +4 |
| 狩猟・当てる（`hunting_aim`） | 0 | +10 | +20 | +40 |

**上乗せの刻みを揃えられないのは、上乗せする先の桁が違うから**です——着火の重みは 60 前後、獣のつまみは 2〜4、
当てる側は 15〜78 で、同じ数を足せば片方は効かず片方は跳ねます。**狩猟が 2 本持つのも同じ理由**で、
出くわすつまみ（2〜4）を動かす刻みは当たり所の重み（55〜70）の前では見えません。**同じ刻みで全部に
効かせられるのは倍率だけ**ですが、掛け算はこの世界の文法に無く、合成の器（`modify`・`base`）はどちらも
加算です（[`GameElementDefinition.md`](../engine/GameElementDefinition.md) 10.2 節）。

**当てる側の中でも幅はあります。** 武器の当たり（55〜70）と魚の群れ（78）は同じ桁ですが、群れの居ない
海面（15）だけは 1 桁下で、`expert`（+40）では 3.7 倍になります——**同じ刻みが最も強く効く場所**で、
群れとの落差が縮む形で現れます（[`Voyage.md`](Voyage.md) 3.9.2 節）。3 本目を足してまで分けるほどでは
ないと見て、当てる側は 1 本のままにしています。

**直接突く手にも積みます。** 獣を殴る `strike` は武器が名乗る当たり所の重みが、突き漁の
`spear_sea`・`spear_shoal` は筏と群れが名乗る釣果の重みが、**当てる腕を土台にします**。海鳥を捕る
`catch_seabird` は `pick` そのものを持たず（必ず獲れる）、積む先がありません。

**積むのは、その卓で最も太い当たり方 1 つだけです。** 当たり方の数だけ積むと、2 つ名乗る石斧だけが
倍受け取り、**配分の合計を 100 に揃えた意味**（[`HuntingSystem.md`](../engine/HuntingSystem.md) 1.2 節）
が実効値で崩れます。1 つに限れば `expert` でどの武器も卓が 105 → 145 になり、仕留めの割合は武器に
よらず同じままです。尖った石の強打（`heavy_blow: 0`）のように 0 を宣言した当たり方へ積まないのも同じ
理由で、積むと腕が上がるだけでその武器に無いはずの一撃が出ます。**土台を持つのは値を名乗った側だけ**
なので、`weapon` trait は土台を持ちません。

**出くわす機会の側にも、積まないつまみが 1 つあります。** ヤシガニ（`crab_find`）は `<動物>_find` と
同じ形ですが、定義は `item` で警戒も手番も持たず、獲るのに狩猟の腕を配る操作もありません——**拾う物
なので、腕が気づく相手になりません**。積むのは、腕を配る操作を持つ相手を湧かせる候補だけです
（`tests/world-codex/skillsYaml.test.ts` がその対応を見張ります）。

- **素の値は相手が持ち、腕は上乗せだけを持ちます。** 枯れ草とヤシの実の皮で火の付きやすさが違うのは
  火口の差、荒野とジャングルで獣に出くわす頻度が違うのは土地の差です。**腕の側に相手ごとの値を
  書かないので、火口や土地が増えても腕は 1 行も変わりません。** 相手の側も、同じ種類の相手は同じ
  上乗せを土台にします——火口はどれも `ignition_ease`、獣のつまみはどれも `quarry_sense` です
  （`tests/world-codex/skillsYaml.test.ts` が見張ります）。
- **積む相手が居なければ、何も起きません。** 土地が宣言していない獣のつまみはそもそも卓に無いので、
  腕がいくら高くても出くわしません。**探索で腕が増やすのは獣そのものではなく、居る獣に気づく確率です。**
  当てる側も同じで、その武器が 0 を宣言した当たり方は卓に無く、腕が上がっても出ません。
- **そのぶん、探索で実りの出る割合は下がります。** 押し上げるのは獣の候補の重みだけですが、卓の合計が
  増えるので他の候補の相対確率は落ちます（数字は
  [`ExplorationSystem.md`](../engine/ExplorationSystem.md) 2.1 節）。**腕を上げた探索は獣へ寄る**、が
  加算だけで出ます。**当てる側でも同じことが起きます**——下の空振り・仕留めがそれです。
- **空振り（`whiff`）には積みません。** 当たる側だけを押せば、卓の合計が増えるぶんで外れの割合は
  自然に落ちます。外れにも積むと、腕が上がるほど空を切る形になります。
- **仕留めの重み（`vulnerability`）にも積みません。** 桁が違う（起きている獣で 5、気絶した獣で
  200 超）ので、当たり所と同じ刻みは効きません。**そのぶん、当たり所が太った卓では仕留めの割合が
  相対的に落ちます**が、気絶させてから仕留める流れは変わりません——気絶した相手の無防備さは
  当たり所の合計より大きいためです。
- **加算なので、相手ごとの差は腕を上げるほど埋もれます。** 枯れ草（60）とヤシの実の皮（100）の差は
  `expert`（+120）では 180 対 220 まで縮み、**火口を選ぶ判断は腕が上がるほど軽くなります**。獣の側も
  同じで、上乗せの総量は獣の種類の数に比例します。**火口の差が埋もれることも、獣の種類が多い土地ほど
  腕が報われることも狙いどおりです**（5.2 節）。**当てる側だけは逆**で、
  積むのが卓に 1 つなので、石斧の強打対浅打（60 対 15）は `expert` で 100 対 15 へ開きます——**腕が
  上がるほど、その武器が得意な当たり方へ寄ります。**
- **狩猟は罠には効きません。** 罠の抽選は誰も操作していない場面で走るため、罠から腕の持ち主が
  見えません（[`TrapSystem.md`](../engine/TrapSystem.md) 8 節）。**腕が動かせるのは、腕の持ち主が
  そこに立って手を出している場面だけです。**
- **採鉱・製錬には積む先がありません。** 鉱石も製錬もこの島にまだ無いので、上乗せも持たせていません。

### 5.1 見せ方は、段の名前だけ

**上乗せの値を、画面が自分から出すことはありません。** 出すのは段の名前と段内進捗だけ
（[`SkillSystem.md`](../engine/SkillSystem.md) 5 節）で、腕が上がったことは**結果の頻度**として現れます。
上乗せのためのバーも数字も増えません。

出せる 1 つの数字が無いからです。実際の成功率は「（相手の側の値＋上乗せ）÷ 卓の合計」で、火口ごと・
土地ごとに違ううえ、火口では同じ 1 枚でも湿り具合で動きます（[`FireSystem.md`](../engine/FireSystem.md)
3.2.1 節）。上乗せ（+50）だけを出せば読み手はそれを成功率として受け取り、成功率を出すなら火口と土地の
一覧を腕の隣に並べることになります。

**腕前の詳細には「与えている影響」の記号が並びます**（[`Windows.md`](../ui/Windows.md) 8 節）。上乗せの
本数ぶんです。`modify` を持つプロパティなら何であれ並ぶ仕組みが、その
まま拾ったものです。値ではなく相手の記号だけなので、上の「1 つの数字を出さない」とは食い違いません。

**その枠を押せば上乗せ自身の詳細が開きます**（同 8.2 節）。そこも数値を出さない面ですが、**そこから
固定表示にすれば、行は上乗せの値そのものを出します**——`range` も段も持たないため、行が出せるものが
値しかないからです（[`StatusArea.md`](../ui/StatusArea.md) 9 節）。**ユーザが自分で選んだときだけ
現れる**ので上の約束とは食い違いませんが、そこに出る数字は分母を持ちません。

### 5.2 火口ごと・土地ごとの調整を入れない理由【確定】

**上乗せは加算のままとし、火口ごと・土地ごとに効き方を変える調整は入れません。** 加算から出る偏り
（5 節）は、狙いどおりのものです。

- **腕が上がるほど、火口を選ぶ判断は軽くなります。** 上達すれば手近な火口で足りるようになるのは、
  上達として自然だからです。
- **獣の種類が多い土地ほど、腕が報われます。** 豊かな狩り場と乏しい狩り場の差が腕とともに開くのは、
  狩り場の格差として自然だからです。

**出どころ**: [#656](https://github.com/gooyyu1/UnmappedIsland/issues/656)（腕前の上乗せは加算のままとする）

## 6. 製作系も、作る速さと歩留まりへ効く【確定】

**製作系の腕は、レシピを解放するだけでなく、作る速さと歩留まりへも効きます。** 採った理由は**伸ばす意味が
常にあること**です——解放だけだと、その腕が開けるレシピを出し切った時点で伸ばす意味が消えます。**代償として
数値の調整が増えること**は織り込んでいます。

**効き方は、行動ごとに個別に宣言します。** 全行動が読む共通の上乗せプロパティを 1 本置いて、そこを全員が
読む形にはしません。**効き始める段も、効く先（時間・収量・成功率）も、行動ごとに違ってかまいません。**
**理由は「どちらが増減するか」です**——腕の数は増減しにくく、行動の数は増減するので、**組み合わせで決まる
ものは、増減する側が宣言します。** 共通の 1 本にすると、そこを触るたびに世界じゅうの所要時間が動き、
**行動の長さが tick の格子から外れます**（[`ActionSystem.md`](../engine/ActionSystem.md) 6.2 節）。

**時間が 50% 縮むこと自体は禁じません。** 長いクラフトチェーンの序盤のように**何度も繰り返す行動**なら、
そこが速くなることが全体の効率とプレイ体験の向上として現れるので、大きく効いてかまいません。

**出どころ**: [#656](https://github.com/gooyyu1/UnmappedIsland/issues/656)（製作系の腕前も上手さに効かせる）・
[#2185](https://github.com/gooyyu1/UnmappedIsland/issues/2185)（腕の効き方を行動ごとの宣言にする）

## 7. 製作系の積み方

**歩留まりの押し上げ方はアクセス系と同じ形**です（5 節）——腕の段の `passives` が `modify` で上乗せを
押し上げ、使う側はその 1 つを読むだけ。**歩留まりは、同じ材料から取れる量として持ちます。**

**速さはそうしません。どの腕が・どの行動を・どの段から・何分縮めるかは、行動の側が個別に宣言します。**
手で作る操作（`interactions`）はその操作の所要時間の `passives` で作り手の腕の段を読み
（[`GameElementDefinition.md`](../engine/GameElementDefinition.md) 11.3 節）、レシピは `deftness` で名乗り
ます（同 13.6 節）。

| 効き先 | 宣言する場所 | 素の値を持つのは |
| ------ | ------------ | ---------------- |
| **速さ**（手際） | 手作業は `<操作名>_minutes` の `passives`、レシピは `deftness` | 作る相手（操作・工程が宣言した時間） |
| **無駄の無さ** | 腕の段が押し上げる `<腕>_thrift` を、作る相手の `pick` が読む | 作る相手（素は 0） |

| 段 | novice | basic | skilled | expert |
| -- | ------ | ----- | ------- | ------ |
| 無駄の無さ（`<腕>_thrift`） | 0 | 10 | 25 | 60 |

速さを行動ごとに宣言する理由は 6 節が持ちます。ここに書くのは、その枠の中で**今どう置いてあるか**です。

- **今は引く分数を 15 分**（tick の刻み 1 つ）**で揃えてあります。** 加算なので**1 回の手が短いほど、
  割合として大きく効きます**（撚る 30 分 → 15 分は半分）。**大きな仕事は手の数で表す**ので
  （[`ActionSystem.md`](../engine/ActionSystem.md) 6.3 節）、**縮む分もその数だけ積まれます**——木を
  1 本倒すのに 60 分の手を何度か入れる者には、その回数ぶんが返ります。**割合を決めるのは 1 回の手の
  長さだけで、仕事の大きさは決めません。**
- **効き始める段は、その行動を何度行うかで分けます。** 何度も繰り返す手は `skilled` から、数えるほど
  しか行わない大物は `expert` から。**「何を作るか」ではなく「何度その手を動かすか」で切ります**
  ——同じ衣類でも、葉を束ねる一着は繰り返す側、裁って縫う革の一着は数えるほどの側です。
- **素が tick の刻み 1 つ（15 分）の行動は、速さを名乗りません。** そこから縮める先が無く、名乗っても
  誰にも効かない宣言になります。**腕で縮めたい短い手は、刻み 2 つ（30 分）から始めます**——半分に
  なってちょうど刻み 1 つです。
- **縮めた先が 15 分を割る宣言はロード時に弾かれます**（[`ActionSystem.md`](../engine/ActionSystem.md)
  6.2 節）。黙って下限で止めると、格子から外れた宣言が世界に残ります。
- **手際が動かすのは経過する時間だけで、進捗は動きません。** 工程が宣言するのは仕事の量で、片付いた量は
  腕によりません——進捗の上限（[`RecipeSystem.md`](../engine/RecipeSystem.md) 1 節）がロード時に決まったまま
  でいられるのはこのためです。手で作る操作は進捗を持たないので、経過する時間がそのまま所要時間です。
- **速くなるのは、その腕を配る操作すべてです**（[`SkillSystem.md`](../engine/SkillSystem.md) 3 節の実行経路）。
  伸びる場面と速くなる場面を揃えておけば、**どの操作が腕の仕事かを決める軸が 2 本に割れません**
  ——素材を採るだけの操作に腕を配らないのと同じ線がそのまま効きます
  （`src/assets/world-codex/characters/player_character.yaml` の腕前の前書き）。
  `tests/world-codex/skillsYaml.test.ts` が、配る側と速くなる側の食い違いを見張ります。
- **無駄の無さは「余る」側へ積みます。** 腕が低いとしくじって素材を失う形にはしません——失った分を採り
  直して同じ物をもう一度作ることになり、**罰としてやり直しを課す**ことになるためです
  （[`DesignPrinciples.md`](../concept/DesignPrinciples.md)「失敗の罰に、同じ作業のやり直しを課さない」）。
  腕が低くても物は必ずでき、腕が高いと同じ材料から余分が取れます。**しくじる側ではなく余る側へ積むのは、
  アクセス系が空振りへ積まないのと同じです**（5 節）。
- **余分の卓を持つのは、まとめて取れる物だけです。** 素の値は作る相手が持つので、卓を宣言していない物には
  腕が上がっても何も起きません（5 節「積む相手が居なければ、何も起きません」と同じ）。**同じ材料から何枚
  取れるか**という見方は既に世界にあります——ヤシの葉は中軸で割れば 1 枚から 2 枚取れます
  （`src/assets/world-codex/weaving.yaml`）。斧のように 1 つしかできない物は卓を持たず、腕は速さだけに
  効きます。**足せる量にも上限があります**（7.2 節）。
- **まとめて取れても、数が材料の作りで決まっているなら卓を持ちません。** 手で作る操作の側で卓を持つのは
  繊維を採る入口（`fiber.yaml` の `strip`・`coconut.yaml` の `ret`）だけで、どこまで髄を落とすかが取れる束を
  決めるのはそこだからです。**同じ 2 枚でも、葉を割って編むほうは持ちません**——2 枚取れるのは中軸を
  割ったからで、刃物が決めた数に腕を足すと葉に無い 3 枚目が出ます。解体も同じで、出る数は死体の重さの
  内訳が決めています。**同じ物を出す入口が複数あるなら、卓も揃えます**——配る腕を揃えるのと同じ理由で
  （`src/assets/world-codex/characters/player_character.yaml` の腕前の前書き）、片方だけが余分を出すと、
  どの島に流れ着いたかが歩留まりに化けます。
- **レシピでは、どの腕が効くかをレシピ自身が名乗ります**（`deftness`、
  [`GameElementDefinition.md`](../engine/GameElementDefinition.md) 13.6 節。同じ節の `surplus` を名乗れる
  レシピは在りません、7.2 節）。上位のレシピは複数の腕を連言で
  要求しますが（[`SkillSystem.md`](../engine/SkillSystem.md) 4.1 節）、**速さを決めるのは名乗った
  1 つ**です。合わせようとすると、`base` の土台は 1 つしか持てないので
  （[`GameElementDefinition.md`](../engine/GameElementDefinition.md) 6.5 節）合計を持つプロパティが
  別に要り、**合成の器が 2 つ目**になります（[`DesignPrinciples.md`](../concept/DesignPrinciples.md)「合成の器を
  2 つ目にしない」）。
- **積む先が無い腕には、歩留まりの上乗せも持たせていません。** 開ける物が世界にまだ 1 つも無い腕がそれで、
  持たせても読む相手が居ません（5 節「積む相手が居なければ、何も起きません」と同じ）。
- **速さのほうは、開けるレシピが無くても効きます**——手を動かす操作があれば、その操作が自分で縮む分を
  宣言できるからです。料理がそれで、縮むのは下ごしらえの時間です（2.5 節）。

### 7.1 どのレシピがどの腕の仕事か

**名乗りは解放条件とは別の宣言です**（[`GameElementDefinition.md`](../engine/GameElementDefinition.md)
13.6 節）。**解放を要求しないレシピも手際を名乗ります**——腕が 0 の者も今までどおり作れて、上げた者だけが
速くなります。解放を置かない理由（素材チェーンが既にゲートしている、最初の 1 着を腕で塞がない、腕の入口と
循環する）は、どれも「腕が上がっても速くならなくてよい」とは言っていないからです。**名乗りまで省くと、
同じ技術の仕事なのに腕が効くものと効かないものが並びます**——撚る仕事そのものである縄が、同じ繊維で結ぶ
くくり罠より遅いまま、といった形で。

**どの腕かは、その工程で手を動かしている技術で決めます**（素材ではなく技術で切る、1 節）。

| 工程でしていること | 名乗る腕 |
| ------------------ | -------- |
| **保たせるための造作を組む**（食べ物を掛けて保たせる設備） | **保存**（**先に当てる**。下の「行が重なったら」） |
| 石を打ち欠く | 石器 |
| 木を削る・木を縛って**組む**（骨組みになる物） | 木材加工（ほぞで組む物なら指物ですが、そう組む物はまだありません。2.1 節） |
| 繊維を撚る・編む・結ぶ・巻く（**留めるだけで、骨組みを組まない物**） | 繊維・編み |
| 皮を扱う（なめす・縫う・穴を開けて形を取る） | 皮革 |

- **行が重なったら、上の行を先に当てます。** 保存の行だけが**何のための造作か**で切っていて、手つきで切る
  下の行と必ず重なるからです——干し場は枝と縄を縛って組む物でもありますが、**同じ保たせる造作である
  燻し小屋が保存を名乗っている**以上、そちらへ揃えます。**同じ仕事の 2 つ目の設備で腕が食い違うほうが、
  手つきの取り違えより害が大きい**（`tests/world-codex/skillsYaml.test.ts` が、同じ物を出す操作について
  同じことを見張っています）。それでも重なるのは保存の行だけなので、当てる順はこの 1 つで足ります。
- **名乗れるのは 1 つ**（13.6 節）なので、**工程で技術が分かれる物は、長いほうを名乗ります**——丸太を
  くり抜いて生皮を張る太鼓は、くり抜きのほうが長いので木材加工です。
- **どの行にも当たらない仕事は名乗りません。** 担う腕が一覧（2 節）に無いか、あっても手つきが違うもので、
  石を並べるだけの塩田がそれです（石を使うことは、石を打ち欠く仕事であることを意味しません）。
  **名乗らないと決めた側は、そのレシピのコメントに理由を書きます。**
- **行に当たっていても、縮める先が無ければ名乗りません。** 工程が tick の刻み 1 つ（15 分）なら、そこから
  引ける分数が無いためです（[`ActionSystem.md`](../engine/ActionSystem.md) 6.2 節）——名乗っても誰にも
  効かない宣言になり、**上の「腕が効くものと効かないものが並ぶ」を名乗りでは直せません。** 直すなら
  工程の側を刻み 2 つにします（7 節）。**この理由で名乗らない側も、コメントに理由を書きます。**
- **伸ばす操作をまだ持たない腕には名乗らせません**（2 節でそう断ってある腕）。上げようのない腕が速さを
  握ると、誰にも縮められない時間になります。
- **アクセス系も名乗りません**（5 節）。火が決めるのは着火の重みだけなので、火起こし具を削る速さは
  木材加工が決めます。
- **名乗らない側と、名乗ってよい腕は `tests/world-codex/skillsYaml.test.ts` が見張ります**——新しいレシピは、
  名乗るか、名乗らない側として数え上げたうえで理由をコメントに書くかのどちらかを選ばないと落ちます。
  **どの行を当てるのが正しいかは見ていません**（それは内容の判断で、拠り所はこの節と各レシピのコメント）。

### 7.2 余分は、もとの産出の 1/3 まで【確定】

**腕が引く余分の卓が足してよいのは、素の産出の 1/3 までです。** もとが 3 つの物が 4 つになる程度で、
腕が上がったからといって 1 つの物が 2 つになるような卓は置きません。**縛るのは卓だけです**——道具が
広げる歩留まり（刃物で中軸を割れば葉が 1 枚から 2 枚、`src/assets/world-codex/weaving.yaml`）は、
腕ではなく持ち物が決めるので、ここの上限には掛かりません。

- **余分を足せるのは、素が 3 つ以上ある卓だけです。** 物は割れないので、素が 2 つの卓は 1 つ足しただけで
  +50% になり、この上限のもとでは卓そのものを持てません。**まとめて取れるかどうかは、卓を持ってよいかの
  必要条件でしかありません**（7 節）——いくつまとめて取れるかで、持てるかが決まります。
- **レシピは卓を持てません。** 成果物は 1 つなので（[`RecipeSystem.md`](../engine/RecipeSystem.md) 1 節の
  `become`）、余分を 1 つ足せば必ず倍になります。**文法（`surplus`、
  [`GameElementDefinition.md`](../engine/GameElementDefinition.md) 13.6 節）は残っていますが、世界に
  使い手は居ません。**
- **上限は「当たったときの増分」で置きます。** `pick` は枝を 1 つしか引かないので、当たりやすさをどう
  変えても増分は当たりの枝を超えません——**上限を満たす卓は、平均で見ても同じ水準に収まります。**
  刻み（`<腕>_thrift`）の側で期待値を合わせる必要はありません。

**出どころ**: ユーザーの判断（2026-09-14、
`agent-ops/decisions/2026-09-14-craft-randomness-and-surplus-scale.md`）

`tests/world-codex/skillsYaml.test.ts` が見張ります。**拾い方は在り処ではなく重み**——枝の重みが
`<腕>_thrift`（上の表）を読んでいれば、レシピの `surplus` でも手作業の `pick` でも同じ 1 本に掛かるので、
**名指しで数え上げていない分、新しく足した卓も掛かります。** 余分を `spawn` 以外で渡す枝は、出す物が
無いものとして落ちます。
