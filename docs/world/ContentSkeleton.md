# コンテンツの骨格

## 概要

本ドキュメントは、**1周回に何がどれだけ要るか**の骨格を決めます。系統が何本か・各系統が何段か・終盤に
何が要るか・アーティファクトが何種類か、そして航海の決着（[`GameEndings.md`](../concept/GameEndings.md)
12節）で増えた海区と遠征先の小島で何が採れるかです。

**個々のレシピは決めません。** 工程の分割・所要時間・材料の個数は幅出しの仕事です。各系統の中身は既存の
カタログ（[`SurvivalItems.md`](./SurvivalItems.md)・[`Containers.md`](./Containers.md)・
[`Dwellings.md`](./Dwellings.md)・[`Bedding.md`](./Bedding.md)・[`Animals.md`](./Animals.md)・
[`Voyage.md`](./Voyage.md)）が持ち、本書はそれらを「何本・何段」として数え直し、足りない箇所を指すだけ
です。スキルの粒度は [`Skills.md`](./Skills.md)、航海の遊び方は
[`GameEndings.md`](../concept/GameEndings.md) 12節が持ちます。

**新設した文法はゼロです。「系統」も「段」もエンジンには写しません。** 型の側に段を表すプロパティは
持たせず、段はレシピの要求（スキルと材料の連言、[`Skills.md`](./Skills.md) 3節）が結果として作ります。
本書が持つのは数え方だけで、その数え方は**区間によって変わります**（2節）。

在処は、数え直しの材料として使った [`stats/balance.yaml`](../../stats/balance.yaml)（`npm run
stats:balance` の生成物）・[`stats/climate.yaml`](../../stats/climate.yaml)・
[`stats/terrain.yaml`](../../stats/terrain.yaml)と、`src/assets/world-codex/terrain_generation.yaml` の
`island.site_count` です。読み方は [`docs/diagnostics/`](../diagnostics/README.md) の各文書が持ちます。
本書自身に対応する定義・実装はありません。

**生成物から書き写した数値には、出どころのキーを名乗る印（HTMLコメント）が付いています。**
再生成で値が動いたときに本書だけが古いままにならないよう、
[`tests/docs/docStatsCitations.test.ts`](../../tests/docs/docStatsCitations.test.ts) が印の指す先と
突き合わせます。**印が付くのは書き写した数値だけ**で、そこから導いた数値（158日・176日など）は
対象外です。

**確定しているのは 5.1 節（望遠鏡を置かず山頂が担う）・6 節（アーティファクトの数）・8.1.1.1 節（夜の
空は月あかりを項として持たない）だけで、他の節は暫定です。** とりわけ8節の日数は、2つの仮置き
（屋外の割合・土地の配分）に支配されているので、桁の話として読んでください。

## 1. 系統は「繰り返し払う支出」で割る

**系統とは、プレイヤーが繰り返し払っている1つの支出と、それを安くしていく手段の連なりです。支出を
数えれば、系統が数えられます。**

割り方の候補は3つありました。

- **材料の出どころで割る**（石・木・繊維・獣・土・鉱）。採りません。プレイヤーが欲しいもの——住居・
  容器・船——はどれも材料をまたぐので、1本の系統が完結しません。幅出しを並列に流すときも、石の系統と
  木の系統が同じ住居の定義を取り合います。
- **道具の用途で割る**（切る・叩く・掘る・突く）。採りません。「切る道具」と「叩く道具」を分けても、
  どちらも石を打ち欠く同じ労働なので、品数は増えても支出は減りません。用途は系統ではなく、**1つの段の
  中の幅**です。
- **支出で割る。** 採ります。埋めるものが違えば手段が転移しないので、系統どうしが干渉しません。

支出で割ると、系統の本数は「プレイヤーが何に繰り返し払っているか」の本数に一致し、こちらの都合で
増減できなくなります。これが本数を数える根拠になります。

## 2. 段の物差しは、区間で変わる

**足止めしているものが区間で違うので、段の切り方も変えます。開始直後は不確実性が、それ以降は労働の量が
足止めします。**

| 区間 | 足止めしているもの | 段の切り方 |
| --- | --- | --- |
| **開始直後** | 知らないこと。探索が終わっていないので次にどこへ行けるかも、行った先に何があるかも分からない。在庫が無いので最悪を想定するしかない | 1段だけ。完了条件は2.1節 |
| **それ以降** | 払う労働の量 | 1日（1440分）以上の労働がかかる山を1段と数える |

**平均値の表は開始直後には当てはまりません。** [`stats/balance.yaml`](../../stats/balance.yaml) の
`chain_routes` の分数は、どの経路も選べて `pick` の期待値どおりに引ける前提の数字です。開始直後のプレイヤーはどちらの
前提も満たしていないので、表の分数はその区間の重さを表しません
（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の
「何が足止めしているかは区間で変わるので、段の物差しも変える」節）。

**1日未満で越えられる前提は、段ではなく幅です**（同「段は、実際に足止めしたものだけを数える」節）。
実測では、刃物（72.2分<!-- stats: balance.yaml object_costs object=sharp_stone total_minutes -->）・焚き火（55.9分<!-- stats: balance.yaml object_costs object=campfire total_minutes -->）・くくり罠（103.3分<!-- stats: balance.yaml object_costs object=snare total_minutes -->）・覆い焼きの炉（303.8分<!-- stats: balance.yaml object_costs object=earth_kiln total_minutes -->）はいずれも
0.04〜0.21日で、どれも段になりません。4桁の労働がかかるのは筏（4,305分<!-- stats: balance.yaml object_costs object=raft total_minutes -->）と帆（4,449分<!-- stats: balance.yaml object_costs object=rawhide_sail total_minutes -->）だけです。

**この物差しは道具が判定します。** `npm run stats:balance` の総コストがそのまま「段かどうか」を決めるので、
幅出しで物が増えたときに数え直しが要りません。

### 2.1 最初の段は、アクセスの確保と数日分の備え

**開始直後の段が終わるのは、主要な資源へ手が届き、数日死なない量の水と食料を確保した時点です。**

- **アクセスの確保** — 石・繊維・木・水源・食料が採れる土地への道が見つかっていること。開始地点は砂浜で
  （`IslandSpawner.placePlayer` が `sandy_beach` を優先）、**砂浜には石も小枝も枯れ草もありません。**
  最初の仕事は、隣に何があるかを知ることです。
- **数日分の備え** — 最悪を想定しなくてよくなる量。

この2つが揃った時点で、プレイヤーは初めて「明日どうするか」を選べます。**それまでは選択肢が
「今日死なないこと」に固定されているので、労働の量で段を切っても何も表しません。**

### 2.2 切るものと火は、目的にせず最初の段の中で配る

**刃物と火は仕組みの上では本物の前提ですが、プレイヤーが追う目的としては置きません。**

前提としては外せません——水の経路は3本とも `cutting_tool` を要求し（[`stats/balance.yaml`](../../stats/balance.yaml)
の `chain_routes` の `property: hydration`）、タロイモもヤシガニも火が要ります（[`Animals.md`](./Animals.md) 1節）。外すと組み立てが
崩れます。

目的にしない理由は、目的にした瞬間、まだ何も知らないプレイヤーへ「石を探せ」という指示を出すことに
なるからです（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の
「仕組みの前提を、プレイヤーの目的にしない」節）。目的は生きる手段の確保に置き、刃物と火はその途中で
自然に手に入る道具として配ります。

### 2.3 開始地点は、最初の段を越えられる地点から選ぶ

**生成された島を測って、最初の段を越えられる地点だけを開始地点の候補にします。生存が成立することを、
生成の保証（`guarantees`）では作りません**（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の
「生成への保証は島の顔を作る道具で、生存を成立させる道具ではない」節）。

保証そのものは使えます——山がある島・湖がある島といった**その島が何であるかを決める**のは保証の仕事
です。生存の側でだけ第一選択にしない、という切り分けです。

測るのは、開始地点から道をたどって、生きるのに要るものが何歩以内に揃うかです。今の分布は次のとおりで、
**1つの土地で全部は揃いません。**

| 要るもの | 出どころ |
| --- | --- |
| 火口 | 枯れ草（草原・荒野） |
| 錐 | 小枝（森・密林・岩石地・荒野・山腹） |
| 軸 | 太い枝（砂浜・岩礁海岸・断崖海岸） |
| 刃 | 石（岩礁海岸・断崖海岸・岩石地・荒野・山腹・山頂） |
| 水 | ヤシの木（砂浜・密林）・湧き水（草原・森） |
| 道具の要らない食料 | 空心菜（草原・密林） |

**砂浜から始めると、この表がそのまま最初の数日の道順になります。** 砂浜にあるのは太い枝とヤシの実と
ヤシガニだけで、ヤシの実は割るのに刃が要り、ヤシガニは焼かないと食べられません
（[`Animals.md`](./Animals.md) 1節）。**プレイヤーは「石と火が要る」ことを、指示ではなく手元の物から
知ります**（2.2節）。そして砂浜は海岸帯なので岩礁海岸・断崖海岸と隣り合いやすく、そこに石があります。

**開始地点が説明を兼ねます。** 何を採ればよいかを教える文章は要らず、持っている物が次にすることを
決めます。逆に、この道順が成立しない地点は候補から外します。

#### 2.3.1 候補が残らない島は、引き直さない

**どの地点も選抜の条件を満たさない島では、その中で最も条件の良い地点から始めます。島は引き直しません**
（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の「引きが厳しい周回は、そのまま始めさせる」節）。

その周回は腕にかかわらず苦しく、死ぬこともあります。周回のロストは新しい島を始めることなので
（[`GameEndings.md`](../concept/GameEndings.md) 8節）、外れの引きはそこで清算されます。

#### 2.3.2 難易度は、揃うまでの歩数で作る

**難易度は消費や獣の強さではなく、最初の段をどれだけ楽に越えられるかで作ります**
（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の
「難易度は、数値ではなく配置の散らばりで作る」節）。

判定は、**知識あり／なし × 最善手／無駄のある手**の4通りで生存可能性を出し、その値で候補を分けます。

| 段 | 目安 |
| --- | --- |
| **初心者** | 知識なし・無駄の多い手でも越えられる。要るものが2歩以内に揃い、開始地点自身に水と食料がある |
| **経験者** | 知識ありなら余裕、知識なしだと際どい。3歩まで散らばる |
| **ハードコア** | 最善手でようやく越えられる。4歩以上に散り、途中に実りの薄い土地が挟まる |

**この算出は道具にやらせます**（`stats:balance` と同じく、定義と生成された島だけから計算できます）。
段ごとのしきい値を決めるのはその数字が出てからです。

#### 2.3.3 運の幅は、生成の側で締める

**引き直さないぶん、島ごとの立ち上がりやすさの散らばりは生成の側で抑えます。散らばりが大きすぎれば、
選抜をしても引きで決まるだけになります**（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の
「運の幅は、例外の救済ではなく分布への制約で抑える」節）。

**制約の中身は実測を見てから決めます。** どの配り方が幅を広げているかは、多数の種で回した分布を
見ないと分かりません。今わかっている範囲での候補は2つです。

- **カバレッジを型ではなく「採れるもの」で置く。** 今の `guarantees` は「標高が最大のサイトへ山頂を
  置く」という形で型を名指ししています。生存のためのカバレッジは、代わりに上の表の6つそれぞれについて
  「島のどこかで採れる」を条件にします。**どの型がそれを担うかは島ごとに変わり**——火口を草原が持つ島も、
  荒野が持つ島もありえます——型を名指ししないぶん、島の個性は削れません。**山を必ず1つ置く既存の保証は
  そのままです**（あれは島の顔を決めるもので、2.3節の切り分けの向こう側にあります）。
- **開始地点になりうるサイトの行き止まりを減らす。** 今は道の平均次数が2.5で行き止まりが15%
  （`terrain_generation.yaml` の `extra_edge_detour_factor`）。行き止まりの砂浜から始まると、
  次の一手が1つしかありません。

どちらも「必ずこの型をここへ置く」ではなく、**満たすべき性質を配り方の条件に足す**形なので、
2.3節の選抜と同じ考え方に乗ります。

### 2.4 それ以降の段は、物ではなく量で立つ

**1つの物で1日を超えるものはほとんどありません。段になるのは「まとまった量」です。**

石の斧は482分<!-- stats: balance.yaml object_costs object=stone_axe total_minutes -->（0.33日）、甕は465分<!-- stats: balance.yaml object_costs object=jar total_minutes -->（0.32日）、ロープは680分<!-- stats: balance.yaml object_costs object=rope total_minutes -->（0.47日）。段として立つのは「家1軒ぶんの
丸太20本」「水を貯める甕10個」「航海の30日ぶん」のような量のほうです。4節はこの単位で並べます。

**行き先が絡む段は、そこにしかない材料と対で書きます**
（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の「行き先は、行きたくなる理由と同時に作る」節）。

## 3. 系統は12本

支出を数えると12本になります。

| # | 系統 | 埋める支出 |
| --- | --- | --- |
| 1 | **水** | 渇き。得て、運んで、溜める |
| 2 | **食の調達** | 飢え。採る・獲る・育てる |
| 3 | **保存** | 腐敗。得た食を保たせる |
| 4 | **刃物・打撃** | 切る・割る手間 |
| 5 | **火** | 熱が要ること |
| 6 | **狩りの道具** | 獣を仕留める手間 |
| 7 | **運ぶ入れ物** | 運ぶ手間 |
| 8 | **衣類** | 寒さ・濡れ |
| 9 | **寝床** | 眠気 |
| 10 | **住居** | 雨風・虫・湿気 |
| 11 | **遠出** | 移動の距離。補給の要る行程 |
| 12 | **船と海図** | 海を渡ること |

手当て（怪我・病気）は系統に数えていません。支出ではありますが、繰り返し払うのは**失敗したときだけ**で、
安くしていく段の連なりを持ちません（[`InjurySystem.md`](../engine/InjurySystem.md) の治療は、段ではなく
症状ごとの対処です）。

## 4. 各系統の段

**最初の段（2.1節）に入るものと、そのあとに来る「1日以上の山」を分けて並べます。山は合計30個、
日数にして約90日ぶんです。**

日数は自由時間（1日816分）に対する概算で、実測のあるものは印を付けました。**この90日は、明るさと
移動時間を無視した下限です**——どちらも入れると同じ山が約128日ぶんに広がり、島を開く17日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->を足すと
1周回は約145日になります（8節）。

| # | 系統 | 最初の段の中で手に入るもの | 1日以上の山（括弧内は日数） | 山 | 日 |
| --- | --- | --- | --- | --: | --: |
| 1 | 水 | ヤシの実・湧き水・運ぶ器 | 雨受けと貯水を据える（2）／甕を10個焼く（3.2）／航海ぶんの水を積む（4） | 3 | 9.2 |
| 2 | 食の調達 | 拾う・掘る・くくり罠 | 畑を拓いて回す（4）／**家畜の囲い（3.2<!-- stats: balance.yaml object_costs object=pen days -->・実測）**／大型の狩り（2） | 3 | 9.2 |
| 3 | 保存 | 焼く | 干し場（1）／燻し小屋（2）／製塩（3）／30日ぶんを保存加工（6） | 4 | 12 |
| 4 | 刃物・打撃 | 剥片・叩き石・石の斧 | 磨製一式（1.5）／鉱石を掘って製錬（5） | 2 | 6.5 |
| 5 | 火 | きりもみ・焚き火・覆い焼きの炉 | 恒久窯（3） | 1 | 3 |
| 6 | 狩りの道具 | くくり罠・木の槍 | 石鏃の槍（1）／青銅の穂先（2） | 2 | 3 |
| 7 | 運ぶ入れ物 | 肩掛けの袋・編み籠 | なめし革の背負い袋（1）／そり（2） | 2 | 3 |
| 8 | 衣類 | 束ねた葉・編んだ葉 | なめし革の一式（3） | 1 | 3 |
| 9 | 寝床 | 敷物 | 高床の寝台（1.5）／詰め物（1） | 2 | 2.5 |
| 10 | 住居 | 洞窟・雨よけ | 葉の小屋（3）／高床（4）／板の壁・床（5） | 3 | 12 |
| 11 | 遠出 | 日帰りの探索 | 泊まりの行程を通す（2）／山と洞窟の前線（4） | 2 | 6 |
| 12 | 船と海図 | — | **筏（5.3<!-- stats: balance.yaml object_costs object=raft days -->・実測）**／**帆（5.5<!-- stats: balance.yaml object_costs object=rawhide_sail days -->・実測）**／櫂と舵（2）／沿岸航海（3）／海図を仕上げる（5） | 5 | 20.8 |
| | | | **合計** | **30** | **90.2** |

**山が「量」で立っていることに注意してください**（2.4節）。石の斧も甕も1つでは0.33日で段になりません
——段になるのは家1軒ぶんの丸太であり、貯水に足りる数の甕です。**畑も1枚は0.32日<!-- stats: balance.yaml object_costs object=field days -->**で、段になるのは
拓いた枚数と、撒いて収穫しに戻る往復の回数のほうです。**塩田も1枚は0.35日<!-- stats: balance.yaml object_costs object=salt_pan days -->**で、段になるのは据えた枚数と、
海水を汲みに戻る往復の回数です。**囲いは1つで段に届きます**——丸太4本と縄2本が要るためです。

**表の中身は既存のカタログのままです。** 9は [`Bedding.md`](./Bedding.md) 2節、10は
[`Dwellings.md`](./Dwellings.md) 3節、7は [`Containers.md`](./Containers.md) 2節、4・5・6は
[`SurvivalItems.md`](./SurvivalItems.md) 1〜3節、12は [`Voyage.md`](./Voyage.md) 1〜3節に既にあります。
**新しく足したのは1・2・3・11の4本**で、このうち2の飼育は [`Animals.md`](./Animals.md) 3.1節、3の製塩と
塩蔵は [`SurvivalItems.md`](./SurvivalItems.md) 9節が持ちます。残りはまだどの文書も担当していません。

**新しい4本のうち3本は、仕掛けて待つ形です。** 水を溜める・畑と家畜・保存の設備（干す・燻す・天日で
塩を採る）はいずれも、留守の間に設備が働きます。罠が既にこの形なので
（[`TrapSystem.md`](../engine/TrapSystem.md)）、新しい仕組みは要りません。**畑と家畜、そして塩田はこの形で
入っています**——`farming.yaml` の `field`・`pen` と `salt.yaml` の `salt_pan` は罠と同じ宣言だけで
書けていて、新しい文法は1つも足していません（飼育の中身は [`Animals.md`](./Animals.md) 3.1節、製塩と
塩蔵は [`SurvivalItems.md`](./SurvivalItems.md) 9節）。**まだ宣言が無いのは、水を溜める設備と、干し場・
燻し小屋の2つです。**

## 5. 終盤に要るもの

**出航までにプレイヤーが到達している必要があるのは、5つです。**

1. **積める船。** 筏に帆と櫂が付いたもの（[`Voyage.md`](./Voyage.md) 2.1節）。丸太・ロープ・帆材が要り、
   丸太は斧だけが作ります（同1節）。
2. **水を30日ぶん運ぶ手段。** 甕（水の段4）か革の袋（段3）。ヤシの実は1日5個の勘定になり、30日で150個は
   積めません。**水の系統の段4に届いていないと出航できません。**
3. **腐らない食料。** 保存の段2〜4。生のままでは、積み終える前に前半が傷みます。
4. **浜まで運ぶ手段。** そり（運ぶ入れ物の段4）。備蓄は拠点にあり、出航地点は海岸なので、積み込みの前に
   陸の運搬が要ります。
5. **残りの海区数が読める海図**（[`GameEndings.md`](../concept/GameEndings.md) 12.6節）。山頂からの視認と
   沿岸航海で作ります。

出航に適した季節の窓（同3.1節）が、この5つに期限を与えます。

### 5.1 望遠鏡は置かない【確定】

**望遠鏡は骨格に入れません。海図の段階（[`GameEndings.md`](../concept/GameEndings.md) 9.1節）で
「方角と、幅のある海区数が海図に入る」役割は、山頂への到達が担います。**

レンズには研磨したガラスが要り、青銅を上限とする技術水準（[`SurvivalItems.md`](./SurvivalItems.md)
7節）から2000年ほど飛びます。ここだけ技術の段を跳ばすのは、終盤に新しい能力を要求しないという方針
（[`GameEndings.md`](../concept/GameEndings.md) 3節が言う「それまでの遊びの強度を上げる」）とも合いません。

山頂は補給を積んだ数日の行程が要る場所（遠出の段3）なので、中盤の目標としての重さは望遠鏡と同じです。
得られるものも同じ——方角と、幅のある海区数が海図に入ります。**島には必ず山がひとつあります**
（`terrain_generation.yaml` の `guarantees`）。

## 6. アーティファクト【確定】

**全周回に共通する集合は24種類、1周回の島に配置されるのは6つとします。棚が埋まるまでにおよそ6周。**

- **周回中は何の役にも立ちません。重いだけです。** 使い道があると、持ち帰るより使うほうが得になる場面が
  出て、航海で積荷を捨てる決断（[`GameEndings.md`](../concept/GameEndings.md) 4節）が鈍ります。重さは
  水と食料と同じ枠を食うので、6つ見つけても全部は積めません。
- **出どころは、材料の無い行き先です。** 浅い洞窟・山頂・沈船の海区・遠征先の小島。材料を置けない場所に
  「行きたくなる理由」を与えるのがアーティファクトの役目です
  （[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の「行き先は、行きたくなる理由と同時に作る」節）。

| 出どころ | 種類数 | 1周回に配置 |
| --- | --: | --: |
| 浅い洞窟 | 8 | 2 |
| 山と岩場 | 4 | 1 |
| 沈船と漂着物 | 6 | 1 |
| 遠征先の小島 | 6 | 2 |

24種類は、1周で6つ持ち帰れたとして最短4周、重複を織り込んで6〜8周で埋まる勘定です。

## 7. 海区の顔ぶれと、遠征先の小島

足しません（[`GameEndings.md`](../concept/GameEndings.md) 12.1節、
[`ExplorationSystem.md`](../engine/ExplorationSystem.md) 2節の「発見量のつまみ」）。

| 海区 | 拾えるもの | 湧くもの | 実り | 役割 |

### 7.1 遠征先の小島には錫を置く

**青銅の材料のうち、銅は母島の山で採れ、錫は遠征先の小島にしかありません。**

これで沿岸航海（[`GameEndings.md`](../concept/GameEndings.md) 11節）が「渡らないと道具の最終段に届かない」
場所になります。移動手段だけを先に入れて
後から理由を足すことにならず、[`SurvivalItems.md`](./SurvivalItems.md) 0節が既に銅鉱石と錫鉱石を別々に
挙げているので、材料も増えません。

小島は上陸して探索できる土地なので、アーティファクトの配置先にもなります（6節）。

## 8. 埋まる時間

**同じ30個の山が、明るさ・移動・土地の差を入れると約128日ぶんになり、島を開く17日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->を足して1周回は
約145日です。1日816分という自由時間は上限であって、実際に使える時間ではありません。**

1日を賄う最小労働は624分<!-- stats: balance.yaml daily_minimum place=島全体 total_minutes -->（[`stats/balance.yaml`](../../stats/balance.yaml) の `daily_minimum`）なので、差し引きの自由
時間は1日816分。4節の山の合計は約73,000分なので、**そのまま割れば90日ぶん**です。しかしこの816分は、
1日のどの時間でも何でもできる場合の数字で、**明るさと移動がこれを削ります**（8.1・8.2）。

**山の数を増やしても日数は伸びません。** 日数は山の合計そのものなので、増やす道は「山を増やす」か
「1つの山の量を増やす」かのどちらかで、合計から見れば同じことです。**増やすと決めた場合に選ぶのは、
どちらが同じ作業の反復になりにくいかだけです**（[`DesignPrinciples.md`](../concept/DesignPrinciples.md)
の「失敗の罰に、同じ作業のやり直しを課さない」節が問題にしているのと同じ反復）。

**最初の段は、この勘定には乗りません。** 足止めしているのが労働の量ではないので（2節）、分で測っても
その区間の重さは出ません。乗るのは日数だけで、数日です。

**探索は分では軽く、日数では重いものです。** 島の土地は10〜20（`terrain_generation.yaml` の
`site_count`）、探索率100%までは土地ごとに10〜20回で1回15分
（[`ExplorationSystem.md`](../engine/ExplorationSystem.md) 2節）なので、**全島を100%にしても2,795分<!-- stats: terrain.yaml exploration_phase metric=exploration_minutes mean -->**
——山の合計の4%です。ところが**日数では17日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->**（1周回の12%）になります。1日に探索できる時間が土地の
明るさで切られ、しかも1つの土地を開き切るまでそこに居る必要があるためで、この差が出るのが8.3節の
「探索の局面」です。なお**最初の段の中では探索がほぼ全部**で、そこでの探索は時間を埋めているのでは
なく不確実性を減らしています。同じ行動が区間によって別の働きをするので、まとめて数えられません。

### 8.1 明るさが、1日に使える時間を切る

**明るさは現実の単位（照度）で持ちます。行動ごとに要る明るさが違い、足りなければその行動はできません。**

抽象的な0〜20では、その値が正しいかを誰も確かめられません（[`DesignPrinciples.md`](../concept/DesignPrinciples.md)
の「現実に単位があるものは、その単位で持つ」節）。ルクスなら、嵐の正午が約190 lx——手元の作業まで
できる明るさで、真夜中とは比べものにならない——だと外の知識で確かめられます。

**嵐で出歩けないのは風雨のせいであって、暗いせいではありません**（同「1つの原因に、複数の結果を
兼ねさせない」節）。暗さとして表すと、松明を持てば嵐の中を歩けることになります。風雨が行動を止めるなら、
それは明るさとは別の値で表します。

**線を引くのであって、遅くするのではありません**（同「悪条件は、効率を下げるのではなく、できる／
できないの線で効かせる」節）。これで「暗くなる前に切り上げて帰る」「松明を持って出る」「明るいうちに
しかできない仕事を先に回す」という、1日の組み立てが要るようになります。

#### 8.1.1 持つのはEV（照度の2を底とする対数）

**照度そのものではなく、EV（露出値、`EV = log2(照度 / 2.5 lx)`）で持ちます。** この世界の明るさは
0.00005 lx から125,000 lx まで9桁に渡るので、そのままでは加減算で扱えません。

EVは写真の「段（stop）」で、ISO 2720 が定める標準の量です（入射光式・ISO100・較正定数250）。1段が
2倍にあたり、**掛け算がそのまま足し算になります**——樹冠が通す割合も、天気の透過率も、地面の反射率も、
EVでは引き算・足し算の項になります。名前のある単位なので、値が正しいかを外の知識で照合できます
（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の「現実に単位があるものは、その単位で持つ」節）。

**採らなかった候補**は2つです。**dB**（10·log10）は汎用ですが「照度のdB」という確立した用法がなく、
1段が1.26倍で細かすぎます。**視等級**は天文で使う本物の照度の対数ですが、**明るいほど値が小さくなる**
ので加算の向きが常識と逆になります。

| | 照度 | EV |
| --- | --: | --: |
| 雲のまったく無い空の正午 | 125,000 lx | +16 |
| 曇りの正午 | 5,000 lx | +11 |
| 嵐の正午 | 187 lx | +6 |
| **手元の細かい作業のしきい値** | 80 lx | **+5** |
| **屋外の採取のしきい値** | 20 lx | **+3** |
| **土地の間を移動するしきい値** | 0.1 lx | **−5** |
| **暗さの底（これより下は区別しない）** | 0.04 lx | **−6** |
| 半月の夜の空（開けた土地） | 0.025 lx | −6.6 |
| 月の無い夜の星明かり | 0.002 lx | −10 |
| 半月の夜の密林 | 0.00005 lx | −16 |

**移動のしきい値が −5（0.1 lx）なのは、暗順応した人間が満月の砂浜を普通に歩けるからです。** 満月が
中天にあるとき開けた土地は0.25 lx で、これを歩けないことにすると現実と合いません。**この島に満月は
出ません**（8.1.1.1節）が、しきい値のほうは現実の目盛りに合わせてあります。

**屋外の採取は、手元の作業より2段低いところに線があります。** 80 lx は倉庫や廊下の明るさで、縫製の
推奨（750〜1,500 lx）には遠く及びません——それでも手元の作業を通すのは、屋内の粗い作業の下限がその
あたりだからです。屋外で草を採るのに要るのはそこまでではなく、現実の熱帯雨林の林床は快晴の正午で
600〜2,500 lx あります。**開けた土地では日の出と日没が急峻なので、この2段の差は数分しか動きません**
（8.1.3節）。**効くのは樹冠の深い森と密林だけ**で、そこでは採れる時間が手元の作業の倍以上になります。

**見る値も違い**、手元の作業は据え付けの光源を含む明るさを、屋外の採取と移動は含まない明るさを見ます
（[`IlluminationSystem.md`](../engine/IlluminationSystem.md) 2節・5節）。

**表の夜の3行は、空の側では底（−6）に均されます。** 底があるのは、光源が持ち上げる段数を場所によらず
一定にするためで、−6 自体に現実の根拠はありません（同 4節）。**土地の樹冠と反射は、その底の上へ
足されます**——夜の地表がどうなるかは 8.1.2節です。

#### 8.1.1.1 夜の空は、月あかりを項として持たない【確定】

**夜のあいだ、空が地表へ与える明るさは底（−6）そのものです。** 月の高度でも天気でも動かないので、
夜には項が1つもありません。

**この節が決めるのは空の側だけです。** 土地の樹冠と反射はこの底の上へ足されるので（8.1.2節）、
**夜に歩ける土地があるかどうかは、この節では決まりません。**

**月齢は入れず、半月と仮定します。** 満月ではなく半月を採るのは、**その状態でいる時間が長いほう**を
選ぶためです（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の「周期する状態を固定値で近似
するなら、頻度の高いほうを採る」節）——月が開けた土地を歩ける明るさにするのはひと月の2割弱で、残りの
8割はそこへ届きません。

**半月の照度は満月の約1/10**（中天で 0.025 lx＝−6.6）です。面積が半分だからではなく、欠け際の影が
長く伸び、満月のときだけ効く衝効果が無いためです。**これは暗さの底（0.039 lx＝−6）を下回るので、
月の高度で刻んでも天気の透過率を掛けても、空の側は底のままです**——区別できるものが何も残らないので、
項を持たせません。

【いつか: 月齢】 月齢で周期させる案は、画面に月齢を出す形が決まるまで待ちます
（[`Someday.md`](../Someday.md)）。

#### 8.1.1.2 光源の明るさは、現実の照度ではなく「底から何段か」で決める

**光源の値だけは現実から離します。**

| 光源 | 現実の照度 | 現実のEV | **採る値** |
| --- | --: | --: | --: |
| 獣脂のランプ | 10 lx | +2 | **+1** |
| 松明 | 30 lx | +4 | **+11** |
| キャンプファイヤー | 150 lx | +6 | **+11** |

底（−6）と移動・手元の作業のしきい値（−5・+5）を決めると、光源の値は引き算で一意に出ます——**1つで
歩けるようになる明るさが +1、1つで作業できる明るさが +11** です。**獣脂のランプは1つで歩けますが、作業できる明るさに
するには11個要ります。** これは障壁として十分で、しかも現実の照度でも一致します（10 lx × 11個 =
110 lx で、100 lx のしきい値を超える）。

離すのは光源だけで、**しきい値も自然光も現実のまま**なので、「その値が正しいかを外の知識で照合
できる」（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の「現実に単位があるものは、その
単位で持つ」節）性質は保たれます。光源は「暗闇を何段持ち上げる道具か」という、ゲーム側のつまみとして
読みます。

**松明とキャンプファイヤーは同じ値です。** 差を付けても「底では作業できないが少し明るければできる」
という読みにくい段になるだけなので、光源は「歩けるようになるもの（+1）」と「作業できるようになるもの
（+11）」の2階層で足ります。**両方を同時に使うと雲のまったく無い空の正午を超えますが、しきい値との比較にしか
使わないので害はありません。**

段（`stages`）は、しきい値の境目にだけ置いてあります——`pitch_dark`（−5未満）・`dim`・`bright`で、
`bright` の境は手元が +5、視界が +3。**この3つがしきい値の置き場そのもの**で、条件の側は段の名前で見ます
（[`IlluminationSystem.md`](../engine/IlluminationSystem.md) 8節）。上の表の値を動かすときに
一緒に見るのは、キャラクタの `hand_brightness`・`looking_brightness` の段だけです。

**「携行光源か固定光源か」という区別は、明るさの側には要りません。** 焚き火が視界を明るくしないのは、
それが動かせない設置物だからで、光源自身は何も知りません（[`IlluminationSystem.md`](../engine/IlluminationSystem.md) 3節）。

#### 8.1.2 土地は「樹冠」と「地面の反射」の2つを持つ

**土地が明るさへ与える影響は2つあり、どちらもその土地の環境光へ入ります。**

- **樹冠の透過率** — 空から降る照度のうち、地表まで届く割合。熱帯雨林は1〜2%しか通しません。
- **地面の反射率** — 地面が返す割合。太陽光の下では照り返しが手元も照らすので、**手元の作業にも
  効かせます**。

| 土地 | 樹冠 | EV | 反射率 | EV | **合計（`value`）** |
| --- | --: | --: | --: | --: | --: |
| 砂浜 | 1.00 | 0 | **0.40** | **+1** | **+1** |
| 草原 | 1.00 | 0 | 0.22 | 0 | 0 |
| 岩礁海岸・断崖海岸・岩石地・荒野・山腹・山頂 | 1.00 | 0 | 0.20 | 0 | 0 |
| 森 | 0.05 | **−4** | 0.08 | −1 | **−5** |
| 密林 | 0.01 | **−7** | 0.06 | −2 | **−9** |

**定義に書くのは合計の1つだけ**で、内訳を持つのはこの表です
（[`IlluminationSystem.md`](../engine/IlluminationSystem.md) 2節）。

**浅い洞窟はこの表に載りません。** 土地ではなく土地の中の設置物で、持っている −6 は樹冠と反射の合計では
なく**外との差**だからです——親の土地の環境光を土台に6段下げます
（[`Dwellings.md`](./Dwellings.md) 5.1節）。空から光が来ないことを土台を持たないことで表す形
（[`IlluminationSystem.md`](../engine/IlluminationSystem.md) 7節、値は底そのもの）は**奥の洞窟の値**で、
その奥はまだありません（【いつか: 洞窟内部】、[`Someday.md`](../Someday.md)）。

反射率は基準の地面（0.20）に対する比として掛けます。

**夜の地表は、この2つだけで決まります。** 空は底（−6）に張り付いていて時刻でも天気でも動かないので
（8.1.1.1節）、夜の明暗を作るのは土地だけです。

| 夜の地表 | 環境光 | 移動（しきい値 −5） |
| --- | --: | --- |
| 砂浜 | **−5** | **歩ける** |
| 草原・岩場・荒野など | −6 | 歩けない |
| 森・密林（底へ引き戻される） | −6 | 歩けない |
| 浅い洞窟の中（親の土地からさらに −6。同じく底へ） | −6 | 歩けない |

**夜に歩けるのは砂浜だけです。** 反射 +1 を持つ砂浜だけが底の上へ1段乗り、しきい値にちょうど届きます。
**海沿いは夜でも帰れる道になり**、他の土地から日暮れ後に動くには光源が要ります。

**現実の半月の砂浜は 0.05 lx で、しきい値（0.1 lx）に半段届きません。** 底が空の暗さを持ち上げるぶん、
この島の砂浜は現実より明るいことになります。**それでも砂浜を開けておくのは狙いです**——夜がどの土地も
一様に閉じると、地面の色は線を跨がせる場面を1つも持たなくなります。

**砂浜は草原の2倍近く明るい。** 乾いた砂の反射率は0.4ほどあり、開けているだけの土地より効きます。
効く量では樹冠のほうが圧倒的（100倍）ですが、**反射率が線を跨がせるのは夜のほう**です——昼は日の出と
日没が急峻なので（8.1.3節）、同じ1段では境目が数分動くだけです。

**夜は、樹冠の差が消えます。** 森も密林も浅い洞窟も底へ引き戻されるので、夜の暗さでは区別が付きません。

**浅い洞窟の中で作業できるのは、外が曇りの正午（+11）以上に明るいときだけです。** 中は外より6段暗く、
手元のしきい値は +5 だからです。晴れ以上なら7時から16時まで、曇りの日は11時から12時まで、雨の日は
一日中できません。**アーティファクトの出どころの3分の1が浅い洞窟（6節）**で、そこは同時に序盤の住居
（[`Dwellings.md`](./Dwellings.md) 5節）でもあるので、朝夕と雨の日に中で手を動かすぶんが燃料の需要に
なります。奥の洞窟が開けば（【いつか: 洞窟内部】）、そちらは昼でも光源が要ります。

**移動できるかは、出発する土地の明るさで決めます**（[`IlluminationSystem.md`](../engine/IlluminationSystem.md) 5節）。
道は自分の明るさを持たないので、行き先の暗さは見ません。

#### 8.1.2.1 値は「環境光・手元・視界」の3つに分ける

**行動が見るのは手元と視界の2つで、環境光はそれを導くためだけに在ります。**

| 値 | 何を寄せるか |
| --- | --- |
| **環境光** | 時刻・天気・土地の樹冠と地面の反射。**底（−6）で均す** |
| **手元の明るさ** | 環境光と、持っている光源＋その場に据えられた光源 |
| **視界の明るさ** | 環境光と、**持っている光源だけ** |

しきい値の対応は——**手元の細かい作業は「手元の明るさ」**、**移動と屋外の採取は「視界の明るさ」**を
見ます。

分ける理由は2つあり、**どちらか一方をやめても、もう一方が同じ分け方を要求します。**

- **底は光源より前に効く必要があります。** 底が無いと、密林の夜（−15）と浅い洞窟の夜（−12）とで同じ
  松明の効き方が変わり、「1つで歩ける／11個で作業できる」という段が作れません。
- **据え付けの光源は視界に入ってはいけません。** 焚き火が視界を明るくすると、真っ暗な夜でも拠点から
  出発できてしまい、着いた先で身動きが取れなくなります。

どのオブジェクトがどれを持つかは [`IlluminationSystem.md`](../engine/IlluminationSystem.md) 2節、
底の置き方は同 4節です。**樹冠が光源を遮ってしまう問題は、底が飲み込みます**——密林の夜は樹冠込みで
−15 ですが底で −6 になり、そこへ松明の +11 が乗ります。

**合成はすべて単純加算です。** 対数なので光源を足し合わせるのは厳密には正しくありません（10 lx の
ランプ2つは1段しか増えないところ、加算では2段になります）。**それでもしきい値との比較にしか使わない
ので、誤差が線を跨がなければ結果は変わりません。** 乗算や「大きいほうを採る」をエンジンへ足すよりも、
**定義ファイルが加算だけで書けること**を優先します（同 1節）。

#### 8.1.3 天気は、樹冠を通してだけ効く

赤道付近の島（[`Animals.md`](./Animals.md) 概要）なので、日の出6時・日没18時が年間ほぼ動きません。
太陽高度から出した、雲のまったく無い空の照度に、天気の透過率を掛けます。**天気は`core.yaml`の`weather`の7段すべて
です**——「寄与」は同じ段が`ambient_brightness`へ与える段数で、雲のまったく無い空を0として何段暗いかです。
天気の行名は画面へ出る日本語名（`locale/ja.yaml`の`symbol_texts`）です。

| 天気 | `core.yaml`の段 | 寄与 | 12時（90°） | 9時・15時（45°） | 7時・17時（15°） | 6時・18時（0°） |
| --- | --- | --: | --: | --: | --: | --: |
| 灼熱 | `scorching` | 0 | 125,000 | 68,400 | 8,570 | 1.0 |
| 快晴 | `sunny` | −1 | 68,700 | 37,600 | 4,710 | 0.6 |
| 晴れ | `clear` | −2 | 41,000 | 22,400 | 2,810 | 0.3 |
| 曇り | `cloudy` | −5 | 5,000 | 2,730 | 343 | 0.04 |
| 小雨 | `light_rain` | −6 | 2,000 | 1,090 | 137 | 0.02 |
| 大雨 | `heavy_rain` | −8 | 749 | 410 | 51 | 0.006 |
| 嵐 | `storm` | −10 | 187 | 103 | 13 | 0.002 |

照度の単位はlxです。**灼熱（`scorching`）は暑さの名前ですが、明るさの側では雲のまったく無い空**——寄与を
持たない基準の段です。**晴れ（`clear`）がこの島でいちばん多い天気**で、快晴と曇りの間に落ちます。

**照度と実装を突き合わせるのは正午の列です。** `hour`が正午に与える寄与が+16なので、実装の正午のEVは
「16＋寄与」になります。照度をEVへ直した値（`EV = log2(照度 / 2.5 lx)`、8.1.1節）とは最大0.4段ずれます
——実装は段を整数で持つための丸めで、**正しいのは実装のほう**です。**正午以外の列は直接は一致しません**
——実装の`hour`の段はその1時間の中央の太陽高度を使うのに対し、この表の列は正時の高度だからです。

**夜の列はありません。** 半月の月あかりは中天でも 0.025 lx（−6.6）で、天気の透過率を掛けるまでもなく
底（−6）を下回るためです（8.1.1.1節）。**天気が効くのは昼だけ**で、夜の砂浜が開くかどうかは天気に
よりません。

透過率は正午の実測に合わせました（雲のまったく無い空10〜13万 lx・曇り5,000 lx・嵐200 lx）。**晴れ
（`clear`）だけは実測ではなく、実装の−2段（EV 14 ＝ 41,000 lx）から置いています。**

**土地×季節ごとに1日何時間動けるかは、手で計算せず定義から数えます。**
[`activityHoursOf`](../../src/analysis/activityHours.ts)が、`core.yaml`の`hour`・`weather`の段
（この節の透過率と太陽高度がambient_brightnessへ与える寄与そのもの）・土地ごとのambient_brightness
（8.1.2節）・天気の出現時間（[`stats/climate.yaml`](../../stats/climate.yaml)の`weather_hours`、
20シード×3,600日の実測）から、しきい値（8.1.1節の −5・+3・+5）を満たす時間を積算します。据え付けの
光源は含みません（含めると「焚き火があれば24時間活動できる」になり、表の意味が消えます）。
**表そのものは同じYAMLの`activity_hours`に1本だけ持ち、ここでは繰り返しません。**

**列は行動のクラスと1対1です**——`travel`（移動できる）・`gathering`（屋外で採れる）・`handwork`
（手元の細かい作業ができる）。後ろの2つが違う値になるのはしきい値の差だけによります。見る値は違います
（採る側はlooking_brightness、作る側はhand_brightness）が、据え付けの光源を含めない限りどちらも土地の
ambient_brightnessをそのまま土台にするためです
（[`IlluminationSystem.md`](../engine/IlluminationSystem.md) 2節）。

**夜に動けるのは砂浜だけです。** 他の土地は夜になると移動のしきい値を割るので、日暮れ後に動くには
光源が要ります（8.1.2節）。**密林は昼も天気の影響を受けます**——樹冠が−9と深いぶん、雨季の荒天では
正午でも移動のしきい値を割ることがあり、「移動できる」列が12時間ちょうどにならない唯一の土地です。

**土地の差がいちばん大きく出るのは、採れる時間の雨季です。** 樹冠が深い森・密林ほど雨季に大きく
削られます（森・密林とも雨季は繊維・バナナ・粘土・小枝の産地——2.3節の表——なので、**雨季は繊維が
細る季節**になります）。保存の系統（3番）と備蓄が要る理由が、ここで数字になります。

**夜は空白になりません。** 睡眠が360分、残りの360分は焚き火のそばで手元の作業ができるので、夜は
「集める」から「加工する」へ切り替わります
（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の「時間経過に任せる区間を作らない」節）。

### 8.2 1日は、局面ごとに数える

**「1日」は1つではありません。** 島を開いている最中と、開き切った後とでは、同じ島でも1日の使い方が
別物になります。**片道の平均は86.43分<!-- stats: terrain.yaml base_one_way base=shortest_mean mean -->**（500シード<!-- stats: terrain.yaml meta seeds -->の実測、
[`stats/terrain.yaml`](../../stats/terrain.yaml) の `base_one_way`）ですが、この数字だけでは
どちらの1日も出ません。

[`dailyPhasesOf`](../../src/analysis/dailyPhases.ts)が、生成された島から局面ごとに数えます。道1本の
移動時間には縮尺・歩く速さ・両端の `move_cost`・高低差が生成の時点で畳まれている
（[`TerrainGeneration.md`](../engine/TerrainGeneration.md) 3.5節）ので、積むのは最短経路だけです。
**表そのものはそちらに1本だけ持ち、ここでは繰り返しません。**

**数え方は局面をまたいで1つです。**

```
その日その土地で進む仕事（分） = min(720 − 往復の移動 − 264, その土地で採れる時間)
```

**遠さは移動の項として、暗さは頭打ちとして、同じ1行に入ります。** 局面の違いは**どこへ行くか**と
**そこで何をするか**の2つだけで、式は共有します。720分<!-- stats: terrain.yaml daily_budget outdoor_window -->は屋外の枠、264分<!-- stats: terrain.yaml daily_budget survival_gathering -->は1日を賄う生存の採取
（[`stats/balance.yaml`](../../stats/balance.yaml) の `daily_minimum` の624分<!-- stats: balance.yaml daily_minimum place=島全体 total_minutes -->から睡眠360分を引いた分）です。

**生存の採取は、暗い土地でも払える形にしています。** 密林で1日に働けるのは265分<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 work_minutes_per_day -->ですが、その日の
残りの明るい時間は拠点の周りにあります。頭打ちに掛ける前に引くことで、「密林へ行った日は食べられない」
にならずに済みます。

**移動は、8.1の採れる時間からは引きません。** 移動のしきい値は −5、屋外の採取は +3（8.1.1節）で、
その差の時間帯は**歩けるが採れない**時間です。1日の屋外の枠を決めるのは移動のしきい値のほう
——太陽が出ている12時間（720分）です。

**頭打ちに使うのは採れる時間で、手元の作業ができる時間ではありません。** この式が割っているのは
屋外の枠であって、手元の作業が当たっているのは夜の360分のほうだからです（8.3節）。

**引いた線は3つです。** 1日は1つの土地で使い（往復1回、余りは翌日へ繰り越さない）、荷物は数えず
（運べる量に上限が無いので、採ったものを置いて帰る自由はこの勘定に現れません。
[`ExplorationSystem.md`](../engine/ExplorationSystem.md) 1.1節）、探索の抽選は解きません
（探索は回数と時間だけで測ります）。

### 8.3 1周回は、局面を積んで約145日

**同じ30個の山が、局面ごとに数え直すと約145日ぶんになります。** 内訳は**島を開く17日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->**と、
**開き切った後の128日**です。

局面は2つに割りました。**割る位置を決めているのは「探索がまだ残っているか」の1点だけ**で、
どちらの1日も8.2節の同じ式で出ます。値はすべて500シード<!-- stats: terrain.yaml meta seeds -->の実測
（[`stats/terrain.yaml`](../../stats/terrain.yaml) の `exploration_phase`・`steady_phase`、拠点は片道が
平均で最も短い土地）。

| 局面 | 1日の移動 | 1日に進む分 | 消化するもの | 日数 |
| --- | --: | --: | --: | --: |
| **探索**（島を開き切るまで） | 173分<!-- stats: terrain.yaml exploration_phase metric=day_trip_travel_per_day mean --> | 探索 168分<!-- stats: terrain.yaml exploration_phase metric=day_trip_exploration_per_day mean --> | 全土地を探索率100%まで（2,795分<!-- stats: terrain.yaml exploration_phase metric=exploration_minutes mean -->） | **17日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->** |
| **定常**（開き切った後） | 63分<!-- stats: terrain.yaml steady_phase metric=travel_per_day mean --> | 山 384分<!-- stats: terrain.yaml steady_phase metric=work_per_day mean --> | 屋外の山（48,700分） | **128日** |
| 合計 | | | | **約145日** |

30個の山（73,000分）のうち、屋外での採取・伐採・運搬を2/3（48,700分）、拠点での加工を1/3（24,300分）と
置いています。**この割合と、下の土地の配分は仮置きです。**

**探索の局面で移動が重いのは、行き先が選べないからです。** 未踏の土地は拠点から近い順に開いていく
ので、前線が遠ざかるほど往復が滞在時間を食います（1日173分<!-- stats: terrain.yaml exploration_phase metric=day_trip_travel_per_day mean -->は、定常の63分<!-- stats: terrain.yaml steady_phase metric=travel_per_day mean -->の2倍以上）。それでも
**1日に進む探索が168分<!-- stats: terrain.yaml exploration_phase metric=day_trip_exploration_per_day mean -->しかない**のは、遠さではなく**土地を1つ開き切るまでその土地に居る必要がある**
ためです——道は `[2, max−1]` に均等配置されるので、最後の道はほぼ探索し切る直前に出ます
（[`ExplorationSystem.md`](../engine/ExplorationSystem.md) 3.2節）。

**定常の局面では、行き先を選べます。** 山の配分を開けた土地1/2・森1/4・密林1/4と置き、その組の
中では最も実入りの多い土地を選びます。**ただし配分が決めるのは仕事の量であって、日数ではありません**
——実入りの少ない土地ほど、同じ仕事量に多くの日を使います。

| 配分 | 往復の移動 | 1日に進む山 | **日数の割合** | その組を持つ島 |
| --- | --: | --: | --: | --: |
| 開けた土地（仕事の1/2） | 11.28分<!-- stats: terrain.yaml steady_phase_by_work_share share=開けた土地 round_trip_minutes --> | 445分<!-- stats: terrain.yaml steady_phase_by_work_share share=開けた土地 work_minutes_per_day --> | 50.7%<!-- stats: terrain.yaml steady_phase_by_work_share share=開けた土地 day_percent --> | 100%<!-- stats: terrain.yaml steady_phase_by_work_share share=開けた土地 islands_percent --> |
| 森（仕事の1/4） | 88.86分<!-- stats: terrain.yaml steady_phase_by_work_share share=森 round_trip_minutes --> | 367分<!-- stats: terrain.yaml steady_phase_by_work_share share=森 work_minutes_per_day --> | 31.5%<!-- stats: terrain.yaml steady_phase_by_work_share share=森 day_percent --> | 99.8%<!-- stats: terrain.yaml steady_phase_by_work_share share=森 islands_percent --> |
| 密林（仕事の1/4） | 135.86分<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 round_trip_minutes --> | **265分<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 work_minutes_per_day -->** | **34.3%<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 day_percent -->** | 52.2%<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 islands_percent --> |

**いちばん高く付くのは密林です。** 開けた土地の1日445分<!-- stats: terrain.yaml steady_phase_by_work_share share=開けた土地 work_minutes_per_day -->に対して265分<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 work_minutes_per_day -->なので、**仕事の4分の1が、密林の
ある島では日数の34%<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 day_percent -->を持っていきます**（3つの合計が100%を超えるのは、密林の行だけが密林のある島
52.2%<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 islands_percent -->の中の割合で、残りの島ではその配分が他の組へ回るためです）。しかも足止めしているのは距離ではなく
暗さなので、道を短くしても縮みません。配分を動かすには「どの材料がどの土地で採れるか」（2.3節）から
決め直すことになるので、本節では触っていません。

**夜**は、睡眠360分と、焚き火のそばでの加工360分。**律速は屋外です**——拠点での加工24,300分は夜の
360分/日に対して68日ぶんなので、145日の中に余裕で収まります。**夜が足りなくなることはなく、
足りないのは昼です。**

**泊まりがけは、今の島の広さでは要りません。** 土地ごとに日帰りと泊まりの安いほうを採っても
15.14日<!-- stats: terrain.yaml exploration_phase metric=mixed_days mean -->で、**日帰りだけの16.67日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->との差は1.5日**です。500島<!-- stats: terrain.yaml exploration_day_trip_islands islands -->のうち100.0%<!-- stats: terrain.yaml exploration_day_trip_islands share -->が、日帰りだけで全土地を開き切ります。
縮尺（#797）が入って往復が屋外の枠720分から生存の採取264分を引いた残りを使い切らなくなったためで、
**遠出（11番）の「泊まりの行程」は、この島の広さでは成立しません。**

**この145日は上限としても下限としても読めません。** 上へ振れる材料は、4節の山のうちそり（2日）・
泊まりの行程（2日）・山と洞窟の前線（4日）の3つが**移動が重いことを前提に置いた段**で、どれもまだ
宣言が無く勘定に入っていないこと。下へ振れる材料は、**探索の局面の17日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->に山を1分も乗せていない**こと
——1日の枠283分に対して探索は168分<!-- stats: terrain.yaml exploration_phase metric=day_trip_exploration_per_day mean -->しか進まないので、余る115分×17日<!-- stats: terrain.yaml exploration_phase metric=day_trip_days mean -->は山へ回せます。

**「1周回は約480日」という前の結論は取り下げます。** 480日は、密林のような暗い土地でも生存の採取
264分<!-- stats: terrain.yaml daily_budget survival_gathering -->を丸ごと引いていた（そこでは1日265分<!-- stats: terrain.yaml steady_phase_by_work_share share=密林 work_minutes_per_day -->しか働けないのに）ことと、移動を「一様に選んだ行き先へ
1箇所」（251分）と置いていたことの2つで膨らんでいました。**山を減らす理由は無く、
[`GameEndings.md`](../concept/GameEndings.md) 8節の想定（約200日）に対して55日足りません。**

- 行動ごとのしきい値（8.1.1節の −5・+3・+5 EV）、暗さの底（−6 EV）、光源の明るさ（+1・+11 EV）、土地の

- 松明の燃費と、1本で歩ける時間（8.1.1節）。夜に出るコストと、朝夕や雨の日に浅い洞窟の中で手を
  動かすコストがここで決まります。
- 風雨が行動を止めるかどうか（8.1節）。明るさとは別の値で表すと決めただけで、止めるかは未定です。
- 開始地点の選抜（2.3節）を、どこが実装するか。今の `IslandSpawner.placePlayer` は砂浜を優先して
  index順に採るだけで、何が何歩先にあるかを見ていません。判定に要る「歩数」は生成後のパスネットワーク
  から出るので、生成の後段に置くことになります。
- 生存可能性の算出（2.3.2節）を、何を変数にして解くか。知識あり／なしは「最短の経路を選べるか」で
  表せますが、無駄のある手の割合をどう与えるかは決めていません。
- 段ごとのしきい値（2.3.2節の2歩・3歩・4歩）。上の算出が出るまでは仮置きです。
- 散らばりをどこまで許すか（2.3.3節）。「大きすぎる」の線は実測の分布を見てから引きます。
- 固定シナリオ（山がある島・湖がある島のように、その島が何であるかを保証で決めたもの）を用意するか。
  用意するなら、そのぶん生成の自由度が下がるので、2.3.3節の散らばりも一緒に動きます。
