# 設計ドキュメントの書き方

`docs/` 配下のドキュメントが従う定型です。文章そのもののスタイル（簡潔さ・経緯を書かない等）は
[`CLAUDE.md`](../CLAUDE.md) が持ち、本書は**構造**——見出し・節番号・概要・実装状況の表し方——だけを
決めます。リンクと参照の解決は自動テスト（`tests/docs/docReferences.test.ts`）が検査します。

## 1. 文書の種別

定型は種別ごとに違います。どの文書がどの種別かは各フォルダの `README.md` の分類に従います。

| 種別 | 例 | 構成 |
|---|---|---|
| 設計 | `HuntingSystem.md`、`docs/ui/` の各文書 | 概要（2 節）＋論点ごとの節＋未決事項 |
| リファレンス | `GameElementDefinition.md`、`Localization.md` | 位置づけ＋項目の網羅＋対象外。概要は要らない |
| カタログ | `Animals.md`、`Containers.md` | 分類の軸＋一覧＋住み分け＋未決事項 |
| 実装ガイド | `TerrainGenerationImplementation.md` | 呼び出し関係＋索引。設計理由は書かず設計文書へリンク |
| 教訓集 | `DesignNotes.md`、`DesignPrinciples.md` | 結論を見出しにした項目の列挙 |
| 測定 | `docs/diagnostics/` | [`diagnostics/README.md`](./diagnostics/README.md) に従う |

## 2. 設計文書の概要は 5 つの問いに答える

この順で、最初の画面に収まる分量で書きます。模範は
[`LiquidContainerSystem.md`](./engine/LiquidContainerSystem.md)（実現方法が明快）と
[`ExplorationSystem.md`](./engine/ExplorationSystem.md)（境界の書き方が明快）です。

1. **守備範囲** — この文書は何を決めるか。
2. **境界** — 何を決めないか。隣の文書はどれか（リンク）。
3. **実現方法** — この文書が扱う概念を、エンジンのどの機能へどう写したか。どの trait・タグ・
   スロット名・プロパティ名を使うか（＝この文書が導入する語彙）。新設した文法は何か。
   **新設ゼロならそれを明記します**——汎用機能に載せた場合こそ、写し方の記述が唯一の設計判断です。
4. **在処** — 定義（`src/assets/world-codex/*.yaml`）・実装（`src/`）・検証（`tests/`）はどこか。
5. **確定度と実装状況** — 検討結果か確定仕様か。未決事項は何節か。未実装の節はどれか（4 節）。

節の一覧をなぞる「目次の要約」は書きません。目次で分かることに一等地を使ううえ、全節を挙げるため
網羅的に見え、書かれていないこと（実現方法の欠落など）に気付けなくなります。

## 3. 見出しと節番号

- **節番号が識別子です。** 他の文書やコードからの参照は節番号で行うため、**既存の節番号は
  付け替えません**。節の追加は末尾か枝番（`4.1` の後に `4.2`）で行います。
- 見出しには**その節が決める論点**を書き、**結論は本文の先頭 1 文に太字で**置きます。結論を
  見出しに書くと、結論の推敲のたびに参照が壊れます（名前で参照している場合）。ただし結論を
  見出しにした方が目次が読みやすい場合は禁じません——その見出しを名前で参照しないだけです。
- `概要` と `未決事項・今後の検討課題` は番号付き節の外に置いてもかまいません（既存文書の慣例）。

## 4. 実装状況は宣言し、丸ごと未実装の節にラベルを付ける

ドキュメント先行で書かれた設計は、実装済みの節と未実装の節が同じ断定調で並び、読み手の判断を
誤らせます。

- **文書全体の実装状況は概要で 1 回言います**（模範: [`ClimateSystem.md`](./engine/ClimateSystem.md)）。
  多数派を既定として宣言し、例外の節だけに印を付けます。
- **節の主題が丸ごと存在しないときだけ**、見出しの末尾に `【未実装: 識別子】` を付けます。
  識別子はその節が導入する語彙から 1 つ選びます（例: `【未実装: 海図】`）。子節はラベルを
  継承するので繰り返しません。
- 識別子を書くのは検証のためです。自動テストが `src/` を照合し、実装されたのに剥がし忘れた
  ラベルを検出します。識別子の無い `【未実装】` は検証できないので使いません。
- **節の一部だけが未実装の場合はラベルにせず、本文で書きます。**「一部未実装」というラベルは
  結局本文を読まないと判断できず、警告として機能しません。
- 語彙は「未実装」の一語に統一します（「未対応」「実装していません」等を混在させない）。
  ラベルは TODO 管理ではありません——目的は読み手の判断を誤らせないことだけで、進捗表として
  細かく付けるほど更新漏れが増えます。

### 4.1 いつか実装したいものは、別の印と一覧で分ける

`【未実装: 識別子】` を付けるのは**無いと完成と言えないもの**だけです。**無くても完成を宣言できるが、
いつか実装したいもの**は `【いつか: 識別子】` で分けます。1つの印で両方を扱うと、**残りの作業量を
誰も答えられなくなります。**

| 印 | 意味 | 実体はどこ |
|---|---|---|
| `【未実装: 識別子】` | 無いと完成と言えない。残作業 | `task` ラベルの issue |
| `【いつか: 識別子】` | 無くても完成を宣言できる | [`Someday.md`](./Someday.md) に必ず1項目 |

- **印と項目は1対1です。** 項目の無い印も、印の無い項目も、自動テストが落とします。
- **節の主題が丸ごと「いつか」なら見出しの末尾へ、節の一部ならその節の本文に1行**書きます
  （`【未実装】` と同じ切り分け）。本文に書く形は「印 ＋ 何を待っているかの1文 ＋ `Someday.md` への
  リンク」で、**中身は書きません**——詳しい説明は `Someday.md` にだけ置きます。
- **「未決事項・今後の検討課題」節は、決まっていないこと専用です。** やると決まっていて、やっていない
  だけのものは、2つの印のどちらかへ振り分けます。
- 確定度（6 節）とは別の軸です。両方付くときは `【確定】` を先に書きます。

## 5. 参照の書き方

- 他の文書の節は **`文書名.md N節`** で指します。コメント・YAML では要旨を添えます
  （例: `GameElementDefinition.md 6.4節のalert`）。番号だけでは読み手に何の話か伝わらず、
  名前だけでは見出しの推敲で切れるためです。
- 番号だけの参照（「4 節」）は**同じ文書の節**を指します。コード・YAML では
  `GameElementDefinition.md`（WorldCodex 文法）の節を指す既定とします。「同 N節」は、同じファイル内で
  **直前に名前を挙げた文書**の節を指します。文書名の言及から離れた場所で、他の文書の節を番号だけで
  指してはいけません——読み手にも自動テストにも解決できません。
- 節番号を持たない見出し（`Localization.md` の項目など）は
  **`文書名.md 〇〇節`** と名前で指せます。自動テストが実在を検査します。
- 文書内・文書間の Markdown リンク（`[表示名](#アンカー)` / `[表示名](./Foo.md#アンカー)`）も
  自動テストが解決を検査します。

## 6. 確定していることにだけ印を付ける

決定は後から覆ります。**印の無い記述を暫定**——今はこう書いてあるが覆りうる——という既定にし、
覆すのに判断が要るものにだけ印を付けます。

- **確定した節は、見出しの末尾に `【確定】` を付けます。** 意味は「**覆すには人間の判断が要る**」。
  読み手は従い、疑問があれば書き換えずに問いとして出します。
- **印が無い節は暫定です。** 従ってよいが、矛盾や不都合を見つけたら**覆す提案を出してよい**。
  決まっていない箇所に仮決めを書いたときも、印を付けずにここへ入れます。
- **印は確定の側にだけ付けます。** 大半は暫定なので、暫定に印を付けると全ページに印が並び、
  背景になって読めなくなります。**印は少数側に付けたときだけ印として働きます。** 暫定の側に印を
  付ける語（`【未確定】`・`【暫定】`）は使いません。自動テストが検出します。
- **`【確定】` は内容が正しいという主張ではなく、変更権限の宣言です。** 確定節の記述が実装や他の節と
  食い違っていても、直さずに問いとして挙げます。「動いている方が正しい」で上書きすると、
  印の意味が消えます。
- **確定度と実装状況（4 節）は別の軸です。** 確定した未実装の節も、暫定の実装済みの節もあります。
  両方付くときは `【確定】` を先に書きます（`### 節番号 見出し【確定】【未実装: 識別子】`）。
- 概要の「確定度と実装状況」（2 節）は文書全体の要約として残しますが、**節の印が優先します。**

文書ごとの節数・確定節数・未実装節数は `npm run stats:docs` が一覧にします。
