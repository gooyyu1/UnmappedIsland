# 日をまたぐ長さのレポートの読み方

数値は [`stats/durations.yaml`](../../stats/durations.yaml) にあります。
`tests/diagnostics/durationStatsReport.test.ts` が、定義（`src/assets/world-codex/*.yaml`）だけから
計算したものです。日数を決める値——怪我の `severity`・食べ物の `durability`・`season_remaining`・
道具の `durability` とそれらを動かす `passives`——を変更したら再生成します。

```
npm run stats:durations
```

**この文書は手書きで、再生成しても書き換わりません。** 持つのは読み方——何を測ったか、どこに線を
引いたか、何を数えていないか——だけです。**数値そのものは1行も書きません**（書けば、再生成した
YAMLとずれます）。

## YAMLの節

`unit` は、そのレコードの測定値の単位です。件数（`durations`・`tool_wears`）は単位を持ちません。

| 節 | 中身 |
| --- | --- |
| `meta` | 日の列に載せる下限、数えた長さの数、最長と最短、使うたびに減る値の数 |
| `durations` | **日をまたぐ長さの、長い順の1本の列**。種類では分けない |
| `tool_wear` | 時間では減らず、使うたびに減る値が尽きるまでの**回数** |

**この表とYAMLが食い違うと `npm test` が赤くなります。** 表に挙げた節がYAMLに在って空でないことと、
表に無い節がYAMLに無いことの両方を、生成元のテストが見ます。

## なぜ1本の列なのか

この表が答えたいのは**逆転**です——骨折より擦り傷のほうが治りが遅い、塩漬けの肉が生肉より早く
傷む、といった並びの狂い。逆転は種類をまたいで起こるので、怪我の表・食べ物の表・季節の表と
分けると見えません。**同じ列に並んでいることが検査そのもの**なので、`durations` は種類で分けず、
`days` の降順だけで並べます。

`days` と `shortest_days` の2つがあるのは、条件つきの増減（`GameElementDefinition.md` 8.2節）が
同時に成立するとは限らないためです。`days` は条件つきが最小限しか効かない場合、`shortest_days` は
全部が重なった場合で、実際の長さはこの幅の中にあります。**逆転を読むときは両方を見ます**——
生肉と塩漬けの肉は `days` では順当でも、`shortest_days` では近づきます。

## 計測方法

数え方の線は `src/analysis/durations.ts` の冒頭が持ちます。長さはすべて「tick毎に動く値が `range` の
端へ届くまで」（`src/analysis/rangeCycles.ts`）で、それを日へ直したものです。

- **1日に満たない長さは数えません。** 乾き・飢え・疲れ・調理・火の燃えは1日の中で何度も回るもので、
  日で読む長さとは尺度が違います（[`DesignPrinciples.md`](../concept/DesignPrinciples.md)
  「長くかかるものだけ、現実の4分の1へ縮める」）。同じ列に混ぜると、日をまたぐ長さの逆転が
  1日未満の行に埋もれます。ただし**同じ値が日をまたいで尽きるところは数えます**——渇きで倒れるまで・
  蓄えた脂肪が尽きるまでは日で読む長さで、怪我の治りと並べる意味があります。
- **隣の物に押されて初めて進むものは数えません。** 炉が焼く・刺さった傷が血を奪うといった増減は、
  置いておくだけでは起こりません。これを寿命として数えると、火にかけていない肉まで勝手に
  焼け落ちることになります。
- **繰り返すものも一度きりのものも同じ列に置きます**（`repeats`）。季節は端で値が戻って次の季節へ
  移り、怪我は端で消えますが、**どちらも「その長さのあいだ続く」ことに変わりはありません**。
- **段で切り替わる増減は数えません。** 段ごとに速さが変わるものは、1つの長さでは言い表せません
  （`src/analysis/rangeCycles.ts`）。
- **実際に起きるかは数えません。** 生肉が10日もつのは誰も食べなかった場合の長さで、その前に
  食べられる確率は見ません。

## 使うたびに減る値を、日の列に置かない理由

道具の `durability` は時間では減りません。斧は振ったときだけ、槍は突いたときだけ削れるので、
「何日で壊れるか」は**振り続けた場合**にしか出ません。それは経過時間ではなく労働時間で、
「肉が10日で腐る」と同じ軸に置くと**在りもしない逆転が見えます**（斧のほうが肉より早く壊れる、
のように）。

そこで `tool_wear` は**回数**で出し、1回に払う時間（`labor_minutes`）を添えます。日の列と突き合わせ
たいときは、この2つを掛けたものが「他に何もせず使い続けた場合」の下限になります。

同じ道具でも使い方ごとに行が分かれます（`step`・`owner`）——斧は木を伐るのと獲物を殴るのとで
1回の削れ方が違い、**壊れるまでの回数もそこで変わる**ためです。

時間でも減る耐久（罠が地面で朽ちる分）はここには出ません。使い方に依らない長さなので、`durations`
の側が持ちます。

## このレポートは判定を出さない

逆転が見つかっても、ここでは直しません。どちらを動かすかは、並びを読んでから決めます。
値そのものの妥当性（骨折は10日でよいか）は、この表ではなく
[`InjurySystem.md`](../engine/InjurySystem.md) をはじめとする仕様書が持つ判断です。
