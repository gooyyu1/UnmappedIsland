# 生命と意識のシステム設計

## 概要

**何が意識を奪い、何が命を奪うか**——気絶する・死ぬをどう表すかと、新しい死因が現れたときにそれを
どこへ流すか（8 節）を決めるドキュメントです。怪我という
オブジェクトそのものの構造は [`InjurySystem.md`](./InjurySystem.md)、動物と対峙する局面は
[`HuntingSystem.md`](./HuntingSystem.md)、飢え・渇きの値の刻み方は
[`Characters.md`](../world/Characters.md)、ステータスの見せ方は [`StatusArea.md`](../ui/StatusArea.md) が
扱います。本書が決めるのは、それらが合流する先である**3つのプロパティと、その底に着いたときに何が
起きるか**だけです。

**新設する文法はありません。** 導入する語彙は次の4つのプロパティと2つの段の名前だけで、
残りは既存の仕組み——`stages` の中の `passives`（段ごとの寄与）・`modify`（可逆な寄与）・
`accumulate`（不可逆な削り）・`on_shortfall`（下限を割った瞬間の効果）——にそのまま載ります。

| 語彙 | 何を表すか |
| --- | --- |
| `consciousness`（意識） | 起きていて動けるか。押し下げられる**実効値**（2 節） |
| `shock`（衝撃） | 殴られた揺れ。即座に上がり、自分で引いていく（2.1 節） |
| `blood`（血液量、mL） | 体に残っている血。失われる**実体値**（3 節） |
| `bleeding`（出血） | **傷が持つ**、今流れている勢い。固まれば止まる（4 節） |
| 段 `unconscious` | ここに落ちたら手番が回らない。名前を固定する（6 節） |
| 段 `exsanguinated` | 失血で助からない域。本書が `fatal` を置く唯一の段 |

定義の置き場所は `public/world-codex/animals.yaml`（動物）と `characters/player_character.yaml`
（キャラクタ共通の props）、削る側は `public/world-codex/injuries.yaml` の各傷、読む側は
カードの状態バー（`PlayScreenView`）と、気絶した間の手番を飛ばす側です。

本ドキュメントは検討結果であり、確定仕様書ではありません。**2 節から 6 節まではサルで実装済みです**
（検証は `tests/worldCodex/animalsYaml.test.ts`）——殴れば一撃で気を失い、裂けた傷から血が流れ、
放っておけば固まって止まり、失いすぎれば目を覚まさず、尽きれば死体になります。**キャラクタ側はまだ
配っていません**（7 節。血を戻す仕組みが動くのはそちらだけです）。8 節の新しい死因と 4.1 節は未実装で、
未決事項は末尾に整理しています。

## 1. 意識と血は分ける

**気絶するかを決める値と、死ぬかを決める値は、別のプロパティにします。**

決め手は**痛みです。痛みは意識を奪いますが、血は減らしません。** 1本の値に統一すると、激痛で意識を落とす
経路がそのまま命を削ることになり、「傷は浅いが激痛で倒れた」が書けなくなります。分けておけば、原因ごとに
宛先を選べます——痛みと衝撃は意識へ、出血は血へ、殴打はその両方へ。

分かれ目はエンジンの機構そのものでもあります。2つは**別の仕組みに載ります**。

| | `consciousness`（意識） | `blood`（血液量） |
| --- | --- | --- |
| 値の性質 | **実効値**（自分では動かない。`pain`・`load` の仲間） | **実体値**（削られて残る。`severity` の仲間） |
| 動かすもの | 痛み・失血・衝撃の**段**が `modify` で押し下げる | 出血する傷が `accumulate` で削る |
| 元に戻るか | **原因が消えれば自動で戻る**（気絶からの回復に後始末が要らない） | 傷を塞いだ上で、水と食事が揃って初めて、桁違いに遅く戻る |
| 底に着いたら | 段 `unconscious` を**読む側**が手番を飛ばす（6 節） | `on_shortfall` が **死**を起こす（3 節） |

**統一が成り立たないのはここです。** `on_overflow`/`on_shortfall` は実体値の書き込みでしか発火しません
（`PropertyValue.add` が `checkRangeEvents` を呼ぶ経路だけ）。意識のように `modify` だけで決まる値は、
いくら0になっても range イベントを起こせないため、統一値にすると死を起こす主体が世界の側に居なくなり、
毎 tick 見張る側が要ります。逆に実体値1本へ統一すると、今度は気絶からの復帰を誰かが書き戻すことになり、
[`HuntingSystem.md`](./HuntingSystem.md) 6 節が「値は効果の入力であって通知路ではない」として避けた形に
戻ります。

## 2. 意識は押し下げられる実効値

**`consciousness` は自分では動きません。** 初期値は満たした状態（100）で、痛み・失血・衝撃が
`modify` で押し下げます。原因が消えれば寄与も消えるので、**気絶から覚めるのに回復処理は要りません**。

```yaml
consciousness:
  tags: [status, health]
  value: 100
  range: {min: 0, max: 100}
  stages:
    - {name: unconscious, alert: danger}
    - {name: dazed, min: 25, alert: caution}
    - {name: foggy, min: 60, alert: watch}
    - {name: clear, min: 80}
```

- 段の刻みは [`Characters.md`](../world/Characters.md) の規約に従い、**安全域を外れるのは `max` の80%**。
- **致命的域（`fatal`）は持ちません。** 気絶それ自体は死に至らず、死に至らせるのは血を失わせている側です。
  致命的域を持つのは `blood` の `exsanguinated` だけにします（3 節）。
- **`pain` と同じく個体差を持たせません**（`player_character` trait が配る）。押し下げる量は傷の側が
  宣言するので、同じ傷が誰に刺さっても同じ意味を持つ必要があります。

**押し下げるのは、押し下げる側の段です。** 寄与は `stages` の中の `passives` に書きます
（[`GameElementDefinition.md`](./GameElementDefinition.md) 6.4節）。時刻（`hour`）の段が日射
（`sunlight`）へ寄与しているのと同じ形で、**しきい値と寄与量が同じ1箇所に並びます**。

```yaml
pain:
  stages:
    - {name: painless}
    - {name: sore, min: 25, alert: watch}
    - name: hurting
      min: 50
      alert: caution
      passives:
        - modify: {self: {consciousness: -20}}
    - name: unbearable
      min: 83
      alert: danger
      passives:
        - modify: {self: {consciousness: -45}}
```

段は排他なので（同じ値が2つの段に該当することはない）、階段がそのまま並びます。**効き方は連続では
なく階段でよい**——段はまさにその単純化のための仕組みで、刻みの細かさは段の数で決めます。

寄与元は3つあり、いずれもこの1つの形で書きます。

| 寄与元 | 何を表すか | 意識が戻るきっかけ |
| --- | --- | --- |
| `pain` の段 | 痛みで朦朧とする | 傷が治る・手当てで痛みが引く |
| `blood` の段 | 血を失って意識が遠のく | 傷を塞ぎ、水と食事で戻す |
| `shock` の段 | 殴られた衝撃（2.1 節） | **自分で引く** |

**痛みだけでは気絶させません。** 痛みが最も深い段でも意識は朦朧（`dazed`）に留め、そこへ失血か
衝撃が重なって初めて落ちる、という配分にします。痛みで気絶できてしまうと、手当てを怠っただけで
行動不能になり、2 節の「意識は原因が消えれば戻る」が「痛みが引くまで何もできない」に変わります。

**意識が他の値を押し返す向きには書けません。**「意識が薄いほど痛みを感じない」は、`pain` の
`modify` のゲートが `consciousness` を読み、その `consciousness` が `pain` から決まる循環になり、実行時に
例外が飛びます（同 14.1節）。

### 2.1 衝撃は、自分で引いていく量

**殴られて意識が飛ぶのは、傷ではなく打たれたことの結果です。** 傷（`severity`）の段にぶら下げると
時間の尺度が合いません——深い傷は10日かけて治り、気絶から覚めるのは数十分だからです。同じ量の段で
2桁違う時間は表せないので、衝撃を1つの量として持ちます。

```yaml
shock:
  value: 0
  range: {min: 0, max: 100}          # maxが体格。イノシシは大きく、同じ一撃では倒れない
  passives:
    - accumulate: {self: {shock: -4}}      # 1時間で16引く
  stages:
    - {name: steady}
    - name: rattled
      min: 30
      passives:
        - modify: {self: {consciousness: -30}}
    - name: reeling
      min: 70
      passives:
        - modify: {self: {consciousness: -80}}
```

与えるのは攻撃の側で、`add` は実体値への即時の書き込みなので**殴った瞬間に効きます**。

```yaml
- weight: 70
  add: {self: {shock: 80, wariness: 25}, dragged: {durability: -20}}
  spawn: {object: deep_gash, into: self}
  signal: hit
```

- **一撃で気絶し、階段状に覚めます。** 80で `reeling`（-80）、`-4/tick` で引いて70を割れば `rattled`
  （-30）、30を割れば戻り切ります。当たり所が頭でなくても同じように効きます
- **`shock` は `accumulate` だけを受け、`consciousness` は `modify` だけを受けます。** 1つの量に
  両方を掛けると、どちらが今の値を決めているのか読めなくなります
- **画面には出しません**（`status` タグを付けない）。意識への入力であり、低ければ意識のバーがそう
  言っています（9 節）
- 脳震盪を怪我のカードとして別に立てません。**当たり所によらず衝撃は生じる**ので、傷の種類の数だけ
  意識を奪う傷を用意することになります（[`InjurySystem.md`](./InjurySystem.md) 4 節）

## 3. 血は失われ、尽きれば死ぬ

**`blood`（血液量、mL）は失われたら戻りにくい実体値**で、下限を割った瞬間に死にます。形は怪我の
`severity` と同じ——`range.min` を 1 に置き、`on_shortfall` で自分を消します
（[`InjurySystem.md`](./InjurySystem.md) 1 節）。

```yaml
blood:
  tags: [status, health]
  value: 5000                       # 体重のおよそ1/13。maxがそのまま体格
  range: {min: 1, max: 5000}
  stages:
    - name: exsanguinated                             # 6割を失えば助からない
      alert: fatal
      passives:
        - modify: {self: {consciousness: -100}}
    - name: hemorrhaging
      min: 2000
      alert: danger
      passives:
        - modify: {self: {consciousness: -70}}
    - name: bled
      min: 3000
      alert: caution
      passives:
        - modify: {self: {consciousness: -30}}
    - {name: low, min: 3500, alert: watch}
    - {name: replete, min: 4250}
  on_shortfall:
    destroy: self
  passives:
    # 血は水と食事から作られる。どちらかが欠けていれば戻らない。
    - conditions:
        - {prop: hydration, gte: 96}
        - {prop: satiety, gte: 96}
      accumulate: {self: {blood: 2}}
```

- **`max` は体格です。** ヒトは体重のおよそ1/13（70kgで5,000mL）で、動物の体重比もほぼ同じ。専用の
  戦闘数値ではなく、`weight`・`volume` と並ぶ**物理量**として読めます。
- **段のしきい値は「失った割合」から引きます。** 15%までは何も起きず、15〜30%で表に出はじめ、
  **30〜40%で意識が落ちはじめ**、40%を超えると危機——臨床の出血性ショックの分類（ATLS）そのままです。
  しきい値を決めるのに「ゲームらしさ」を持ち込む必要がありません。
- **意識を奪う量は、深い段ほど大きくします。** 段の寄与は今居る段のものだけが立つので、最も深い段に
  寄与を書き忘れると、**瀕死の相手が中等症より意識がはっきりする**という裏返りが起きます。
- **戻すのは水と食事です。** どちらかが欠けていれば戻りません。**失血は独立した量ですが、独立した
  対処では埋まらない**——渇きと飢えを断ち切ってから初めて血が戻る、という結び付きがここで生まれます。
  **動物はこのブロックを持ちません。** `hydration` も `satiety` も宣言していないので条件を書けず、
  手負いのまま逃げた個体は弱ったまま残ります（追跡に意味が出る側面もあります。未決事項）。
- 動物に配るときは `on_shortfall` へ `spawn` を並べ、**同じ枠での置き換え**として死体を出します
  （`destroy` が `spawn` より先に走る、[`GameElementDefinition.md`](./GameElementDefinition.md) 9.4節）。
  ただし**狩りの決着で死体になる道は、血が尽きるより先に仕留めの一撃**が持ちます
  （[`HuntingSystem.md`](./HuntingSystem.md) 1.4 節）。失血死は、逃げられた個体が後で倒れる道です。

## 4. 出血は、血を失う速さ

**出血する傷とは「宿主の `blood` を毎 tick 削る傷」のこと**で、勢いの違いはレートの違いとして表れます。
そして**血は固まります**——傷の側が `bleeding`（今流れている勢い）を持ち、それが尽きた時点で止まります。

```yaml
laceration:
  props:
    # 傷の重さとは別の時間で動く。4 tick（1時間）で固まる。
    bleeding:
      value: 100
      range: {min: 0, max: 100}
      passives:
        - accumulate: {self: {bleeding: -25}}
  passives:
    - modify: {parent: {pain: 50}}
    # 流れている間だけ、宿主の血が失われていく。これが出血そのもの。
    - conditions:
        - {prop: bleeding, gte: 1}
        - not: {slot: treatment, tag: hemostatic}
      accumulate: {parent: {blood: -15}}
```

- **止まる仕組みを傷の側に持たせないと、掠り傷でも必ず死にます。** `severity` の段をゲートにすると、
  **傷が治りきるまで何日も流れ続けます**。血が固まるのは数分、傷が塞がるのは数日で、**2つは別の時間**
  で動きます。
- **勢いは桁で書き分けます。** 1 tick は15分なので、`-15` は毎時60mL——尖った石で裂けた傷の桁です
  （潰れた血管は縮んで塞がるので、切れる刃で切った傷ほどは出ません）。刺し傷は `-200`、大血管を切れば
  `-1000` の桁で数 tick しか保たず、にじむ程度の擦り傷は `-2` で実質何も起きません。**同じ1つの量に
  対するレートの違い**だけで、致命傷から掠り傷までが並びます。
- **レートは傷が持ち、相手の大きさを知りません。** だから**同じ傷が、体格で意味を変えます**——固まる
  までの合計60mLは、ヒトの5,000mLには響きませんが、サルの400mLでは1割半です。狩る相手が小さいほど
  効く、が調整値なしで出ます。
- **治療具は2通りの効き方をします。** 止血帯（`hemostatic`、未実装）は**ゲートを閉じて止め**、包帯は
  **`bleeding` を余計に引いて固まるのを早めます**（失う量は半分になりますが、ゼロにはなりません）。
  どちらも「効き目」を持たず、結果は傷の側の宣言から出ます（[`InjurySystem.md`](./InjurySystem.md) 3.1節）。
- **体内に溜まった血も同じ量で表せます。** 肝臓や脾臓の破裂は外へ血を出しませんが、**循環から失われた
  点では外出血と同じ**です。分けて数える必要はありません。
- 失血が意識を奪う経路は、`blood` の段が持ちます（3 節）。血の量と意識をそれぞれ数える必要はありません。

### 4.1 閉じた腔の圧は、血では表せない【未実装】

**頭蓋内と胸腔だけは、失われた量ではなく溜まった圧が効きます。** 頭蓋は閉じた箱で、代償できる余地は
100〜150mLしかありません。**30mLを超える頭蓋内血腫は手術の対象**になり、30〜150mLで予後が悪化します
——全身5,000mLの1%未満です。同じ50mLを外へ流しても何も起きないので、**`blood` の目盛りでは表せません**。

表すなら、**時間とともに `severity` が増える傷**が素直です（今の怪我は治る方向にしか動きません）。

- 段が進むにつれ意識を奪い、最上段で宿主を `destroy` する
- **一度気絶から覚めてから沈む**（衝撃の回復と血腫の進行の綱引き）が、値の動きだけで出る
- 緊張性気胸も同じ形で書ける
- [`InjurySystem.md`](./InjurySystem.md) の未決事項「悪化」への答えにもなる

**この節は実装しません。** 出血（4 節）と仕留め（[`HuntingSystem.md`](./HuntingSystem.md) 1.4 節）で
狩りは成立しており、ここを先に入れると「治らない傷」の扱いを同時に決めることになるためです。

## 5. 決着は死ではなく気絶で付く

**狩りの決着は、相手が倒れた時点で付きます。** 気絶すれば手番が回らず、反撃も逃走もありません（6 節）。
意識は `modify` で押し下げられる実効値なので、**衝撃を与えた瞬間に効きます**（2.1 節）——石斧の一撃で
猿が崩れ落ちる、が遅れずに起きます。

**だから血の減少は遅れてかまいません。** 出血で `blood` が尽きるのは何 tick も先（4 節）ですが、
その間に相手が反撃してくることはないので、待つか、止めを刺すか、生け捕りにするか（7 節）を選ぶ時間が
残ります。**実体値を即座に動かす専用の入口は要りません**——衝撃は実効値の側で即座に効き、遅れてよい
ものだけが実体値に載っています。

**決着が付いた後に仕留めるのは、別の一手です。** 気を失った相手へもう一度武器を重ねると、無防備さが
押し上げた重みで一撃が急所へ入ります（[`HuntingSystem.md`](./HuntingSystem.md) 1.4 節）。命を削り切る
のを待つのではなく、**待つか・仕留めるか・生かして運ぶかを選べる**のは、決着と死が別の出来事だから
です。

体格の差は、`shock` と `blood` の `max` に出ます（2.1 節・3 節）。同じ一撃でも、猿は一撃で沈み、
イノシシは数撃を要します。武器の差は当たり所と同じく `pick` の重み配分が持つので
（[`HuntingSystem.md`](./HuntingSystem.md) 1.2 節）、**どの傷を引くか**として現れます。

## 6. 倒れたことを読むのは2箇所だけ

| 起きること | 誰が起こす・読むか |
| --- | --- |
| 死 | **世界の側**（`on_shortfall`）。プレイヤーの死は「プレイヤーが世界から出た」として `observeChanges` にそのまま現れる（[`ActionSystem.md`](./ActionSystem.md) 7 節） |
| 気絶 | **画面**（操作を受け付けず時間だけ進める）と、**動物の1手を与える側**（[`HuntingSystem.md`](./HuntingSystem.md) 5.2節）が、段 `unconscious` を読んで手番を飛ばす |

**個々のアクションに `conditions` を撒きません。** 「意識が無いと何もできない」は操作ごとの条件ではなく、
手番が回るかどうかの1つの判断だからです。撒けば、アクションを足すたびに書き忘れが増えます。

読む側が知るのは**段の名前だけ**です。荷重の `too_heavy` を道の `travel` が読み、水分の `full` を飲用が
読むのと同じ分担で（[`Characters.md`](../world/Characters.md) 値の刻み方節）、しきい値を宣言しているのは
ワールドの側だけになります。だから `unconscious` は**名前を固定します**。

## 7. 4つとも、人にも獣にも配る

`pain`・`shock`・`consciousness`・`blood` は、キャラクタと動物の両方が持ちます。**同じ傷が両方に刺さる**
（[`HuntingSystem.md`](./HuntingSystem.md) 3 節）以上、傷の側が押し下げる先は両方に在る必要があり、
片方にしか無ければ傷の定義を2通り書くことになります。

これは狩りの側に副産物を1つ生みます。**気絶した獣は抵抗できません**——`resists`（同 4 節）に意識の段を
足すだけで、殴って気絶させた個体をかごや台車へ入れられます。生け捕りが、飼いならしとは別の入口として
成立します。

## 8. 新しい死因は、既存の死に方へ流す

**致死性プロパティは「死に方」の数だけ持ち、「死因」の数だけ持ちません。** 今ある死に方は3つ——
渇き（`hydration`）・飢え（`body_fat`）・失血（`blood`）——で、感染・発熱・下痢・毒はいずれも
**死に方ではなく、そこへ至る道**です。新しい原因を足すたびにプレイヤーが見張るバーが増えるのでは、
原因を見抜く判断は生まれず、ただ計器盤を眺めることになります。

3つとも**現実の量そのもの**である点は偶然ではありません。水・脂肪・血はいずれも体から出入りする物で、
「減れば死ぬ」は抽象化ではなく事実です。**残り物のような抽象量（生命力・HP）を1つ置いて、行き場のない
効果をそこへ流し込む、という逃げ道を作らない**ための線引きでもあります。

道として書けば、[`GameConcept.md`](../concept/GameConcept.md) が掲げる連鎖——「怪我を放置すると細菌感染が
進み、感染は発熱や下痢につながり、下痢は脱水を招き、最終的には死に至る」——がそのまま立ち上がります。
**水がいつもより速く減っていく → なぜか → 熱がある → なぜか → 傷が膿んでいる**、と遡れるのは、
感染が自分専用のバーを持たず既存の量を動かしているからです。

### 8.1 対症療法で買えるのは時間だけ

**同じ原因が、対症療法の効く道と効かない道の両方へ同時に効くようにします。** 感染した傷を例に取ると、
2つの経路を並べます。

| 経路 | 削るもの | 対症療法 |
| --- | --- | --- |
| 発熱・下痢 | `hydration`・`satiety` を余計に食う | **効く**。水をがぶ飲みすれば延命できる |
| 敗血症 | `blood` を直接削る | **効かない**。傷の側を断つ以外に止まらない |

```yaml
laceration:
  passives:
    # 熱で水が余計に要る。飲めば追いつくので、ここだけなら水で凌げる。
    - conditions: [{prop: infection, in_stage: festering}]
      accumulate: {parent: {hydration: -1}}
    # 膿が回ると血が血管から漏れ出す。飲んでも循環へは戻らない。
    - conditions: [{prop: infection, in_stage: septic}]
      accumulate: {parent: {hydration: -2, blood: -40}}
```

**敗血症が血を削るのは、辻褄合わせではありません。** 敗血症性ショックでは血管が漏れ、血漿が循環の外へ
抜けます。**傷口から流れ出るのと、体内で循環から失われるのは同じこと**（4 節）なので、外傷と同じ量へ
そのまま載ります。そして**飲んだ水は漏れを塞がない**——渇きは戻るのに血は戻らない、という非対称が
そのまま「対症療法では買えないもの」になります。

血が戻るには水と食事が揃った上で桁違いの時間がかかるので（3 節）、**重体になってからの対症療法は時間しか
買えず、傷を洗うなり膿を出すなりして原因を断たなければ死ぬ**、が値の動きだけで成立します。症状に対処
しても根本解決にならない、というコンセプトはここに宿ります。

なお敗血症は「傷が血を奪う」道の延長なので、**4本目の死に方ではありません**。感染そのものが直接
プレイヤーへ見えるのは、傷カードの側（`infection`、[`InjurySystem.md`](./InjurySystem.md) 4 節）です。

### 8.2 死に方を増やしてよいのは、終わり方と対策の両方が独自のとき

新しい致死性プロパティが正当なのは、**独自の終わり方と独自の対策を同時に持ち込むとき**だけです。
低体温症（体温という別の量、火と衣類という別の対策、凍死という別の終わり）や溺死がそれにあたります。
感染にはどちらも無く、既存の終わり方へ流し込めます。

「増えて100%で死ぬ」形自体はエンジンで書けます（`range.max` と `on_overflow` に `destroy: self`）。
避けるのは表現力の問題ではなく、**閾値イベントで死ぬこと**——加減算の積分で駆動するという全体の原則
（[`GameElementDefinition.md`](./GameElementDefinition.md) 2 節）から、そこだけが外れるためです。

## 9. 画面に出すのは、意識のバーと出血の印

**動物のカードに出すバーは意識1本だけです。** 意識は痛み・失血・衝撃の合流点（2 節）なので、そのまま
「あと何手か」の統合指標になります。血のバーを並べると、2本のバーが同じ問いに別々の答えを返し、
どちらを見ればよいか分からなくなります。色は段（`alert`）から引き、しきい値を持つのはワールド側だけ、
という分担を保ちます（[`CardView.md`](../ui/CardView.md) 8 節）。

**出血は量ではなく印で出します**（同 9 節の、絵文字ひとつを絵の左下へ重ねる仕組み）。行動を変えるのは
「手当てが要るか」だけで、どれだけ失ったかではありません。量が知りたくなればカードを開けば傷が並びます。

印は**血が流れている傷のカード**に出ます（`bleeding` が 1 以上の間）。**手当て済みの印より優先します**
——当ててあってもまだ流れているなら、伝えるべきは「当ててある」ではなく「止まっていない」のほうです。

**プレイヤー自身には新しい見せ方を作りません。** `status` タグを付ければステータスエリアの既存の規約に
乗り、**安全域を外れたときだけ**行が現れます（[`StatusArea.md`](../ui/StatusArea.md)）。健康な間は本数が
増えないので、致死性の値が3つあることがそのまま画面の複雑さにはなりません。

動物のカードには既に、警戒（`wariness`）が安全域を外れている間の**輪郭の赤い明滅**があります
（[`HuntingSystem.md`](./HuntingSystem.md) 3.1 節）。役割は重なりません——明滅が言うのは「気が立っている
＝放っておくな」、意識のバーが言うのは「弱っている＝あと何手か」で、**反撃してくるかを決めているのは
警戒のほう**です。

## 未決事項・今後の検討課題

- **値に比例した効き**が書けない。「`severity` が重いほど意識が下がる・速く出血する」は `modify` /
  `accumulate` の量がリテラルのため、段ごとのブロックで階段状に刻むしかない。傷の種類が増えて刻みが
  増えたら、`transfer` の `linked_add`（[`GameElementDefinition.md`](./GameElementDefinition.md) 9.5節）に
  相当する「比例する寄与」を検討する
- 傷ごとの出血レート（4 節）。今あるのは裂傷の `-15` だけで、**桁の違う傷（刺し傷・大血管）が並んで
  初めて配分が決まる**。血が固まるまでの 4 tick も、傷の種類で変えるべきか未定
- 血が戻る速さ（3 節の `+2/tick` = 1日およそ200mL）。現実の赤血球の回復はこの程度だが、**失った1,000mLに
  5日かかる**のが遊びとして重すぎないかは、狩りの頻度が決まってから見る
- **動物は血が戻らない**（3 節）。水と食事を持たないので条件を書けず、手負いの個体は弱ったまま残る。
  追跡する意味が出る一方、群れが弱った個体だらけになる恐れがある。動物に飢えと渇きを持たせるか、
  動物にだけ無条件の回復を書くかは、動物の生活を作るときに決める
- **出血の印が届くのは傷のカードまで**（9 節）。負っている本人のカードには出ないので、レーンを流し見
  しているだけでは「血が流れている」に気付けない。傷を持つ側へ印を上げるには、傷から親へ何かを寄与
  させる（数を数えるプロパティ）か、UI が子まで見るかのどちらかが要る
- `shock` の配分（2.1 節）——一撃でどれだけ与え、どれだけの速さで引くか。**気絶している間に動物が
  何をするか**（襲い続けるのか、興味を失うのか）と一緒に決まる
- 感染の値の配分（8.1 節）——熱が水をどれだけ余計に食うか、敗血症がどれだけ速く命を削るか。
  **傷を洗う操作を入れて初めて釣り合いが決まる**ので、洗浄の手間と一緒に決める
- 低体温症を4本目の死に方にするか（8.2 節）。体温の仕組みを入れるときに判断する
- 気絶している間に何 tick 進めるか。その間に動物が何をするか（襲い続けるのか、興味を失うのか）
- プレイヤーが死んだときの見せ方（画面・セーブデータの扱い）。[`SaveDataManagement.md`](./SaveDataManagement.md)
  との接続
- 死体オブジェクトの重さ・解体・腐敗（[`HuntingSystem.md`](./HuntingSystem.md) 未決事項節と共通）
