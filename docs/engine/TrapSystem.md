# 罠システム設計

## 概要

本ドキュメントは、罠を仕掛けてから獲物が掛かるまでの設計をまとめたものです。罠は**時間と運を払って、
危険を払わずに獲物を得る**道で、直接戦う狩猟との非対称（7 節）が設計の芯です。

**掛かった後は狩猟と同じです。** 罠の中の獲物は普通の動物のカードで、仕留め・解体・怪我・警戒は
すべて [`HuntingSystem.md`](./HuntingSystem.md) が持ちます。どの動物がどの土地にどれだけ居るかは
[`Animals.md`](../world/Animals.md)、罠そのものの素材とレシピは
[`SurvivalItems.md`](../world/SurvivalItems.md) 1.2 節・[`Skills.md`](../world/Skills.md) の関心事です。

**新設する文法はありません。** 導入するのは語彙の名前だけで、仕組みはすべて
[`GameElementDefinition.md`](./GameElementDefinition.md) の既存機能に載ります。

| 種別 | 名前 |
|---|---|
| タグ | `trap`（罠）・`bait`（餌になる物） |
| スロット | `catch`（掛かったもの） |
| プロパティ | `catch_remaining`（次の判定までの残り）・`bait`（仕掛けた餌。餌の側では「仕掛けると増える量」）・`miss_weight`（空振りの重み）・`<動物>_catch`（その土地でその動物が掛かる重み） |
| 型 | `snare`（くくり罠） |

| 決めたいこと | 載せた既存機能 |
|---|---|
| 結果が出るまでの時間（2 節） | `range` + `accumulate` + `on_shortfall`（6.3 節） |
| 待ち時間のばらつき（2.1 節） | 生成時に 1 回ロールする初期値（6.2 節）と、当たるまでの回数 |
| 土地ごとの成否（3 節） | `inherit`（6.5 節）と `pick` の `weight`（10.2 節） |
| 餌（4 節） | `transfer`（9.5 節。炉へ薪をくべるのと同じ形、[`FireSystem.md`](./FireSystem.md) 2 節） |
| 開けるまで分からない（5 節） | `main_item_slot`（7.8 節） |
| 掛かった獲物が暴れない（5 節） | `passives` の `child` への `modify`（8.1 節） |

定義は `public/world-codex/traps.yaml`、検証は `tests/worldCodex/trapsYaml.test.ts` に置く予定です。

本ドキュメントは検討結果であり、確定仕様書ではありません。**本書の設計は全体が未実装**で、上記の
ファイルはまだ存在しません。5 節は `resists`（`HuntingSystem.md` 4 節）が実装されていることを前提に
します。数値はいずれも目安で、tick = 15 分・1 日 = 96 tick を前提とします。未決事項は 8 節に
整理しています。

## 1. 罠は 1 つの型で、土地に置かれている間だけ動く

**「仕掛けた罠」と「持ち歩く罠」を別の型にはしません。** 作動しているかどうかは、罠が今どのスロットに
入っているかが決めます。

```yaml
object_defs:
  snare:
    tags: [item, trap]
    main_item_slot: catch
    slots:
      # 掛かったもの。プレイヤーは取り出せるが入れられない枠ではなく、普通のitemスロットでよい
      # ——罠へ動物を手で入れられて困ることは無い（そもそも荒ぶる動物は手に持てない、
      # HuntingSystem.md 4節）。
      catch:
        cell_count: 1
        cell: {accept: {tag: animal}}
```

作動の条件は `{in_slot: items}`（14.2 節）1 つです。土地の `items` スロットは「地面」で
（[`ExplorationSystem.md`](./ExplorationSystem.md) 1.1 節）、手持ちは `hand`、かごの中は `contents` と
名前が違うので、**地面に置いた罠だけが動く**が条件 1 つで書けます。装備の `{in_slot: equip}`（8.2 節）
と同じ形で、罠のための新しい概念ではありません。

- **回収は普通のドラッグです。** 拾えば `in_slot` が変わって止まります。仕掛け直す専用の操作は要りません。
- **中身ごと持ち帰れます。** 掛かった獲物は罠の子なので、罠を手に取っても親は変わりません
  （5 節が拘束を保つのもこの間ずっとです）。その場で仕留めるか、罠ごと担いで帰るかが判断になります。

## 2. 見えないタイマーは、尽きたら周期を置き直して回り続ける

**罠は仕掛けた時刻からの残り時間を 1 つ持ち、0 に達した瞬間に 1 回抽選して、周期を置き直します。**

```yaml
props:
  catch_remaining:
    # 生成時に1回ロールされる位相（2.1節）。以後この幅は使われない。
    value: {min: 1, max: 16}
    # 0に達した瞬間にon_shortfallを発火させるため、下限は0ではなく1（6.3節）。
    range: {min: 1, max: 16}
    passives:
      - conditions:
          - {in_slot: items}                    # 地面に置かれている間だけ（1節）
          - not: {slot: catch, tag: animal}     # 空いている間だけ（6節）
        accumulate: {self: {catch_remaining: -1}}
    on_shortfall:
      pick:
        # 空振りは必ずリテラル参照の重みで、かつ先頭に置く（3節）。
        - weight: {prop: miss_weight}
          add: {self: {catch_remaining: 16}}
        - weight: {prop: rat_catch}
          add: {self: {catch_remaining: 16}}
          spawn: {object: rat, into: self}
        - weight: {prop: junglefowl_catch}
          add: {self: {catch_remaining: 16}}
          spawn: {object: junglefowl, into: self}
```

- **周期の置き直しを全候補へ書くのは、`add` と `pick` が排他な兄弟キーだからです**（10 節）。
  探索の進捗 +1 が `explore` の全候補に書かれている（`ExplorationSystem.md` 2 節）のと同じ形です。
- **`set` ではなく `add` で戻します**（6.3 節）。1 tick で複数回分飛び越えた場合でも超過分を失いません。
- **`spawn` の `into: self` は罠の `catch` 枠へ入ります**（9.4 節。スロットは 1 つしか無いので、著者は
  スロット名を書きません）。枠が埋まっていれば土地へ強制配置されてしまいますが、埋まっている間は
  そもそもタイマーが減りません（6 節）。
- **バーには出ません。** カードの状態バーは名前で決まった量だけを映す（[`CardView.md`](../ui/CardView.md)
  8 節）ので、`catch_remaining` を隠すための仕掛けは要りません。罠のカードに出るのは耐久度だけです。

### 2.1 ランダムにするのは待ち時間ではなく、位相と回数

**「いつ結果が出るか分からない」は、タイマーの初期値を毎回振り直すのではなく、当たるまでの回数が
決まっていないことが作ります。**

抽選は 16 tick（4 時間）ごとに回り、1 回あたりの成功率は 3 節が決めます。仮に 3 割なら、掛かるまでの
待ち時間は幾何分布になり——数時間で掛かることも、丸一日空振りが続くこともあります。**乱数を 1 つも
足さずに、狩猟には無い「待たされる」が出ます。**

そのうえで初期値だけは `{min: 1, max: 16}` の範囲でロールします（6.2 節）。これは待ち時間の幅ではなく
**位相**で、複数の罠が同じ tick に一斉に判定するのを防ぐためだけのものです。

**周期そのものを毎回振り直す形は採りません。** `set`/`add` の値はリテラルだけで（9.2 節）、範囲ロールが
効くのは生成時だけなので、周期を毎回振るには罠が自分を `destroy` して同じ型を `spawn` し直すことに
なります。生まれ直した罠は耐久も餌も引き継がない（9.4 節）ので、**待ち時間をばらけさせるためだけに
罠の状態が消えます**。

## 3. 何が掛かるかは、土地が宣言した量を罠が継承して決める

**その土地に何がどれだけ居るかは土地の `props` が持ち、罠は `inherit` でそれを自分の重みとして
引きます**（6.5 節）。

```yaml
# locations.yaml — 草原
grassland:
  props:
    rat_catch: {value: 6}
    junglefowl_catch: {value: 10}
```

```yaml
# traps.yaml — くくり罠
props:
  # 素の値は0で、祖先（＝置かれている土地）が宣言していれば、その実効値が加算される。
  rat_catch: {value: 0, inherit: true}
  junglefowl_catch: {value: 0, inherit: true}
  miss_weight:
    value: 40
    # 餌のmodifyが押し下げても0にはしない（4節）。上限は素の値。
    range: {min: 5, max: 40}
```

- **宣言していない土地では、その候補が抽選から外れます。** 寄与が 0 なら重みが 0 になり、`pick` は
  重みを 0 でクランプして候補ごと落とします（`HuntingSystem.md` 5.3 節）。**罠の側は 1 行も書き換えずに、
  土地の `props` の有無だけで「岩礁海岸にヤケイは掛からない」が決まります。**
- **全候補が 0 になっても先頭が選ばれるため**（同 5.3 節）、空振り候補は必ずリテラル参照の重みを持ち、
  かつ先頭に置くことを規約にします。動物の 1 手で攻撃を先頭に置くのと同じ理由です。
- **土地を経由するので、罠を別の土地へ移すだけで確率が入れ替わります。** `inherit` は親が変われば
  解決し直され、どこに仕掛けるかがそのまま判断になります。

**動物ごとに別のプロパティを持たせ、1 つの生息数へまとめないのは、罠が何を捕るかを土地が選ぶ
ためです。** 1 つの量にすると、掛かる確率は土地で変えられても、掛かるものは罠が決めることになります。

**探索の `<動物>_find`（`ExplorationSystem.md` 2 節）とは別のつまみです。** 見つけて追う相手と罠に
掛かる相手は同じではなく（シカは探索では出るが罠には掛からない）、1 つのつまみに兼ねさせると、
どちらかの調整がもう一方を巻き込みます。土地の亜種が両方を上書きできる点は同じです
（`Animals.md` 8 節）。

## 4. 餌は成功率を上げず、空振りの重みを下げる

**餌になる食料を罠へ重ねると、その物が持つ `bait` が罠の `bait` へ移り、食料そのものは消えます。**
炉へ薪をくべるのとまったく同じ形です（`FireSystem.md` 2 節）。

```yaml
# 罠の側が宣言する
combinations:
  add_bait:
    with: bait
    duration: 1
    conditions:
      - {reason: trap_baited, prop: bait, lt: 24}
    transfer:
      amount: 999
      from_object: dragged
      from_prop: bait
      to_prop: bait
    destroy: dragged
```

```yaml
# 餌の側が宣言する
props:
  bait:
    value: 8
```

`transfer` を使うのは、`add` だと罠の種類 × 餌の種類の数だけ固定値を書くことになるためです。移る量は
餌の側が 1 箇所で持ちます。

**効かせ先は各動物の重みではなく、空振りの重み 1 つです。**

```yaml
props:
  bait:
    value: 0
    range: {min: 0, max: 24}
    stages:
      - {name: unbaited}
      - name: baited
        min: 1
        passives:
          - modify: {self: {miss_weight: -25}}
    passives:
      - conditions:
          - {in_slot: items}
        accumulate: {self: {bait: -1}}
```

- **動物ごとに押し上げると、餌が「何が掛かるか」まで決めてしまいます。** それは土地の担当です（3 節）。
  空振りを下げれば、掛かるものの比率は変えずに掛かる確率だけが上がります。
- **`miss_weight` の `range.min` が 5 で止めるので、餌を積んでも必中にはなりません**（8.3 節。合成結果の
  下限はプロパティ側の `range` が持ちます）。
- **餌は仕掛けている間だけ減ります**（24 tick = 6 時間）。**罠を放置しても餌は待っていてくれない**ので、
  「餌を仕掛けて見に行く」が 1 往復の単位になります。
- **これが罠の代償です。** 罠自体は繊維から作れて安全ですが、餌は**自分が食べられる食料を先に賭ける**
  ことです。序盤ほど重く、蓄えができるほど軽くなる——罠を回し始める時期が、餌を出せるようになった
  時期と一致します。

## 5. 掛かった獲物は、スロットの中で拘束される

**罠は自分の子の `wariness` を打ち消し、`vulnerability` を押し上げます。**

```yaml
passives:
  - modify:
      child:
        wariness: -100
        vulnerability: 200
```

これは気を失った動物に対する宣言（`animals.yaml` の `consciousness` の `unconscious` 段）とまったく
同じ内容で、**罠は「もがけない状態」を外から与える 2 つ目の道**になります。`HuntingSystem.md` 1.4 節が
「同じ量へ後から『罠にかかっている』『拘束されている』も流せます」と予告していた接続がこれです。

**この 1 ブロックが 3 つのことを同時に決めます。**

| | |
|---|---|
| 掛かった獲物が飛び出さない | `resists` は実効値を読む（14.1 節）ので成立せず、`HuntingSystem.md` 4.1 節の「入れ物の中で成立したらこぼれ出る」が起きない |
| その場で仕留められる | 仕留めの候補の重みが `vulnerability` そのもの（同 1.4 節）なので、罠に掛かった相手はほぼ一撃で決まる |
| 取り出せば暴れる | 罠から出れば寄与が消えて元の警戒へ戻る。`resists` が成立し、手には持てず地面へ落ちる |

**専用の「拘束」という概念を作りません。** 罠が捕らえるという出来事は、既にある 2 つの量を外から
動かすことに尽きます。

**何が掛かったかは、カードを押すまで分かりません。** `main_item_slot: catch` を名乗るので、罠のカードを
押せば中身が並びます（7.8 節）。レーンの上では罠は罠のままで、空の罠と獲物の入った罠は見分けが
付きません——**開けてみるまで分からない**が、隠すための処理を 1 つも書かずに成立します。

**作動したことも告げません。** 出入りを伴わない出来事は、起こした側が `signal`（9.8 節）で告げなければ
誰にも届きません。罠はその沈黙のほうを使います——**掛かったかどうかは見回って初めて分かる**が罠の
本体で、告げる経路を 1 つでも開けると、罠は待つ物ではなく報せる物になります。

## 6. 回収するまで、次は掛からない

**タイマーが減る条件には「`catch` が空であること」が入っています**（2 節の
`not: {slot: catch, tag: animal}`）。掛かった瞬間に時間は止まり、獲物を出すまで次の抽選は回りません。

- **見に行く理由が値だけで立ち上がります。** 放置した罠は 1 匹目で止まるので、罠を増やしても
  見回らなければ増えません。「仕掛けて忘れる」が最適にならない、という制約を条件 1 つで書けます。
- **罠は餌を食い続けません**（4 節の `bait` も同じ `in_slot` のゲートで減りますが、こちらは獲物が
  入っていても減り続けます——掛かった獲物の周りで餌が傷むのは止められません）。
- **枠が埋まったまま抽選が回る状態を作らないので、2 節の `spawn` が土地へこぼれることもありません。**

罠の耐久（`durability`、[`DurabilitySystem.md`](./DurabilitySystem.md)）は仕掛けている間ずっと減り、
獲物が掛かった回にまとめて減ります（もがかれて傷む）。**罠は永久機関にならず、繊維を編み直す仕事が
定期的に戻ってきます。**

## 7. 狩猟との非対称

| | 狩猟（`HuntingSystem.md`） | 罠（本書） |
|---|---|---|
| **危険** | 反撃を受ける。深手は数日残り、手当ての間も殴られる | 無い。掛かった相手は拘束されている（5 節） |
| **拘束** | tick が動物の手番なので、対峙している間は他のことができない | 仕掛けたら別の土地へ行ける。ただし回収に戻る（6 節） |
| **時間** | 15 分の一撃を重ねる。決着はその場 | 4 時間ごとに 1 回抽選。掛かるまで何度でも回る（2 節） |
| **前払い** | 武器（作る手間と、賭ける耐久） | 罠（繊維）と餌（**食べられる食料**、4 節） |
| **獲物** | 大型まで。1 頭で数日分の肉 | 小動物だけ（`Animals.md` 3 節）。1 匹の肉は少ない |
| **運** | 当たり所と、負う怪我の抽選 | **いつ・何が掛かるかの抽選**（2.1 節・3 節） |
| **土地の効き方** | 遭遇するかどうか（探索・移動） | 成功率そのもの（3 節） |

**罠は狩猟の下位互換ではなく、賭けるものが違います。** 狩猟が賭けるのは身体と武器で、罠が賭けるのは
時間と食料です。序盤は食料が出せないので罠が回らず、武器を作れば大型が獲れるようになるので罠は
上位に置き換わりません——**両方が同時に成り立つのは、片方が危険を、もう片方が時間を課しているから**です。

## 8. 未決事項・今後の検討課題

- **同じ土地に罠を何個も置いた場合。** 現状は個数に比例して収穫が増えます。掛かった瞬間に土地の
  `<動物>_catch` を `add` で減らす（獲り尽くすと居なくなる）形は書けますが、**回復の仕組み**を
  同時に決める必要があります
- **仕掛けるのに時間を課すか。** 今は地面へ置くだけで作動します（1 節）。枠の `put_in`（7.10 節）は
  土地の `items` 全体に効いてしまうので使えず、罠の側の `actions` で課すと「置いただけの罠」と
  「仕掛けた罠」を区別する状態が 1 つ増えます
- **獲物を入れたまま放置したときの変化。** 死ぬ・傷む・他の動物に食われる・自力で外れて逃げる。
  腐敗（`DurabilitySystem.md` 3 節）がまだ入っていないため、今は掛かったまま無限に待てます
- **餌の段を増やすか**（4 節は 2 段）。量が多いほど効く形にするか、置いた瞬間から一定にするか
- **仕掛けた罠が画面のどこにも出ないこと。** 5 節のとおり罠は何も告げないので、遠くの土地に置いた
  罠は、そこへ戻るまでプレイヤーの視界から完全に消えます。仕掛けた場所を忘れる負担が実際に重いなら、
  罠の作動ではなく**どこに何個仕掛けたか**を出す形（一覧・地図側）で埋めることになります
- **狩猟スキル**（[`SkillSystem.md`](./SkillSystem.md)）の効かせ方。`miss_weight` を押し下げる `modify` が
  素直ですが、スキルは罠ではなくプレイヤーが持つため、罠から見て `ancestor` に居ません
  （仕掛けた罠の祖先は土地です）
- **罠の種類を増やすか。** 落とし穴（大型・掘削具が要る）、筌（魚・`Animals.md` 9 節）はいずれも
  本書の形をそのまま使えますが、掛かる相手が土地の別のつまみになります
- **罠が効かない動物の表し方**（`Animals.md` 10 節）。サルは学習し、シカは速い、という「その土地には
  居るのに罠には掛からない」を、土地が `<動物>_catch` を宣言しないことで表すのか、別の量で表すのか
