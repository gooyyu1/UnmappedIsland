# 罠システム設計

## 概要

本ドキュメントは、罠を仕掛けてから獲物が掛かるまでの設計をまとめたものです。罠は**時間と運を払って、
危険を払わずに獲物を得る**道で、直接戦う狩猟との非対称（7 節）が設計の芯です。

**掛かった後は狩猟と同じです。** 罠の中の獲物は普通の動物のカードで、仕留め・解体・怪我・警戒は
すべて [`HuntingSystem.md`](./HuntingSystem.md) が持ちます。どの動物がどの土地にどれだけ居るかは
[`Animals.md`](../world/Animals.md)、罠そのものの素材とレシピは
[`SurvivalItems.md`](../world/SurvivalItems.md) 1.2 節・[`Skills.md`](../world/Skills.md) の関心事です。

**新設する文法は `spawn` の `into: child` 1 つだけです**（5.3 節）。罠が自分の生んだ獲物へ怪我を渡す
経路がこれしかなく、他はすべて [`GameElementDefinition.md`](./GameElementDefinition.md) の既存機能に
載ります。

| 種別 | 名前 |
|---|---|
| タグ | `trap`（罠）・`plant_bait`（草の餌になる物）・`meat_bait`（肉の餌になる物） |
| スロット | `catch`（掛かったもの） |
| プロパティ | `catch_remaining`（次の判定までの残り）・`plant_bait`/`meat_bait`（仕掛けた餌。餌の側では「仕掛けると増える量」）・`herbivore_weight`/`carnivore_weight`（食性の卓の重み）・`miss_weight`（何も寄って来なかった回の重み）・`<動物>_catch`（その土地でその動物が掛かる重み） |
| 型 | `snare`（くくり罠）・`box_trap`（かご罠）・`pitfall`（落とし穴）・`staked_pitfall`（杭を打った落とし穴）・`pen`（檻） |

| 決めたいこと | 載せた既存機能 |
|---|---|
| 結果が出るまでの時間（2 節） | `range` + `add` + `on_shortfall`（6.3 節） |
| 待ち時間のばらつき（2.1 節） | 生成時に 1 回ロールする初期値（6.2 節）と、当たるまでの回数 |
| 土地ごとの成否（3 節） | `inherit`（6.5 節）と `pick` の `weight`（10.2 節） |
| 罠のサイズ（1.1 節） | 内側の `pick` に並べた候補の一覧 |
| 餌と食性（4 節） | `transfer`（9.5 節。炉へ薪をくべるのと同じ形、[`FireSystem.md`](./FireSystem.md) 2 節）と `pick` の入れ子（10.1 節） |
| 開けるまで分からない（5 節） | `main_item_slot`（7.8 節） |
| 掛かった獲物が暴れない（5 節） | `passives` の `child` への `modify`（8.1 節） |
| 獲物を生かすか殺すか（5.1・5.2 節） | 罠ごとの怪我（[`InjurySystem.md`](./InjurySystem.md)）と、その `bleeding` の有無 |
| 掛かり方のばらつき（5.1 節） | 生成時に 1 回ロールする初期値（6.2 節） |

定義は `public/world-codex/traps.yaml`（罠）・`injuries.yaml`（`snare_laceration`）・`animals.yaml`
（ヤケイ・ネズミ）・`locations.yaml`（土地ごとのつまみ）、検証は `tests/worldCodex/trapsYaml.test.ts` です。

本ドキュメントは検討結果であり、確定仕様書ではありません。**くくり罠 1 つが実装済み**で、仕掛ける・
待つ・掛かる・怪我が刺さる・死ぬか生き延びる・放置すれば壊れる、までが動きます。**未実装なのは
1.2 節が挙げる残り 4 つの型と、そこに乗る 5.2 節（生かす罠）**です。5 節の `resists`
（`HuntingSystem.md` 4 節）も未実装のため、掛かった獲物が飛び出さないことは今のところ拘束の宣言
だけが支えています。数値はいずれも目安で、tick = 15 分・1 日 = 96 tick を前提とします。未決事項は
8 節に整理しています。

## 1. 罠は 1 つの型で、土地に置かれている間だけ動く

**「仕掛けた罠」と「持ち歩く罠」を別の型にはしません。** 作動しているかどうかは、罠が今どのスロットに
入っているかが決めます。

```yaml
object_defs:
  snare:
    tags: [item, trap]
    main_item_slot: catch
    stackable: false        # 中身が個体ごとに違う（1.1節）
    slots:
      # 掛かったもの。プレイヤーは取り出せるが入れられない枠ではなく、普通のitemスロットでよい
      # ——罠へ動物を手で入れられて困ることは無い（そもそも荒ぶる動物は手に持てない、
      # HuntingSystem.md 4節）。
      catch:
        cell_count: 1
        # 生きた獲物と死体の両方が持つタグ（1.1節）。capacityは宣言しない（同）。
        cell: {accept: {tag: quarry}}
```

作動の条件は `{in_slot: items}`（14.2 節）1 つです。土地の `items` スロットは「地面」で
（[`ExplorationSystem.md`](./ExplorationSystem.md) 1.1 節）、手持ちは `hand`、かごの中は `contents` と
名前が違うので、**地面に置いた罠だけが動く**が条件 1 つで書けます。装備の `{in_slot: equip}`（8.2 節）
と同じ形で、罠のための新しい概念ではありません。

- **回収は普通のドラッグです。** 拾えば `in_slot` が変わって止まります。仕掛け直す専用の操作は要りません。
- **中身ごと持ち帰れます。** 掛かった獲物は罠の子なので、罠を手に取っても親は変わりません
  （5 節が拘束を保つのもこの間ずっとです）。その場で仕留めるか、罠ごと担いで帰るかが判断になります。

**掘って作る罠は動きません。** 落とし穴は `fixture` で、作動の条件は `{in_slot: fixtures}` になります。
回収できないので、仕掛けた土地がそのまま賭けになります——**持ち運べる罠は仕掛け直せる代わりに小さい、
掘る罠は大きい代わりにその土地に据え置き**、という差が、型ごとのスロット名 1 つから出ます。

### 1.1 罠のサイズは、掛かる候補の一覧が持つ

**「どこまで大きい獲物が掛かるか」は、その型の内側の `pick`（3 節）にどの動物を並べたかで決まります。**
小型の罠にイノシシの候補は書かないので、掛かりようがありません。

**`catch` スロットに `capacity`（7.3 節）を宣言してサイズを表すことはできません。** 上限を宣言した
スロットを `main_item_slot` として名乗る入れ物には容量のバーが出る（[`CardView.md`](../ui/CardView.md)
8 節）ためで、理由は 2 つあります。

- **バーは比例で、二値になりません**（`Slot.fillRatio` は `min(1, 中身のvolume合計 ÷ capacity)`）。
  動物の `volume` は体格そのものなので、候補が数種しかない罠では**何が掛かったかまで読めます**（5 節）。
  飽和させて二値にすることもできません——`capacity` を最大の候補より小さくすると `spawn` が弾かれ、
  獲物は起点の親＝土地へ強制配置されます（9.4 節）。
- **バーが答える問いが、罠には無い。** 容量のバーは「あとどれだけ入るか」を言うものですが、罠の枠は
  1 つで、次が入らないのは `capacity` ではなく `cell_count: 1` とタイマーの停止（6 節）のためです。

枠が受けるのは `quarry`（狩りの成果として数える物）で、**生きた獲物と死体の両方が持ちます**。`animal`
で受けると、掛かった獲物がその場で死んだ瞬間に死体が枠から弾かれ、地面へ落ちます——**置き換えの配置も
枠の要件を通る**ためです（`WorldObject.attachToSlot`）。タイマーが「何か入っているか」を問うのも同じ
タグで、`item` のような広いタグを流用せずに済みます。

**`stackable: false` を宣言します。** 中身が個体ごとに違う物は束ねない、というかご・道と同じ理由です
（[`SlotSystem.md`](./SlotSystem.md) 4 節）。束ねると、スタックは代表の状態しか映さないので、**空の罠と
獲物の入った罠が 1 枚に重なります**。

### 1.2 型は、サイズと生死の 2 軸で並ぶ

|  | 殺す（5.1 節） | 生かす（5.2 節） |
|---|---|---|
| **小型** | `snare` くくり罠（繊維だけ）**←実装済み** | `box_trap` かご罠（編み籠＋繊維） |
| **中型** | `staked_pitfall` 杭を打った落とし穴（掘削具＋長い棒） | `pitfall` 落とし穴（掘削具） |
| **大型** | `staked_pitfall`（同上） | `pen` 檻（木材＋縄） |

- **生かす側が常に高くつきます。** 締めつけるだけの輪と、閉じ込めておける箱では要る材料が違い、
  大型ではその差が最も開きます（檻は木材と縄、落とし穴は掘る時間）。**手懐けたいなら高いほうを
  払う**が、材料表だけで成立します。
- **落とし穴は 1 つの型を杭で分岐させます。** 掘った穴に長い棒を立てれば殺す罠になる、という
  `combinations` 1 つで、中型と大型の両方の「殺す」欄が埋まります。**杭が変えるのは、掛かった相手へ
  刺さる怪我だけです**（5.1 節）——穴も、掛かる候補も、タイマーもそのままです。
- **殺す・生かすの差は、材料ではなく怪我が持ちます。** 同じ落とし穴が、杭の有無で刺す傷を変えるだけで
  両方の欄に立ちます。**型を増やさずに軸を 1 本足せる**のは、生死が罠の構造ではなく怪我の中身に
  宿っているからです。

## 2. 見えないタイマーは、尽きたら周期を置き直して回り続ける

**罠は仕掛けた時刻からの残り時間を 1 つ持ち、0 に達した瞬間に 1 回抽選して、周期を置き直します。**

```yaml
props:
  catch_remaining:
    # 生成時に1回ロールされる位相（2.1節）。以後この幅は使われない。
    value: {min: 1, max: 16}
    # 0に達した瞬間にon_shortfallを発火させるため、下限は0ではなく1（6.3節）。
    range: {min: 1, max: 16}
    passives:
      - conditions:
          - {in_slot: items}                  # 地面に置かれている間だけ（1節）
          # 空いている間だけ（6節）。獲物も死体もquarryなので、両方をこれ1つで拾う。
          - not: {slot: catch, tag: quarry}
        add: {self: {catch_remaining: -1}}
    on_shortfall:
      # 外側は食性の卓を選び（餌が決める、4節）、内側はその卓で掛かるかどうかと種を選ぶ
      # （土地が決める、3節）。
      add: {self: {catch_remaining: 16}}
      pick:
        # 何も寄って来なかった回。先頭に置く（3節）。
        - weight: {prop: miss_weight}
        - weight: {prop: herbivore_weight}
          pick:
            # 寄ってはきたが掛からなかった回。その食性の相手が居ない土地では必ずここになる。
            - weight: 8
            # 掛かった候補は、獲物とその罠の怪我を順に生む（5.1節）。
            - weight: {prop: junglefowl_catch}
              spawn:
                - {object: junglefowl, into: self}
                - {object: snare_laceration, into: child}
            - weight: {prop: rat_catch}
              spawn:
                - {object: rat, into: self}
                - {object: snare_laceration, into: child}
        - weight: {prop: carnivore_weight}
          pick:
            - weight: 8
            # ネズミは雑食なので、両方の卓に同じつまみで載る（4.1節）。
            - weight: {prop: rat_catch}
              spawn:
                - {object: rat, into: self}
                - {object: snare_laceration, into: child}
```

- **周期の置き直しは、どの候補が選ばれても起こるので、`pick` の外へ1つだけ置きます**（9.7 節）。
  探索の進捗 +1 が `explore` で同じ形になっている（`ExplorationSystem.md` 2 節）のと揃えています。
- **`set` ではなく `add` で戻します**（6.3 節）。1 tick で複数回分飛び越えた場合でも超過分を失いません。
- **`spawn` の `into: self` は罠の `catch` 枠へ入ります**（9.4 節。スロットは 1 つしか無いので、著者は
  スロット名を書きません）。枠が埋まっていれば土地へ強制配置されてしまいますが、埋まっている間は
  そもそもタイマーが減りません（6 節）。
- **バーには出ません。** カードの状態バーは名前で決まった量だけを映す（[`CardView.md`](../ui/CardView.md)
  8 節）ので、`catch_remaining` を隠すための仕掛けは要りません。罠のカードに出るのは耐久度だけです。

### 2.1 ランダムにするのは待ち時間ではなく、位相と回数

**「いつ結果が出るか分からない」は、タイマーの初期値を毎回振り直すのではなく、当たるまでの回数が
決まっていないことが作ります。**

抽選は 16 tick（4 時間）ごとに回り、1 回あたりの成功率は 3 節が決めます。仮に 3 割なら、掛かるまでの
待ち時間は幾何分布になり——数時間で掛かることも、丸一日空振りが続くこともあります。**乱数を 1 つも
足さずに、狩猟には無い「待たされる」が出ます。**

そのうえで初期値だけは `{min: 1, max: 16}` の範囲でロールします（6.2 節）。これは待ち時間の幅ではなく
**位相**で、複数の罠が同じ tick に一斉に判定するのを防ぐためだけのものです。

**周期そのものを毎回振り直す形は採りません。** `set`/`add` の値はリテラルだけで（9.2 節）、範囲ロールが
効くのは生成時だけなので、周期を毎回振るには罠が自分を `destroy` して同じ型を `spawn` し直すことに
なります。生まれ直した罠は耐久も餌も引き継がない（9.4 節）ので、**待ち時間をばらけさせるためだけに
罠の状態が消えます**。

## 3. 何が掛かるかは、土地が宣言した量を罠が継承して決める

**その土地に何がどれだけ居るかは土地の `props` が持ち、罠は `inherit` でそれを自分の重みとして
引きます**（6.5 節）。

```yaml
# locations.yaml — 草原
grassland:
  props:
    rat_catch: {value: 6}
    junglefowl_catch: {value: 10}
```

```yaml
# traps.yaml — くくり罠
props:
  # 素の値は0で、祖先（＝置かれている土地）が宣言していれば、その実効値が加算される。
  rat_catch: {value: 0, inherit: true}
  junglefowl_catch: {value: 0, inherit: true}
  miss_weight:
    value: 40
    # 餌のmodifyが押し下げても0にはしない（4節）。上限は素の値。
    range: {min: 5, max: 40}
```

- **宣言していない土地では、その候補が抽選から外れます。** 寄与が 0 なら重みが 0 になり、`pick` は
  重みを 0 でクランプして候補ごと落とします（`HuntingSystem.md` 5.3 節）。**罠の側は 1 行も書き換えずに、
  土地の `props` の有無だけで「岩礁海岸にヤケイは掛からない」が決まります。**
- **全候補が 0 になっても先頭が選ばれるため**（同 5.3 節）、空振り候補はどちらの階層でも先頭に置くことを
  規約にします。動物の 1 手で攻撃を先頭に置くのと同じ理由です。**内側の空振りが要るのはこのためだけ
  ではありません**——その食性の相手が 1 種も居ない土地では、内側は必ずそこへ落ちます。
- **餌が土地に居ない動物を呼ぶことはできません。** 餌は内側の卓を選ぶ確率だけを動かし（4 節）、
  `<動物>_catch` そのものには触れません。触れる形にすると、宣言していない土地でも重みが立ってしまい、
  そうさせない条件は自分の実効値を見ることになって循環します（14.1 節）。
- **土地を経由するので、罠を別の土地へ移すだけで確率が入れ替わります。** `inherit` は親が変われば
  解決し直され、どこに仕掛けるかがそのまま判断になります。

**動物ごとに別のプロパティを持たせ、1 つの生息数へまとめないのは、罠が何を捕るかを土地が選ぶ
ためです。** 1 つの量にすると、掛かる確率は土地で変えられても、掛かるものは罠が決めることになります。

**探索の `<動物>_find`（`ExplorationSystem.md` 2 節）とは別のつまみです。** 見つけて追う相手と罠に
掛かる相手は同じではなく（シカは探索では出るが罠には掛からない）、1 つのつまみに兼ねさせると、
どちらかの調整がもう一方を巻き込みます。土地の亜種が両方を上書きできる点は同じです
（`Animals.md` 8 節）。

## 4. 餌は食性までを決め、種は決めない

**餌は 2 種類あり、どちらを仕掛けたかが、外側の `pick` でどちらの卓を引くかを動かします。** 掛かる確率が
上がるのと、掛かる相手が食性で寄るのは、この 1 つの動きの両面です。

```yaml
# 罠の側が宣言する。草の餌と肉の餌で1つずつ。
combinations:
  add_plant_bait:
    with: plant_bait
    duration: 1
    conditions:
      - {reason: trap_baited, prop: plant_bait, lt: 24}
    transfer: {amount: 999, from_object: dragged, from_prop: plant_bait, to_prop: plant_bait}
    destroy: dragged
  add_meat_bait:
    with: meat_bait
    duration: 1
    conditions:
      - {reason: trap_baited, prop: meat_bait, lt: 24}
    transfer: {amount: 999, from_object: dragged, from_prop: meat_bait, to_prop: meat_bait}
    destroy: dragged
```

```yaml
# 餌の側が宣言する。タグとプロパティの名前で、どちらの餌かが決まる。
raw_meat:
  tags: [item, food, meat_bait]
  props:
    meat_bait: {value: 8}
```

`transfer` を使うのは、`add` だと罠の種類 × 餌の種類の数だけ固定値を書くことになるためです。移る量は
餌の側が 1 箇所で持ちます（`FireSystem.md` 2 節の燃料と同じ形）。

```yaml
# 罠の側の効かせ方
props:
  herbivore_weight: {value: 10, range: {min: 0, max: 35}}
  carnivore_weight: {value: 10, range: {min: 0, max: 35}}
  plant_bait:
    value: 0
    range: {min: 0, max: 24}
    passives:
      - conditions: [{in_slot: items}]
        add: {self: {plant_bait: -1}}
  meat_bait:
    value: 0
    range: {min: 0, max: 24}
    passives:
      - conditions: [{in_slot: items}]
        add: {self: {meat_bait: -1}}
passives:
  - conditions: [{prop: plant_bait, gte: 1}]
    modify: {self: {herbivore_weight: 25, miss_weight: -25}}
  - conditions: [{prop: meat_bait, gte: 1}]
    modify: {self: {carnivore_weight: 25, miss_weight: -25}}
```

- **1 つのブロックが 2 つのことを同時に言います。** その食性の卓が引かれやすくなり、何も寄って来ない回
  （`miss_weight`）が減ります。**餌を置くほど当たり、かつ食性が寄る**が、加算式を 1 つも書かずに出ます。
- **`miss_weight` の `range.min` が 5 で止めるので、餌を積んでも必中にはなりません**（8.3 節。合成結果の
  下限はプロパティ側の `range` が持ちます）。両方の餌を仕掛ければ両方の卓が上がりますが、そのぶん
  食料を 2 種類ぶん賭けることになります。
- **餌は仕掛けている間だけ減ります**（24 tick = 6 時間）。**罠を放置しても餌は待っていてくれない**ので、
  「餌を仕掛けて見に行く」が 1 往復の単位になります。
- **これが罠の代償です。** 罠自体は繊維から作れて安全ですが、餌は**自分が食べられる食料を先に賭ける**
  ことです。序盤ほど重く、蓄えができるほど軽くなる——罠を回し始める時期が、餌を出せるようになった
  時期と一致します。肉の餌はさらに重く、**肉食獣を狙うには先に肉を得ていなければなりません**。

### 4.1 食性は餌が持ち、罠の型は持たない

**草食用の罠・肉食用の罠は作りません。** 同じ輪も同じ穴も、置いた餌が違えば違う相手が掛かる、が現実に
近く、**罠の型はサイズと生死（1.2 節）の 2 軸だけで済みます**。型で分けると、サイズ 3 × 生死 2 × 食性 2 の
12 型を作って餌を無くすことになります。

- **雑食は両方の卓に載ります。** ネズミ・サル・イノシシは、同じ `<動物>_catch` を草食の卓と肉食の卓の
  両方から読むだけです。3 つ目の食性を作る必要はありません（2 節の例のネズミがこれです）。
- **合わない餌は損になります。** 草食の居ない土地で草の餌を焚くと、卓を引く確率だけが上がって内側の
  空振りへ落ちます（3 節）。**罠は土地に合わせて餌を選ぶもの**で、その判断が成立するのは、餌が確率を
  上げるだけでなく**振り分けている**からです。
- **食性そのものはどこにも宣言しません。** 「ヤケイは草食」という事実は、罠の草食の卓にヤケイの候補が
  並んでいることが言います。動物の側にタグやプロパティを足すと、**候補の一覧と動物の宣言という
  2 箇所が暗黙に一致すべき規約**になります。

## 5. 掛かった獲物は、スロットの中で拘束される

**罠は自分の子の `wariness` を打ち消し、`vulnerability` を押し上げます。**

```yaml
passives:
  - modify:
      child:
        wariness: -100
        vulnerability: 200
```

これは気を失った動物に対する宣言（`animals.yaml` の `consciousness` の `unconscious` 段）とまったく
同じ内容で、**罠は「もがけない状態」を外から与える 2 つ目の道**になります。`HuntingSystem.md` 1.4 節が
「同じ量へ後から『罠にかかっている』『拘束されている』も流せます」と予告していた接続がこれです。

**この 1 ブロックが 3 つのことを同時に決めます。**

| | |
|---|---|
| 掛かった獲物が飛び出さない | `resists` は実効値を読む（14.1 節）ので成立せず、`HuntingSystem.md` 4.1 節の「入れ物の中で成立したらこぼれ出る」が起きない |
| その場で仕留められる | 仕留めの候補の重みが `vulnerability` そのもの（同 1.4 節）なので、罠に掛かった相手はほぼ一撃で決まる |
| 取り出せば暴れる | 罠から出れば寄与が消えて元の警戒へ戻る。`resists` が成立し、手には持てず地面へ落ちる |

**ただし戻るのは、実体値が残っている間だけです。** 警戒は罠の中でも `-1/tick` で引き続けるので
（`animals.yaml` の `wariness`）、**長く閉じ込めた個体は出しても暴れません**。掛かってすぐなら暴れ、
半日置けば落ち着く——これが生かす罠から飼いならしへ続く道（5.2 節）になります。

**専用の「拘束」という概念を作りません。** 罠が捕らえるという出来事は、既にある 2 つの量を外から
動かすことに尽きます。

**何が掛かったかは、カードを押すまで分かりません。** `main_item_slot: catch` を名乗るので、罠のカードを
押せば中身が並びます（7.8 節）。レーンの上では罠は罠のままで、空の罠と獲物の入った罠は見分けが
付きません——**開けてみるまで分からない**が、隠すための処理を 1 つも書かずに成立します。

**作動したことも告げません。** 出入りを伴わない出来事は、起こした側が `signal`（9.8 節）で告げなければ
誰にも届きません。罠はその沈黙のほうを使います——**掛かったかどうかは見回って初めて分かる**が罠の
本体で、告げる経路を 1 つでも開けると、罠は待つ物ではなく報せる物になります。

### 5.1 罠は掛けた瞬間に、その罠の怪我を 1 つ刺す

**殺す罠と生かす罠の差は、獲物と一緒に生む怪我の中身だけです。** 罠は死を書かず、削りもしません
——刺すだけです。

```yaml
# 掛かった候補（2節）が、獲物と怪我を順に生む。
- weight: {prop: junglefowl_catch}
  spawn:
    - {object: junglefowl, into: self}
    - {object: snare_laceration, into: child}   # 直前に生んだ獲物のinjuriesスロットへ
```

`spawn` は配列を順に 1 つずつ生んで配置する（9.4 節）ので、**獲物を生んでから、その中へ怪我を生みます**。
`into: child` は本書が唯一新設する文法で、5.3 節が定めます。

**怪我は罠の型ごとに 1 つで、重さは個体ごとにばらつきます。** 生成時に 1 回ロールする初期値（6.2 節）が
「浅く掛かったか、深く食い込んだか」をそのまま表します。

```yaml
# くくり罠の怪我。縄が食い込んで裂ける傷で、laceration（injuries.yaml）より浅い。
snare_laceration:
  tags: [injury]
  traits: [treatable]
  bound_to_owner: true
  stackable: false
  props:
    severity:
      value: {min: 240, max: 480}
      range: {min: 1, max: 480}
      passives: [{add: {self: {severity: -1}}}]
      on_shortfall: {destroy: self}
    # 掛かり方の深さ。2〜4 tickで固まり、その間に30〜60mLを奪う。
    bleeding:
      value: {min: 40, max: 100}
      range: {min: 0, max: 100}
      passives: [{add: {self: {bleeding: -25}}}]
  passives:
    - modify: {parent: {pain: 50}}
    - conditions:
        - {prop: bleeding, gte: 1}
        - not: {slot: treatment, tag: hemostatic}
      add: {parent: {blood: -15}}
```

**死ぬかどうかは、怪我が奪う量と獲物の体格の比が決めます。** `blood` の `range.max` は体格そのもの
（サル 5 kg で 400 mL）なので、同じ 1 枚の傷が体格で意味を変えます。

| 獲物 | 血の量 | 奪われる 30〜60 mL は | 掛かった結果 |
|---|---|---|---|
| ネズミ（80 g） | 6 | 全部 | **必ず死ぬ** |
| 海鳥（400 g） | 32 | 全部〜ほぼ全部 | **ロール次第**（浅ければ 2 mL 残る） |
| ヤケイ（1 kg） | 80 | 4〜8 割 | 生き残るが、次の傷は耐えない |
| サル（5 kg） | 400 | 1 割前後 | 生き残る |
| イノシシ（60 kg） | 4,800 | 1 % 未満 | 応えない |

- **「小動物にとってはほとんどが致命的」が、レートを分けずに出ます。** 1 kg あたりに線が引かれるのは、
  怪我の側が奪う量を宣言し、体格の側が持ちこたえる量を宣言しているからです。
- **同じ罠でも死んだり死ななかったりします。** 海鳥はロールが分かれ目で、これが罠の運の 2 つ目です
  （1 つ目は 2.1 節の「いつ掛かるか」）。
- **見回りが早ければ助けられます。** 出血は 2〜4 tick（30 分〜1 時間）で固まり、その間に止血の治療具を
  当てれば `add` のゲートが閉じます（`InjurySystem.md` 3.1 節）。**生かして持ち帰りたいなら、
  罠を見に行く速さがそのまま手段になります。**
- **大型を殺す罠は、固まらない傷を刺します。** 杭を打った落とし穴の刺し傷は `bleeding` の引きが遅く
  （-1/tick で 100 tick）、その間 `blood` を -60/tick 奪います。イノシシの 4,800 mL でも 80 tick
  （20 時間）で尽きます。**サイズの差は罠の側ではなく、刺す怪我の中身が持ちます**
  （`InjurySystem.md` 4.2 節「武器の性格は、傷の枚数ではなく傷の中身で表す」と同じ形）。
- **死体は罠の中に残ります。** 枠が `quarry` で受ける（1.1 節）ので、`same_slot` の置き換えがそのまま
  通ります。タイマーのゲートも同じタグを問う（2 節）ので、**死体が入ったままでも次の抽選は回りません**。
- **最も小さい相手は、掛かった tick のうちに死にます。** 傷は最初の 1 tick で 15 mL 奪うので、
  6 mL のネズミは生きた姿で 1 度も画面に出ません。
- **掛かっていることは漏れません。** 出血の印（`CardView.md` 9.0 節）が上がるのは怪我を負った本人まで
  で、UI が見るのは直下の子だけです。罠の直下に居るのは動物で、動物自身は `bleeding` を持たないため、
  そこで止まります。

### 5.2 出血しない怪我は殺さず、動けなくする

**生かす罠が刺すのは、血を奪わない怪我です。** 落とし穴の骨折・捻挫（`sprained_ankle` の形）は
`bleeding` を持たないので、`severity` と `pain` だけが動きます。

**出血しない怪我で死ぬ道は要りません。** 死に方は渇き・飢え・失血の 3 つだけで、新しい死因は既存の
死に方へ流す、が全体の方針です（[`VitalsSystem.md`](./VitalsSystem.md) 8 節）。**出血しない怪我は、
殺さないための道具です**——生かす罠の性格そのものが、その空白でできています。

**無傷では捕らえません。** 罠は落ちるか締まるかで捕らえるので、何も起きずに閉じ込められることは
ありません。生かす罠が与えるのは「治る傷」で、5 節の `modify` が警戒を打ち消している間、
`resists`（`HuntingSystem.md` 4 節）は成立しないままです。

飼いならしは「`wariness` が 0 になれば台車・かごへ入る」ことで表される（同 4 節）ので、**生かす罠の
中身は、その条件を満たしたまま待っていられます**。危険な相手を無傷で確保しておける、という檻の
価値がそのまま出ます。

- **檻が高いのはこのためです**（1.2 節）。木材と縄を払う相手は、殺すには惜しい相手だけです。
- **殺す罠で飼いならすには、間に合わなければなりません。** 刺さるのは出血する傷なので、止血して
  初めて生かして持ち帰れます（5.1 節）。**生かす罠を建てるか、見回りを速くするか**という取り引きが、
  型と時間のあいだに立ちます。
- **治りを待つ必要はあります。** 骨折した個体は `severity` が引くまで傷を負ったままで、飼いならしの
  完了条件（`HuntingSystem.md` 8 節）がそれをどう見るかはまだ決まっていません。

### 5.3 新設する文法は、`spawn` の `into: child` 1 つ

**`into` に `child` を足します。** 起点を自分の子に取り、**子を走査して最初に受け取れた子のスロットへ**
配置します。

`into` は既に「起点の持つスロットを宣言順に走査し、最初に配置できたスロットへ入れる」という規則を
持つ（9.4 節）ので、**同じ規則が 1 階層下へ伸びるだけ**です。著者はスロット名も、どの子かも書きません
——怪我を受け取れるスロットを持つ子は 1 つしか居ません。

- **これが無いと、罠は自分が生んだ獲物へ何も渡せません。** `into` は `same_slot`/`self`/`actor` しか
  取れず、`actor` は `on_shortfall` に存在しません（9.4 節）。**罠には手番を持つ実行者が居ない**という
  一点だけで、`strike` が `into: actor` で書けること（`animals.yaml`）が書けなくなります。
- **一意性は罠が保証します。** `catch` は `cell_count: 1` なので子は 1 つです。一般には「最初に
  受け取れた子」で決まり、`into` が既にスロットに対して行っている決め方と同じです。
- **順序は `spawn` の配列が持ちます**（9.4 節）。獲物より前に怪我を書くと、受け取る子がまだ居ません。
- **型の差し替え（`snared_junglefowl`）は採りません。** `HuntingSystem.md` 4 節が飼いならしについて
  述べているのと同じ理由で、獲物の型が 2 つに割れると `resists`・解体・警戒がすべて二重になります。

## 6. 回収するまで、次は掛からない

**タイマーが減る条件には「`catch` が空であること」が入っています**（2 節の
`not: {slot: catch, tag: quarry}`）。掛かった瞬間に時間は止まり、獲物か死体を出すまで次の抽選は回りません。

- **見に行く理由が値だけで立ち上がります。** 放置した罠は 1 匹目で止まるので、罠を増やしても
  見回らなければ増えません。「仕掛けて忘れる」が最適にならない、という制約を条件 1 つで書けます。
- **罠は餌を食い続けません**（4 節の餌も同じ `in_slot` のゲートで減りますが、こちらは獲物が
  入っていても減り続けます——掛かった獲物の周りで餌が傷むのは止められません）。
- **枠が埋まったまま抽選が回る状態を作らないので、2 節の `spawn` が土地へこぼれることもありません。**

罠の耐久（`durability`、[`DurabilitySystem.md`](./DurabilitySystem.md)）は仕掛けている間ずっと減り、
獲物が掛かった回にまとめて減ります（もがかれて傷む）。**罠は永久機関にならず、繊維を編み直す仕事が
定期的に戻ってきます。**

### 6.1 放置された罠は破られ、獲物は逃げる

**獲物が入っている間、耐久は速く減ります。** もがかれ続ける罠は、空のまま風雨に晒される罠より
桁違いに早く傷みます。

```yaml
props:
  durability:
    value: 960
    range: {min: 1, max: 960}
    passives:
      - conditions: [{in_slot: items}]
        add: {self: {durability: -1}}       # 屋外での劣化（10日）
      - conditions: [{slot: catch, tag: quarry}]
        add: {self: {durability: -10}}      # もがかれている間（新品でも1日弱）
    on_shortfall:
      destroy: self
```

**壊れた罠の中身は、道連れにならず土地へこぼれます**（9.3 節）。

- **今のところ罰は「罠を失うこと」に留まります。** 罠が破られるまでのおよそ 86 tick（21 時間）で
  警戒は引き切っている（5 節）ので、こぼれた獲物は暴れも逃げもせず、その土地に立っています。
  **動物の手番**（`HuntingSystem.md` 5 節）が入って初めて、放置した罠の獲物は逃げます。
- **死なせずに罰するので、生かす罠の値打ち（5.2 節）は損なわれません。** 見回らなければ増えない
  （6 節）だけでなく、待たせすぎれば罠が減ります。
- **獲物ごとに何も分けません。** 大型ほど罠が保たないのは、耐久の側ではなく**掛かった相手が
  居座る時間**が決めます——小動物は掛かってすぐ死ぬ（5.1 節）ので、もがかれる時間そのものが短くなります。
- **飢えや渇きでは表しません。** 死に方は 3 つで、動物はまだ `blood` しか持ちません
  （[`VitalsSystem.md`](./VitalsSystem.md) 7 節・8 節）。渇きで死ぬ道は人にも実装されていない
  （`hydration` は下限に張り付くだけ）ので、罠のためだけに先取りすると、**死に方が人と獣で食い違います**。

## 7. 狩猟との非対称

| | 狩猟（`HuntingSystem.md`） | 罠（本書） |
|---|---|---|
| **危険** | 反撃を受ける。深手は数日残り、手当ての間も殴られる | 無い。掛かった相手は拘束されている（5 節） |
| **拘束** | tick が動物の手番なので、対峙している間は他のことができない | 仕掛けたら別の土地へ行ける。ただし回収に戻る（6 節） |
| **時間** | 15 分の一撃を重ねる。決着はその場 | 4 時間ごとに 1 回抽選。掛かるまで何度でも回る（2 節） |
| **前払い** | 武器（作る手間と、賭ける耐久） | 罠（サイズと生死で変わる、1.2 節）と餌（**食べられる食料**、4 節） |
| **獲物** | 大型まで。1 頭で数日分の肉 | 罠の型が並べた候補まで（1.1 節）。小型の罠なら 1 匹の肉は少ない |
| **運** | 当たり所と、負う怪我の抽選 | **いつ・何が掛かるかの抽選**（2.1 節・3 節） |
| **土地の効き方** | 遭遇するかどうか（探索・移動） | 成功率そのもの（3 節） |
| **生かして獲る** | できない（気絶させても運ぶ間に目覚める） | **生かす罠だけができる**（5.2 節）。飼いならしの唯一の入口 |

**罠は狩猟の下位互換ではなく、賭けるものが違います。** 狩猟が賭けるのは身体と武器で、罠が賭けるのは
時間と食料です。序盤は食料が出せないので罠が回らず、武器を作れば大型が獲れるようになるので罠は
上位に置き換わりません——**両方が同時に成り立つのは、片方が危険を、もう片方が時間を課しているから**です。

**大型ほど、この差が開きます。** 小型では、生かす罠に掛けても傷の 30〜60 mL が体格を超えるので
どちらにせよ死にます（5.1 節）。大型は同じ傷では死なないため、**檻を建てるか、穴に杭を打つか**という
別の仕事になり、しかも生かす側だけが飼いならしへ続きます。**罠の中の差が、獲物が大きくなるほど
狩猟との差より大きくなります。**

## 8. 未決事項・今後の検討課題

- **同じ土地に罠を何個も置いた場合。** 現状は個数に比例して収穫が増えます。掛かった瞬間に土地の
  `<動物>_catch` を `add` で減らす（獲り尽くすと居なくなる）形は書けますが、**回復の仕組み**を
  同時に決める必要があります
- **仕掛けるのに時間を課すか。** 今は地面へ置くだけで作動します（1 節）。枠の `put_in`（7.10 節）は
  土地の `items` 全体に効いてしまうので使えず、罠の側の `actions` で課すと「置いただけの罠」と
  「仕掛けた罠」を区別する状態が 1 つ増えます
- **渇きと飢えを人と獣へ配るか**（`VitalsSystem.md` 7 節）。配れば「閉じ込めた相手は水を得られない」を
  罠が `add: {child: {hydration: -1}}` で宣言でき、6.1 節の耐久より正直な罰になります。ただし
  **先に決めるのは「渇きが死へつながるか」**で、それは人と獣に同時に効く 1 回の決定です。動物が自分で
  減らす形は採れません——水を飲む仕組みが無いため、島中の動物が 3 日で死にます。飢え（`body_fat` は
  67 日）は罠の時間の桁から外れているので、この判断には関わりません
- **死体の腐敗**（`DurabilitySystem.md` 3 節）。今は罠の中の死体も傷まないので、殺す罠を放置した罰が
  「次が掛からない」（6 節）だけです
- **餌の量が効く形にするか。** 今は `gte: 1` の有無だけで、1 つ仕掛けても満杯でも同じです。段を刻めば
  量が効きますが、段の数だけ `modify` のブロックが要ります
- **草食・肉食の 2 つで足りるか。** 果実と穀物、魚と獣肉のように、餌をさらに分けたくなった場合、
  卓が増えるだけで形は変わりません。増やすほど「土地に合わせて餌を選ぶ」判断は細かくなりますが、
  合わない餌を焚く空振り（4.1 節）も増えます
- **仕掛けた罠が画面のどこにも出ないこと。** 5 節のとおり罠は何も告げないので、遠くの土地に置いた
  罠は、そこへ戻るまでプレイヤーの視界から完全に消えます。仕掛けた場所を忘れる負担が実際に重いなら、
  罠の作動ではなく**どこに何個仕掛けたか**を出す形（一覧・地図側）で埋めることになります
- **狩猟スキル**（[`SkillSystem.md`](./SkillSystem.md)）の効かせ方。`miss_weight` を押し下げる `modify` が
  素直ですが、スキルは罠ではなくプレイヤーが持つため、罠から見て `ancestor` に居ません
  （仕掛けた罠の祖先は土地です）
- **落とし穴の掘り方と、杭の打ち方。** 1.2 節は型と分岐だけを決めており、掘る `actions` の
  `duration`、掘削具の要求、杭を打つ `combinations` の材料は未定です。**落とし穴だけが土地に
  据え置かれる**（1 節）ので、仕掛け直せない罠の設計は他の型と別に要ります
- **筌**（魚・`Animals.md` 9 節）。本書の形をそのまま使えますが、水面の土地がまだ無く、掛かる相手が
  土地の別のつまみになります
- **罠が効かない動物の表し方**（`Animals.md` 10 節）。サルは学習し、シカは速い、という「その土地には
  居るのに罠には掛からない」を、土地が `<動物>_catch` を宣言しないことで表すのか、別の量で表すのか
- **用意する怪我の一覧と、その配分。** 罠ごとに 1 つ（5.1 節）と決めたので、型の数だけ怪我が要ります。
  重さ・痛み・出血の割り振りは `InjurySystem.md` 未決事項節と同じ問いです
- **同じ罠から複数の種類の怪我を出すか。** 「首に掛かったか、脚に掛かったか」は `pick` をもう 1 段
  入れれば書けます（食性 → 種 → 怪我の 3 段）が、候補が種の数だけ複製されます。今は 1 種類と
  生成時のロール（5.1 節）で、ばらつきは足りているはずです
- **怪我にできない削られ方が要るか。** 締めつけによる窒息のように、**手当てできず 1 つずつ数えられない**
  ものは怪我にしない、という線が既にあります（`InjurySystem.md` 4 節）。今の罠はすべて刺す傷で
  表せていますが、そこへ収まらない罠が出たら、罠の `passives` が `child` の `blood` を直接削る形に
  なります——`add` の対象に `child` は既にあるので、そのときも新しい文法は要りません
