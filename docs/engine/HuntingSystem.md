# 狩猟システム設計

## 概要

本ドキュメントは、動物を狩る（あるいは狩られる）局面の設計をまとめたものです。「どんな動物が島のどこに
どれだけ居るか」は [`TerrainGeneration.md`](./TerrainGeneration.md)・[`ExplorationSystem.md`](./ExplorationSystem.md)
の関心事、「その動物と出会ったプレイヤーが何をできるか」が本書の関心事です。

戦闘がゲームの主眼ではないため、**狩猟専用の数値を1つも作らない**ことを設計の芯にしています。敵の体力・
ダメージ・命中率といった専用の語彙を新設すると、[`GameConcept.md`](../concept/GameConcept.md) が全体の原則
として掲げる「派手な専用ロジックを足すのではなく、単純な加減算の積分が複雑な挙動を立ち上げる」に対して、
そこだけが例外になります。代わりに怪我・耐久・荷重・腐敗・探索・時間という既存の仕組みへ載せます。

**専用の画面もモーダルな状態も持ちません。** 動物は普通のカードとしてアイテムレーンに並び、攻撃は既存の
ドラッグ操作、逃走は既存の移動アクションです。同時に2頭以上と対峙できるのは、この設計がモーダルな状態を
1つも持たないことの帰結です。

本ドキュメントは検討結果であり、確定仕様書ではありません。1 節・3 節は実装済みです
（`public/world-codex/animals.yaml` のサルと `injuries.yaml`、検証は
`tests/worldCodex/animalsYaml.test.ts`）。6 節の変化の観測も実装済みです（`WorldSession.observeChanges`）。
**4 節・5 節は丸ごと未実装**で、見出しに【未実装】の印を付けています。動物側の手番（5.2 節）が無いため、
2 節が述べる「動物の 6 手」の帰結もまだ現れません。新設が必要なエンジン拡張は 7 節、未決事項は
8 節にまとめています。

## 1. 既存の操作に載せる

### 1.1 動物は `items` スロットのカード

動物は `item` タグを持ち、土地の `items` スロット（[`ExplorationSystem.md`](./ExplorationSystem.md) 1.1 節）に
並びます。`items`/`fixtures` の区別は「持ち運べるか」ではなく**動かせるか**なので、動物は前者です。持ち上げ
られるかどうかは 4 節の `resists` が別に決めます。

### 1.2 攻撃は `combinations`

武器として使える道具を動物のカードへ重ねる操作です。ヤシの実を割る・怪我に治療具を当てるのと同じ、既存の
中核動詞（[`GameElementDefinition.md`](./GameElementDefinition.md) 12 節）そのままで、新しい操作の語彙を
持ち込みません。

```yaml
wild_boar:
  combinations:
    strike:
      with: weapon
      duration: 15
```

**狙い所は武器の性格に畳みます。** 「急所／胴／脚」を選ばせる専用のUIは持たず、槍は急所寄り（当たりにくく
決まりやすい）、棍棒は脚寄り（当たるが倒せない）のように、武器ごとの `pick` の重み配分で表します。選択は
「どのカードを重ねるか」に宿るため、画面に何も足さずに判断が残ります。

道具の `durability`（[`DurabilitySystem.md`](./DurabilitySystem.md)）が減るので、**作るのに手間のかかった武器を
賭ける**という重みが自然に付きます。

### 1.3 逃走は `travel`

専用の逃走コマンドは持ちません。道を渡って隣の土地へ移る、既存の移動アクションがそれです。

置いていったアイテムはその土地に残るため、**取りに戻るにはまだ動物が居る土地へ戻ることになります**。逃走の
ペナルティを別に書く必要がありません（大型の動物ほど長く居座る、が被害の大きさになります）。

## 2. ターンは tick

専用の画面を持たないため、「今から動物の手番」と宣言する場所がありません。動物を動かすのは**時間の経過**
だけです。

- 15分の行動 = 1 tick = 動物の1手
- 90分の行動 = 6 tick = 動物の**6手**

これにより「動物に詰められながら悠長な作業はできない」が、ルールを1行も書かずに成立します。同じ理由で、
**無視することも自動的に罰せられる**ため、行動を禁じるモーダルな鍵が要りません。

不意打ちも同じ仕組みです。発見した tick で既に相手の手が入っていれば先手を取られたことになり、専用の
イニシアチブ判定を持ちません。

怪我の手当てにも同じ帰結が及びます。治療具を当てるのに30分かかる（[`Injuries.md`](../world/Injuries.md)）ため、
**荒ぶっている動物の傷を手当てすると2手ぶん殴られます**。「落ち着くまで待つ方が賢い」を、条件で禁じずに
コストとして表せます。

## 3. 動物は体力を持たず、怪我を負う

攻撃は体力を引くのではなく、動物の `injuries` スロットへ**怪我オブジェクトを1つ足します**。怪我は
[`Injuries.md`](../world/Injuries.md) が定義する構造をそのまま使い、キャラクタと動物で共通です。

この対称性から、次がいずれも追加の仕組みなしで得られます。

| | |
| --- | --- |
| 部位別の状態 | 「脚の裂傷」「脇腹の刺し傷」が別々のオブジェクトとして刺さる。部位ごとの体力表は要らない |
| 傷が行動に効く | 怪我の側の `passives`（`modify`）で、宿主の回避・逃走の重みを下げる |
| 倒れる・死ぬ | `severity` の合計、または急所の怪我が刺さったかで決まる |
| 手負いのまま逃げた後 | `severity` が `-1/tick` で治るので、**追跡に時限が生まれる** |
| 動物の傷を手当てできる | 怪我が持つ `treatment` スロットが働く。4 節の飼いならしの入口になる |

**画面も共通です。** カードの状態バーは既に傷の重さを映せ、`ObjectWindow` は1スロットをレーンとして見せる
作りなので、動物のカードを開けばキャラクタの怪我と同じ見え方で刺さっている傷が並びます。

### 3.1 警戒（`wariness`）

「攻撃してくるか逃げるか」を乱数の分岐にはせず、動物が持つ連続量にします。傷を負えば上がり、時間で下がり、
火や手当てで動きます。値はカードの状態バーとして見えるので、プレイヤーは「もう一撃で逃げに転じるはず」を
読んで賭けられます。

`wariness` は攻撃と逃走の重み配分（5 節）、持ち上げられるか（4 節）、手当てのリスク（2 節）のすべてを
駆動する唯一の量です。

**安全域を外れている間は、その動物のカードの輪郭が赤く明滅します**（[`CardView.md`](../ui/CardView.md) 3 節）。放置してよくない相手が居ることは、ステータスエリアではなく
その札の上で言う必要があります——動物はレーンに並ぶ 1 枚で、プレイヤーの持ち物ではありません。

**野生の個体は警戒した状態で現れます。** 放っておけば落ち着きますが、減り方は自然治癒と同じ基準レート
（`-1/tick`、[`Injuries.md`](../world/Injuries.md) 値の決め方 節）なので待つより追い払うほうが速い、が
値だけで成り立ちます。

## 4. 抵抗する相手（`resists`）【未実装: resists】

荒ぶっている動物を手持ちや入れ物へ入れることはできず、飼いならした後の小動物はかごへ、大型は台車へ
入れられるようにします。

これは**その物の性質**なので、枠ではなくオブジェクト側に宣言します。同じ `hand` の枠でも、入れようとして
いる物が石なら入り、荒ぶるイノシシなら入らないという違いは枠側では言えません
（[`GameElementDefinition.md`](./GameElementDefinition.md) 7.9 節が `bound_to_owner` について述べているのと
同じ理由）。

| | 意味 |
| --- | --- |
| `bound_to_owner: true` | 持ち主から**離れられない**（怪我・液体・道） |
| `resists: [条件]` | 条件が成立している間、**持ち主を持てない**（土地以外の親へ移れない） |

```yaml
wild_boar:
  tags: [item]
  resists: [{prop: wariness, gte: 1}]
```

- 手持ち・かご・台車の定義は変更しません。既存の `accept: {tag: item}` のまま、抵抗する側が拒みます
- 土地の `items` には普通に置けます（親が土地だから）
- **自分で隣の土地へ逃げるのは通ります**（土地から土地への移動なので）
- 警戒が0になれば成立しなくなり、そのまま台車・かごへ入ります。**飼いならしで型を差し替える必要がありません**

型の差し替え（`wild_boar` → `tamed_boar`）は採りません。`spawn` は値も中身も引き継がない
（[`GameElementDefinition.md`](./GameElementDefinition.md) 9.4 節）ため、差し替えると刺さっている怪我と警戒が
消えます。定義を1つに保ち `wariness` だけで駆動すれば、**飼いならした動物が再び荒ぶる**も同じ仕組みで表せます。

### 4.1 入れ物の中で成立したら、こぼれ出る

台車に積んだ動物の警戒が上がった場合、`resists` が成立した瞬間に最も近い土地へこぼれ出ます。`destroy` が
中身を親へこぼす（同 9.3 節）のと同じ扱いで、**暴れて荷車から飛び出す**という見え方になります。

捕まえる手間は枠が持ちます（`put_in: {duration: ...}`、同 7.10 節）。`combinations` に書くと、レーンへ直接
落とす経路だけが無料になります。

## 5. 気まぐれな対象は、実行時に書き込むプロパティで指す【未実装: flee_to】

動物は、その場のアイテムに体当たりして壊し、逃げるときは行き先を気まぐれに選びます。どちらも「定義時点では
決まらず、実行時に初めて確定する個体」を指す必要があります。

これは道の移動先とまったく同じ問題で、既に作法が確立しています——**コードがインスタンスのプロパティへ
書き込み、YAML はそれを読む**（[`ExplorationSystem.md`](./ExplorationSystem.md) 3 節。`path` の
`destination_id` は `IslandSpawner` が `setProperty` で書き込み、`object_defs` の初期値はプレースホルダ）。

### 5.1 動物の1手

```yaml
wild_boar:
  props:
    # いずれも実行時に上書きされるプレースホルダ（5.2節）。
    flee_to: {value: 0}
    escape_routes: {value: 0}
    smash_target: {value: 0}
    smashables: {value: 0}
  actions:
    turn:
      pick:
        # 攻撃は必ずリテラルの重みで、かつ先頭に置く（5.3節）。
        - weight: 10
          spawn: {object: gore_wound, into: actor}
        - weight: {prop: smashables}
          destroy: {prop: smash_target}
        - weight: {prop: escape_routes}
          move: {object: self, to_prop: flee_to}
```

`spawn` の `into: actor` が成立するのは、動物の1手を実行する側（5.2 節）が同居しているキャラクタを `actor`
として渡すからです。`passives` からは兄弟（同じ土地に居るキャラクタ）へ届かないため、この経路が必要です。

### 5.2 1手を与える側が書き込むもの

tick の後処理として、土地に居る動物へ1手ずつ与えます。[`ExplorationSystem.md`](./ExplorationSystem.md) 5 節の
`Location.explore` が `revealDueFixtures` を内側で呼んでいるのと同じ、入口を1箇所に閉じる形にします。

| プロパティ | 内容 |
| --- | --- |
| `flee_to` | 逃げ込む土地のインスタンスID（発見済みの道から1本選ぶ） |
| `escape_routes` | 発見済みの道の本数 |
| `smash_target` | ぶつかる相手のインスタンスID |
| `smashables` | ぶつかれる物の数 |

**重みと対象は必ず同時に書きます。** `smashables` が0なら `smash_target` は絶対に読まれない、という不変条件を
1箇所に閉じるためです（2箇所が暗黙に一致すべき規約を分散させない）。

値は毎ターン上書きされるので、意味は常に「直前のターンで用意した候補」で確定し、古い値が残り続けません。
**0へ戻す後始末は不要**です（`pick` と `set` を併記できない制限——[issue #415](https://github.com/gooyyu1/UnmappedIsland/issues/415)——を
踏まないためにも、後始末を各候補へ複製する形は採りません）。万一消えた個体を指していても、解決に失敗した
効果は何も起こしません（`GameElementDefinition.md` 9.6 節の `to_prop` と同じ規約）。

### 5.3 追い詰められた動物は逃げずに襲う

`PickEffect` は重みを0でクランプするため、**逃げ道が無い土地（`escape_routes` = 0）では逃走候補が抽選から
外れます**。専用の条件を書かずに「追い詰められた獣は反撃する」が成立し、おまけに「開けた土地ほど逃げやすい」
（道が多い＝重みが大きい）も付いてきます。壊せる物が無い土地で暴れる候補が外れるのも同じ仕組みです。

**ただし全候補の重みが0になると先頭候補が選ばれます。** 攻撃はリテラルの重みを持ち、かつ先頭に置くことを
規約にします。逃走を先頭に置くと、逃げ道の無い土地で何も起きない手番になります。

### 5.4 何にぶつかるか

「暴れまわって、たまたまぶつかった物が壊れた」を表します。選ぶのはコード側なので、次の2点を規約にします。

- **かさ（`volume`）で重み付けする。** 大きい物にぶつかりやすい＝地面に大きな物を広げていると危ない、という
  読める判断になります
- **壊れうる物だけを候補にする。** `durability` を持つ物すべてにすると大事な道具まで一撃で消えるため、
  タグで著者が明示的に選びます

`destroy` は中身を親へこぼす（`GameElementDefinition.md` 9.3 節）ので、**壊された編み籠の中身は地面に散らばります**。追加のルールは
要りません。

## 6. 追うのは分岐ではなく、世界に起きた変化

イノシシのカードが標的のカードまで動いて壊し、戻ってくる——という演出には、「誰が何をしたか」がUIへ
伝わる必要があります。

**追うのは `pick` が発火した分岐ではなく、世界に起きた変化です**（`WorldSession.observeChanges`、
[`ActionSystem.md`](./ActionSystem.md) 7 節）。動物の1手の中で起きた物の出入りには、主体としてその動物が
付くので、UIは次のように読めます。

| 動物がしたこと | 観測される変化 |
| --- | --- |
| 壊した | ヤシの実が、土地のアイテムスロットから世界の外へ |
| 持ち去った | ヤシの実が、土地のアイテムスロットから隣の土地へ |
| 逃げた | 動物自身が、今の土地から隣の土地へ |
| 攻撃した | 怪我が、どこでもない所からプレイヤーの怪我スロットへ |

**UIの語彙はエンジンの動詞（`spawn`/`move`/`destroy`）になり、動物の分岐名にはなりません。** 動物を増やしても
`pick` の候補を足しても、観測する側は1行も変わりません。分岐を観測する形では、候補を足すたびにUIが追随します。

**プロパティは効果の入力であって、UIへの通知路ではありません。** 分岐ごとに偽のカウンタ（`smash_count` の類）を
持たせる必要も、後始末で0へ戻す必要もありません（5.2 節）。

### 6.1 どう見えるかは、控えたスナップショットが持つ

変化のログが答えるのは「何が起きたか」だけで、「どう見えるか」は別です。`PlayScene` は tick 境界ごとの表示内容を
`RecordedView` として控え、実時間をかけて再生しているので、**ログはその控えと並べて運びます。** 両方が要ります
——ログだけでは絵にならず、絵だけでは誰の仕業か分かりません。

- 90分の行動が1コマに潰れません（tick ごとに控えて再生しているため、突進した tick が独立したコマになる）
- 被害者のカードの矩形が取れます。再生中の画面にはその tick より前の控えが出ているため、`PlayScene.rectOf` が
  まだ被害者の枠を返します。「到達してから消す」順序が追加の仕掛けなしに成立します

カードの同定はインスタンスID（`CardContent.identity`）で行い、突進は `CardMotion` が扱う「レーンの並びから
外れて宙に在る札」の3つ目のケースになります（飛んでいる分身・離した場所へ置いたままの分身に続く）。

### 6.2 既存の演出も同じ観測に寄せた

カードの移動アニメーションは、**新しく現れた札の出どころを個体ごとに変化のログから引きます**
（`MotionContext.origins`・`motionOrigins`）。ログが「この個体はこの札から来た」と言うので、UIは主体の札の
矩形を引くだけです。同じ tick に出どころの違う物が生まれても、それぞれの出どころから飛べます。

出どころは主体で、主体を持たない変化は移動前の親になります。これで画面に出ていないスロット（未発見の設置物、
閉じた入れ物の中）から出てきた物が、その持ち主の札から飛びます。

| 現れたもの | 出どころ |
| --- | --- |
| `combinations` の成果物 | 重ねた相手（効果を宣言している側が主体） |
| アクションで採ったもの | そのカード（ヤシの木から採った実は木から手元へ） |
| 探索で見つけたもの | 現在地（`explore` の主体。設置物は移動前の親としても同じ土地を指す） |
| tick の中で生まれたもの | それを起こしたオブジェクト |

**呼び出し側が渡すのは画面の事実だけになりました。** 指を離した位置（`MotionContext.released`）と、
一覧から作り始めた製作中オブジェクトの出どころ（閉じた一覧の中で選んだ札の位置）の2つです。どちらも世界の
どこにも無い位置なので、世界の側は答えを持ちません。

ログを控えと並べて運ぶ必要があるのはここでもです（6.1 節）。矩形へ直すのは**再生する時点**——出どころの札の
位置は、そのtickの画面（1つ前の控え）にしかありません。

## 7. 新設が必要なエンジン拡張

狩猟専用の文法は導入しません。次の4つはいずれも汎用の拡張です。

| 拡張 | 内容 |
| --- | --- |
| `resists`（4 節） | `bound_to_owner` の対称形。条件が成立する間、土地以外の親へ移れない。成立した瞬間に土地へこぼれ出る |
| `move` の `object: self` | 現在は `actor`/`dragged` のみでロード時エラー（`GameElementDefinition.md` 9.6 節）。`child` と違い `self` は一意なので曖昧さが無い |
| `destroy: {prop: ...}` | プロパティの実効値をインスタンスIDとして解釈する。`move` の `to_prop` の解決器をそのまま使う |

加えて、tick の後処理として動物へ1手与える箇所（5.2 節）が実装の中心になります。変化の観測（6 節）は
狩猟に限らない汎用の仕組みなので、[`ActionSystem.md`](./ActionSystem.md) 7 節が持ちます。

**「その場から1つ選ぶ」汎用語彙（`choose` の類）は、今は導入しません。** 用途が逃走先と体当たりの2つしか
ない状態で形を決めると、守れているか確かめられない約束になります。導入するなら**選択は1回だけ行って名前を
付ける**形が必須です——逃走は「選んだ道の `destination_id`」と「選んだ道の `travel_minutes`」の2箇所が同じ
個体を指す必要があり、参照ごとに振り直す形では移動時間と行き先が食い違います。

## 8. 未決事項・今後の検討課題

- **怪我の内容**: 部位別の怪我をいくつ用意するか。それぞれが動物の回避・逃走・攻撃へ効かせる量
- **`wariness` の増減レート**: 傷でどれだけ上がり、時間でどれだけ下がるか。火・手当て・子連れ・囲い込みの
  効き方。カードの状態バーへどう出すか（バーの本数は既に6種ある）
- **飼いならしの完了条件**と、飼った動物の扱い（`resists` が外れた後の居場所、餌、逃走）
- **動物の種類と体重**: 攻撃・体当たり・逃走の重み配分。死体の重さと運搬（`load` の `too_heavy` で移動が
  止まるため、倒した後の運搬が本題になる）。解体・腐敗との接続
- **くくり罠**（[`Skills.md`](../world/Skills.md) の繊維・編み）との役割分担。安全だが遅い罠と、速いが
  遅発性の怪我を賭ける直接戦闘の非対称
- **武器ごとの重み配分**（1.2 節）: 当たり外れの重みは、武器が 1 種類しかない間はリテラルで書いてある。
  `pick` の重みは `{object: dragged, prop: ...}` で武器のプロパティから引けるので、槍と棍棒が並んだ時点で
  そちらへ移す。1 種類のために武器の能力値を作ると、守れているか確かめられない約束になる
- **回避されたときの見え方**: 何も起きなかったように見えないための、カード側の一時的な演出
- **壊れうる物を示すタグ**の名前と、どのアイテムに付けるか（5.4 節）
- **突進の演出を、観測した変化から組み立てる**（6 節）。カードの出どころを個体ごとに引く形へUI側を寄せると、
  探索・クラフトの出どころも呼び出し側が渡さなくなる（6.2 節）
