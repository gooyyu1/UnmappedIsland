# 消化システム設計

## 概要

**食べた物が蓄えになるまでの経路**を決めるドキュメントです。口に入れた物は胃に入り、腸へ送られ、
そこで初めて体脂肪になります。段を刻む場所と輸送の速さ、そしてその速さをどう見積もったかを扱います。

境界は 3 つ。**尽きたときに死ぬこと**は [`VitalsSystem.md`](./VitalsSystem.md) 8 節（飢えは 3 つの
死に方の 1 つ）、**プロパティの契約と個体差の置き場所**は [`Characters.md`](../world/Characters.md)、
**ステータスの見せ方**は [`StatusArea.md`](../ui/StatusArea.md) が持ちます。栄養バランスの 3 本
（`vegetable_nutrition` ほか）は本書の対象外です（6 節）。

**新設する文法はありません。** 導入する語彙は次の 2 つのプロパティと、既存プロパティの読み替え 1 つ
だけで、残りは既存の仕組み——`stages`（段ごとの寄与と速さ）・`modify`（可逆な寄与）・`transfer`
（tick 毎の輸送、[`GameElementDefinition.md`](./GameElementDefinition.md) 8.4.1節）——にそのまま載ります。

| 語彙 | 何を表すか |
| --- | --- |
| `stomach`（胃の中身） | 食べた物が最初に入る所。**これ以上食べられない**を決める（1 節） |
| `intestine`（腸の中身） | 吸収されつつある分。**食べたのに身にならない**が奪える量（1 節） |
| `satiety`（空腹感） | 胃と腸が押し上げる**実効値**へ読み替える（2 節） |
| 段 `full` | 胃が満杯。`eat` がこの名前で「もう食べられない」を見る（1 節） |

定義の置き場所は `public/world-codex/characters/`（胃はキャラクタごと、腸と空腹感は
`player_character` trait）と、食べ物側の `eat`（`foods.yaml` ほか）。空腹感が trait へ移ると
ステータスエリアの並びは `pain`/`blood`/`satiety`/… になり、
[`Characters.md`](../world/Characters.md) が定めた順とそのまま一致します。

**本ドキュメントは検討結果であり、全節が未実装です。** 土台となる `passives` の `transfer`
（検証は `tests/domain/passiveTransfer.test.ts`）と、蓄えが尽きたときの餓死
（[`VitalsSystem.md`](./VitalsSystem.md) 8 節）だけが実装済みで、本書が導入する 2 つのプロパティと
4 節の段はまだどのファイルにもありません。既にある `body_fat` の段は 2 つだけで、基礎代謝は
体格によらず 1/tick 固定です。未決事項は末尾に整理しています。

## 1. 器官を増やしてよいのは、それが無いと書けない症状があるとき

**胃と腸を別のプロパティにします。** 増やす基準は [`VitalsSystem.md`](./VitalsSystem.md) 8.2 節の
「死に方を増やしてよいのは、終わり方と対策の両方が独自のとき」と同じ形で、**その器官が無いと書けない
症状があるかどうか**だけで決めます。

| 器官 | それが無いと書けないもの |
| --- | --- |
| `stomach`（胃） | **吐く**（身になる前に失う）・**これ以上食べられない**（一度に詰め込めない） |
| `intestine`（腸） | **下痢**（食べたのに身にならない）・食後しばらく空腹が戻らないこと |

胃だけでは下痢が「水分が減る」以上のことを言えません——食べた物が身にならないという、下痢の中心が
落ちるためです（[`GameConcept.md`](../concept/GameConcept.md) が挙げる連鎖の一部）。腸だけでは、
吐いても既に身になった後になり、一度に食べ溜められない理由も無くなります。

**3 つ目は作りません。** 肝臓も膵臓も、上の基準を満たす症状を今は持ち込みません。

### 1.1 現実は FIFO だが、よく混ざった槽として表す

現実の消化管は**先に入った物から順に出ていく**（FIFO）管ですが、ここでは中身を 1 つの数として持つ
**よく混ざった槽**として表します。食べた物ごとの区別は残らず、腸に届く順序も保証されません。

それでも成り立つのは、この模型が答えるべき問いが「**いつ・どれだけ身になるか**」だけだからです。
個々の食材を追跡できないことで失われるのは「先に食べた物だけが吐き出される」といった細部で、
どれも症状としては書いていません。管を模すには中身を列として持つことになり、
[`GameConcept.md`](../concept/GameConcept.md) の「加減算の積分であらゆる現象を駆動する」から外れます。

## 2. 空腹感は、胃と腸が押し上げる実効値

**`satiety` は自分では動きません。** 実体値（食べると増え、tick で減る値）をやめ、`pain` や
`consciousness` と同じ**実効値**——胃と腸の段が `modify` で押し上げる合流点——にします。

決め手は、**胃が空になった瞬間に空腹が最大になるわけではない**ことです。実際の空腹感は胃の伸展だけで
なく血糖にも従い、胃が空でも吸収が続いている間は保たれます。実体値のままだと、この 2 つの入力を
1 本の値へ書き戻す手順を誰かが持つことになります。

| | 実体値（削られて残る） | 実効値（自分では動かない） |
| --- | --- | --- |
| 既存 | `blood`・`severity` | `pain`・`consciousness`・`load` |
| 本書 | `stomach`・`intestine`・`body_fat` | **`satiety`** |

- **胃の寄与は伸展**、**腸の寄与は血糖の代理**です。両方が尽きて初めて 0 になり、そこから先は
  `body_fat` が削られていきます（4 節）。
- **血糖そのものは持ちません。** 腸の段が代理できるためです。持つべきなのは「蜂蜜を舐めて即座に
  立て直す」「低血糖で気を失う」——腸を経由せず効く経路——を書きたくなったときで、そのときは
  独自の対策と独自の終わり方が揃います（1 節の基準）。
- **押し上げは階段になります**（`modify` の量がリテラルのため）。これは
  [`VitalsSystem.md`](./VitalsSystem.md) 2 節の「効き方は連続ではなく階段でよい」と同じ割り切りです。

**「これ以上食べられない」は胃が持ちます。** `stomach` の `range.max` が胃の大きさで、`min: max` の段
**`full`** を置き、`eat` を `not: {object: actor, prop: stomach, in_stage: full}` で塞ぎます。水分の
`full` と `not_thirsty` の完全な対称形です（[`LiquidContainerSystem.md`](./LiquidContainerSystem.md) 5節）。

## 3. 輸送量は、実際の消化時間から見積もる

**単位は 1 = 15 分ぶんの生命維持**です（[`GameElementDefinition.md`](./GameElementDefinition.md)
6.0 節の「時間を数えるもの」）。基礎消費が 1/tick なので、1 日を保つには 96 単位が要ります。
**食べ物側の数値は書き換えません**——今 `satiety` へ足している値（タロイモ 20、ヤシガニ 16）が、
そのまま `stomach` へ入る量になります。

### 3.1 胃は、溜まっているほど速く出す

**排出速度を段で刻み、中身が多い段ほど速くします。** 現実の胃排出は残量におよそ比例する（多いほど
速く出る）ので、段の階段はその近似です。副産物として**絞りすぎて溜まり続けることが起きません**
——溜まれば自動的に速くなるためです。

```yaml
stomach:
  tags: [nutrition]
  value: 12                       # 漂着直後。最後の食事から数時間
  range: {min: 0, max: 32}        # maxが胃の大きさ。8時間ぶんを一度に詰め込める
  stages:
    - {name: empty}                                  # 空。輸送も寄与も持たない
    - name: trace
      min: 1
      passives:
        - modify: {self: {satiety: 10}}
        - transfer: {from_prop: stomach, to_prop: intestine, amount: 1}
    - name: light
      min: 4
      passives:
        - modify: {self: {satiety: 25}}
        - transfer: {from_prop: stomach, to_prop: intestine, amount: 2}
    - name: filled
      min: 12
      passives:
        - modify: {self: {satiety: 45}}
        - transfer: {from_prop: stomach, to_prop: intestine, amount: 3}
    - name: full
      min: 24
      passives:
        - modify: {self: {satiety: 60}}
        - transfer: {from_prop: stomach, to_prop: intestine, amount: 4}
```

この階段が出す排出時間は次のとおりで、**現実の胃排出（軽食 1〜2 時間、多めの食事 3〜4 時間）**に
収まります。

| 食べた量 | 何時間ぶんか | 胃が空になるまで |
| --- | --- | --- |
| 4（空心菜1束） | 1 時間 | 45 分 |
| 8 | 2 時間 | 1 時間 15 分 |
| 16（ヤシガニ1匹） | 4 時間 | 2 時間 |
| 20（タロイモ1個） | 5 時間 | 2 時間 30 分 |
| 32（満杯） | 8 時間 | 3 時間 15 分 |

最下段（`empty`）が輸送を持たないのは、**そこに残る物が無い**からです（食べ物が足す量も輸送の量も
整数なので、胃の中身は整数のまま動きます）。

### 3.2 腸は、蓄えへ抜ける速さそのもの

腸の通過は現実で 3〜5 時間です。胃より遅くします——**上流を速くした差が、そのまま腸の在庫になる**
（[`GameElementDefinition.md`](./GameElementDefinition.md) 8.4.1節）ためで、この在庫が「食後しばらく
空腹が戻らない」と「下痢で失える量」の両方を持ちます。

```yaml
intestine:
  tags: [nutrition]
  value: 16                       # 漂着直後。吸収の途中から始まる
  range: {min: 0, max: 64}
  stages:
    - name: fasting                                  # 尽きかけ。空腹感への寄与は無い
      passives:
        - transfer: {from_prop: intestine, to_prop: body_fat, amount: 0.5}
    - name: trickle
      min: 2
      passives:
        - modify: {self: {satiety: 10}}
        - transfer: {from_prop: intestine, to_prop: body_fat, amount: 0.5}
    - name: absorbing
      min: 8
      passives:
        - modify: {self: {satiety: 20}}
        - transfer: {from_prop: intestine, to_prop: body_fat, amount: 1}
    - name: loaded
      min: 16
      passives:
        - modify: {self: {satiety: 30}}
        - transfer: {from_prop: intestine, to_prop: body_fat, amount: 1}
    - name: heavy
      min: 32
      passives:
        - modify: {self: {satiety: 40}}
        - transfer: {from_prop: intestine, to_prop: body_fat, amount: 2}
```

**`to_amount` は書きません（等倍）。** 吸収率は「下げる側だけを持つ」ようにします——健康なら食べた分が
そのまま身になり、食料の数値がそのまま 1 日の予算として読めます。下がるのは下痢・感染のときだけです
（5 節）。

### 3.3 1 日を通すとこうなる

上の 2 つと 4 節の基礎代謝で、7:00・12:00・18:00 に満杯（32）まで食べる 1 日を回すと次のようになります。

| 時刻 | 胃 | 腸 | 空腹感 |
| --- | --- | --- | --- |
| 6:00 | 0 | 0 | 0 |
| 7:00（食事） | 28 | 3.5 | 70 |
| 9:00 | 5 | 19 | 55 |
| 11:00 | 0 | 16 | 30 |
| 12:00（食事） | 28 | 16 | 90 |
| 14:00 | 5 | 30 | 55 |
| 17:00 | 0 | 22 | 30 |
| 18:00（食事） | 28 | 22 | 90 |
| 21:00 | 0 | 30 | 30 |

- **食後 3 時間ほどが満腹**で、そこから胃が空いて空腹が戻ります。腸には 20〜30 が居続けるので、
  空腹感が 0 まで落ちるのは 1 食抜いたときだけです。
- 1 日 96 単位を食べれば体脂肪は横ばい（3 食で摂れる上限がちょうど 96 = 32 × 3）。**胃の大きさが
  1 日に食べられる量の上限**を決めるので、食い溜めで数日ぶんを先に確保することはできません。

**空腹感の段は、この分布から刻みます。**

```yaml
satiety:
  tags: [status, nutrition]
  value: 0                        # 自分では動かない。胃と腸が押し上げる
  range: {min: 0, max: 100}
  stages:
    - {name: starving, alert: danger}
    - {name: hungry, min: 15, alert: caution}
    - {name: peckish, min: 30, alert: watch}
    - {name: fed, min: 65}
```

[`Characters.md`](../world/Characters.md) の「安全域を外れるのは `max` の 80%」は**当てはめません**。
あの規約は `max` が容量（満タンで始まる値）である前提のもので、`satiety` の `max` は容量ではなく
**感じ方の頂点**——胃も腸も満ちた瞬間にしか届かない値——だからです。容量の側の規約は `stomach` の
`full` が引き受けています。開始時（胃 12・腸 16）の空腹感は 75 で、既存の「やや空いた状態から始める」
（同 域の区分節）と揃います。

## 4. 基礎代謝は体格に比例させる

**`body_fat` の減る速さを、`body_fat` 自身の段で変えます。** 太っているほど基礎代謝が大きいという
事実がそのまま、**食べ過ぎても際限なく太らない**平衡点になります
（[`DesignNotes.md`](./DesignNotes.md) tick毎のaddの平衡点節）。

```yaml
body_fat:
  tags: [nutrition]
  value: 1440                     # 標準体格。maxの1/4
  range: {min: 0, max: 5760}      # 最大限に肥えた状態から絶食で60日
  on_shortfall:
    destroy: self                 # 尽きれば餓死（VitalsSystem.md 8節）
  stages:
    - name: starved               # 残り1日を割った域。ここが餓死の死因の名前
      alert: fatal
      passives:
        - add: {self: {body_fat: -0.5}}
    - name: gaunt
      min: 96
      passives:
        - add: {self: {body_fat: -0.7}}
    - name: nourished
      min: 480
      passives:
        - add: {self: {body_fat: -1}}
    - name: stout
      min: 2880
      passives:
        - add: {self: {body_fat: -1.3}}
    - name: obese
      min: 4320
      passives:
        - add: {self: {body_fat: -1.6}}
```

摂取量ごとの落ち着き先は次のとおりです（60 日回した結果）。

| 1 日の摂取 | 落ち着く体脂肪 | 意味 |
| --- | --- | --- |
| 156（5 食、胃の上限いっぱい） | 3,986 | 太るが、際限なくは太らない |
| 120（5 食） | 2,858 | 蓄えが厚くなる |
| **96（3 食、満杯）** | **1,421** | **横ばい。これが標準** |
| 72（3 食、腹七分） | 480 | 痩せた状態で止まる |
| 48（3 食、半分） | 96 | 餓死の一歩手前で止まり続ける |
| 0（絶食） | — | **17.7 日で餓死** |

- **飢えても即座には死にません。** 痩せるほど基礎代謝が落ちるので、半分しか食べられない日が続いても
  「痩せた状態で釣り合う」に落ち、そこから先の悪化は緩やかです。
- 絶食 17.7 日は、`Characters.md` が定めた「初期値 = 最大の 1/4」から出る値（一定 1/tick なら 15 日）を、
  代謝の低下が伸ばしたものです。

**個体差はここと胃の大きさに出ます。** 今キャラクタごとに違う「満腹度の `max`」（96/120/84/96）は、
そのまま **1 日の必要量**の差なので、`body_fat` の段ごとの速さへ移します（農夫は全段 1.25 倍で
1 日 120 単位）。胃の大きさ（`stomach.range.max`）もそれに比例させ、**3 食で 1 日ぶんが入る**関係を
全キャラクタで保ちます。空腹感と腸は個体差を持たず `player_character` trait が配ります
（痛みや血液量と同じ理由）。

## 5. 吐くと下痢は、同じ配管の別々の場所を叩く

どちらも新しい値を必要とせず、既にある 2 つの在庫のどちらを捨てるかだけが違います。

| | 何をするか | 失うもの |
| --- | --- | --- |
| 吐く | `set: {actor: {stomach: 0}}` | まだ腸へ届いていない分**だけ**。届いた分は残る |
| 下痢 | 腸から `body_fat` へ渡さず捨て、`hydration` も余計に削る | 食べた物が身にならない＋脱水 |

下痢は「腸の中身を、蓄えへ寄与しない形で減らす」ので、`transfer` ではなく `add` で書きます
（行き先が無いため）。同じブロックで `hydration` を削れば、
[`VitalsSystem.md`](./VitalsSystem.md) 8.1 節が言う「対症療法で買えるのは時間だけ」——水を飲めば脱水は
凌げるが、食べた物が身にならないほうは止まらない——がそのまま立ち上がります。

## 6. 栄養バランスの 3 本は、当面この配管に載せない

`vegetable_nutrition`・`meat_nutrition`・`grain_tuber_nutrition` は、今までどおり `eat` が直接足し、
tick で減る実体値のままにします。**腸を 3 つに割ることになる**ためです（カテゴリごとに別々の在庫と
吸収を持たせない限り、混ざった腸から「野菜だけが吸収される」は書けません）。

エネルギー（本書の配管）とバランス（3 本）は別の軸で、**片方だけでも成立します**——満たされていても
偏っていれば別の不調が出る、という関係になります。3 本を配管へ載せるかは、偏りが何を起こすかを
決めるときに判断します。

## 未決事項・今後の検討課題

- **`eat` が満杯を越える分を捨てる。** 胃が 30 のときにタロイモ（20）を食べると、`range.max` の
  クランプで 18 が消えます。`transfer` の `allow_overflow: false` で「入る分だけ食べる」に直せますが、
  食べかけのオブジェクトを作ることになるため、食料側の数値の持ち方と一緒に決める
- 空腹感が行動へ与える影響。今は画面に出るだけで、空腹でも同じように動ける
  （`stamina` との関係を決めていない）
- **胃の中身に質を持たせるか。** 今は 1 つの数なので、消化の速い物・遅い物（液体と脂）の違いが
  書けない。書くなら胃を 2 本（速い分・遅い分）に割ることになり、1 節の基準を満たすかは
  「腹持ちの違い」がゲームとして効くかで決まる
- 睡眠中の消化。今の模型は起きている間と同じ速さで進む
- 3.1 節・3.2 節の配分そのもの。**食料の入手量が決まって初めて釣り合いが見える**ので、狩り・採集の
  収量が固まってから見直す
