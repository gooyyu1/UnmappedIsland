# 消化システム設計

## 概要

**食べた物が蓄えになるまでの経路**を決めるドキュメントです。口に入れた物は、かさとして腹を満たし、
栄養として体に残り、そこから体脂肪になります。何をどの物差しで数えるか、どの速さで動くかを扱います。

境界は 3 つ。**尽きたときに死ぬこと**は [`VitalsSystem.md`](./VitalsSystem.md) 8 節（飢えは 3 つの
死に方の 1 つ）、**プロパティの契約と個体差の置き場所**は [`Characters.md`](../world/Characters.md)、
**ステータスの見せ方**は [`StatusArea.md`](../ui/StatusArea.md) が持ちます。

**新設する文法はありません。** 使うのは既存の仕組み——`stages`（段ごとの寄与）・`transfer`
（tick 毎の輸送、[`GameElementDefinition.md`](./GameElementDefinition.md) 8.4.1節）——だけです。

## 1. 物差しを 3 つに分ける

**この模型の要は、何をどの単位で数えるかです。** 以前は 1 本の値が「かさ」と「エネルギー」を
兼ねていて、腹が満ちる量をカロリーで数えていました。かさばるが軽い葉物と、小さいが重い脂は
同じ数直線に乗らないため、どちらかが必ず狂います。

| 物差し | プロパティ | 1 単位の意味 |
| --- | --- | --- |
| **かさ（mL）** | `satiety`（満腹感） | 胃に入っている物の体積 |
| **エネルギー（tick）** | `carbohydrate`・`protein`・`lipid`・`body_fat` | 15 分ぶんの生命維持（1 日 = 96） |
| **微量栄養（mg）** | `vitamin` | ビタミン C 相当の体内量 |

**食べ物は「かさ」と「中身」を別々に名乗ります。** ほとんどの食べ物では近い値になりますが、
別の数なので次が書けます。

- 水気の多い物（青い実の水）は**かさだけ大きい**
- 生肉は**かさの割に身にならない**（焼くと縮むが、身になる量は増える）
- ヤシの果肉は**小さいのに大きな力になる**（脂質）

## 2. 満腹感は、胃に入っているかさ

`satiety` は実体値です。食べたかさぶん増え、tick で減ります。`max` が胃の容量（1,500mL）で、
減りは一定（−16/tick）。**1 日 1,536mL ＝ 3 食 × 512mL** が、ちょうど食べる量と釣り合います。

**「これ以上食べられない」もここが持ちます。** 段 `full` を置き、`eat` を
`not: {subject: actor, prop: satiety, in_stage: full}` で塞ぎます。水分の `full` と `not_thirsty` の
対称形です（[`LiquidContainerSystem.md`](./LiquidContainerSystem.md) 5節）。

| 段 | 下限 | 域 |
| --- | --- | --- |
| `starving` | 0 | 危険 |
| `hungry` | 50 | 要注意 |
| `peckish` | 200 | 留意 |
| `fed` | 400 | 安全（1 食で届く） |
| `full` | 900 | 安全。**ここから上は食べられない** |

**`full` を `max` ではなく 6 割に置くのは、あふれた分を捨てずに済ませるためです。** 食料は個体の
カードなので、入る分だけ食べて残すことはできません（[`GameElementDefinition.md`](./GameElementDefinition.md)
9.2 節。一部だけ使えるのは中身入りの容器だけ）。最大の食料は 550mL（焼いた
タロイモ）なので、`full` の直前（899）で食べても 1,449 で収まり、**1 mL も捨てません**。

段は `max` の 80% で安全域を外れる規約（[`Characters.md`](../world/Characters.md)）に従いません。
`max` は容量であって「これだけ満ちていてほしい」量ではないためです。1 食（512mL）で `fed` に届き、
そこから 8 時間かけて `starving` へ落ちます。

## 3. エネルギーは、栄養素ごとに 3 本

**体内に残っているエネルギーを、糖質・たんぱく質・脂質の 3 本で持ちます。** 在庫がある間は
`transfer` で `body_fat` へ流れ続け、尽きれば `body_fat` が削られていきます（4 節）。

3 本に分けているのは、**吸収の速さ**と**欠乏したときに起きること**が違うからです。器官（胃・腸）で
分けるのをやめたのは、器官には物差しが 1 つしか無く、栄養素の違いを表せないためです。

| | 速さ | 主な食材 | 尽きると（未実装） |
| --- | --- | --- | --- |
| `carbohydrate`（糖質） | 2/tick | イモ・穀物・果実 | **固有の弊害は無い** |
| `protein`（たんぱく質） | 1/tick | 肉・魚・甲殻類 | 筋が落ちる・傷が治らない |
| `lipid`（脂質） | 0.5/tick | ヤシの果肉・脂の乗った肉 | 必須脂肪酸欠乏。加えて 4 節の毒性 |

**糖質に固有の欠乏症が無いのは、炭水化物が必須栄養素ではないためです。** 体は糖新生でブドウ糖を
作れるので、肉と脂だけでも生きられます。糖質を残しているのは弊害のためではなく、**栽培で安定して
大量に得られる**という入手経路の違いと、吸収が速いことのためです。

`max` は 3 本とも 120（1.25 日ぶん）。**食べ溜めはできません**——満杯の在庫へ足した分は捨てられます。

## 4. ビタミンは、エネルギーとは別の物差し

`vitamin` は mg（ビタミン C 相当）で持ちます。**エネルギーの在庫にはしません**——葉物はエネルギーを
ほとんど持たないので、エネルギーとして数えると常に 0 に張り付き、「食べていない」と区別が付かなく
なるためです。

ヒトのプールは飽和で約 1,500mg、300mg を割ると壊血病が出ます。代謝回転は 1 日およそ 48mg なので、
`max` 1,500・−0.5/tick。空心菜 1 束（83mg）で 1.7 日ぶんです。

**尽きた先はまだ書いていません。** 壊血病（古傷が開き歯が抜ける）は既にある怪我の仕組みへ繋がるので、
書くときは「0 が続いた時間」を数える不可視のプロパティを足すことになります。同じ形で、たんぱく質の
欠乏（筋が落ちる）・脂質の欠乏・**たんぱく質過多**（脂質が 0 のまま肉だけを食べ続けると、肝臓が
処理し切れず数週間で死ぬ。いわゆるウサギ飢餓）も書けます。

## 5. 体脂肪は、3 本から届いた分が積み上がる

`body_fat` の単位はエネルギーと同じ tick です。3 本からの `transfer` で増え、段ごとの基礎代謝で
減ります（太っているほど速い＝食べ過ぎても際限なく太らない平衡点）。

**糖質だけで暮らすと、ちょうど釣り合います**——糖質は 2/tick 流れますが、在庫が半分の時間しか
続かないため、1 日 96 単位（1,536mL のイモ）が基礎代謝 1/tick と釣り合う勘定です。3 本とも在庫が
あるときは合計 3.5/tick で流れるので、食べた直後は身になるのが速く、尽きれば止まります。
**流れる総量は速さによらず変わらない**（`transfer` は保存する）ので、速さは timing だけを決めます。

## 6. 吐く・下痢【未実装: 吐き下し】

| 症状 | どう書くか | 何が起きるか |
| --- | --- | --- |
| 吐く | `satiety` を 0 にし、3 本を割合で減らす | 腹が空になり、少し前に食べた分まで失う |
| 下痢 | 3 本を `body_fat` へ渡さずに減らし、`hydration` も余計に削る | 食べた物が身にならない＋脱水 |

下痢は「行き先が無いまま減らす」ので、`transfer` ではなく `add` で書きます。吸収率を下げたい場合は、
`transfer` の `to_amount` を `amount` より小さくしても同じことが表せます。

- 睡眠中の消化。今の模型は起きている間と同じ速さで進む
- 3 本の速さと食べ物の値。**食料の入手量が決まって初めて釣り合いが見える**ので、狩り・採集の収量が
  固まってから見直す
