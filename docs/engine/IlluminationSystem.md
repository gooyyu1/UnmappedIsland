# 明るさシステム設計

## 概要

**守備範囲**: 明るさをどう持ち、行動の可否をどう決めるか。単位（EV）・3つの値（空・手元・見回す）・
各項（時刻・天気・樹冠・地面の反射・光源）がどのオブジェクトのどのプロパティに載るか・行動ごとの要求を
どこに書くかを決めます。

**境界**: 天気そのものの駆動は [`ClimateSystem.md`](./ClimateSystem.md)、土地と道は
[`ExplorationSystem.md`](./ExplorationSystem.md)、火の維持と燃料は [`FireSystem.md`](./FireSystem.md)。
**どの値をいくつにするか**（照度とEVの換算・しきい値・土地ごとの樹冠と反射・その結果1日に何時間
行動できるか）は [`ContentSkeleton.md`](../world/ContentSkeleton.md) 8.1節〜8.1.3節が持ち、本書は
繰り返しません。風雨で出歩けないことは明るさでは表さないので（同 8.1節）、それを何の値で表すかも
本書の外です。

**実現方法**: 3つの値はいずれも普通の数値プロパティで、`props` の `value`（土地ごとの定数）・`inherit`
（[`GameElementDefinition.md`](./GameElementDefinition.md) 6.5節）・`modify`（同 8.3節）・`conditions`
（同 14節）だけで組み立てます。計算式を持ち込む `derived`（同 17節）は使いません。ただし**今の文法には
足りないものが2つあり**——寄与の合成を「大きいほうを採る」にできること（5節）と、値を自分の別の
プロパティから継げること（6節）——それを足すまでは書けません。

**在処**: 定義は `src/assets/world-codex/core.yaml`（world）・`locations.yaml`（土地）と各光源の型。
実装・検証はまだありません。

**確定度と実装状況**: **本書の設計はすべて未実装**で、記述は暫定です（`【確定】` の節はありません）。
5節・6節の文法追加を採るかは
[issue #656](https://github.com/gooyyu1/UnmappedIsland/issues/656) で確認待ちです。`core.yaml` の
`sunlight` からの移し替え（9節）と、`GameElementDefinition.md` への文法の追記は別タスクです。

## 1. 明るさはEV（照度の2を底とする対数）で持つ

**明るさを表すプロパティはすべてEV（`EV = log2(照度 / 2.5 lx)`）で、単位はプロパティ名の `_ev` が
名乗ります。** 1段が2倍にあたるので、樹冠が通す割合も天気の透過率も地面の反射率も、**掛け算ではなく
足し算の項**になります。エンジンが持っているのは加算（`modify`・`inherit`）だけなので、この形でなければ
9桁に渡る照度を扱えません。値の由来と換算表は `ContentSkeleton.md` 8.1.1節にあります。

EVは連続量なので小数を書けます（`GameElementDefinition.md` 6節）が、いまの項はすべて整数です。

## 2. 値は3つあり、木の上から下へ流れる

**空・手元・見回すの3つを別々のプロパティとして持ち、下の値は上の値を継いで作ります。** 1つの値へ
全部を寄せると、遮る項（樹冠）と足す項（反射）と光源の「大きいほうを採る」が混ざって計算の順序が結果を
変えます（`ContentSkeleton.md` 8.1.2.1節）。

| 値 | プロパティ | 載るオブジェクト | 中身 |
| --- | --- | --- | --- |
| 空の明るさ | `sky_ev` | world・土地 | 時刻・満月・天気（world）に、その土地の樹冠を足したもの |
| 手元の明るさ | `hand_ev` | 土地・キャラクタ | 空の明るさと、そこに在る／持っている光源のうち大きいほう |
| 見回す明るさ | `looking_ev` | キャラクタ | 手元の明るさに、その土地の地面の反射を足したもの |

オブジェクトの木は world → 土地 → キャラクタ → 持ち物です（`core.yaml` の `location` trait の
`characters` 枠）。値はこの木を下りながら育ちます。

- **上から継ぐ**（`inherit`、`GameElementDefinition.md` 6.5節）: 土地の `sky_ev` は world の `sky_ev` を、
  キャラクタの `hand_ev` は土地の `hand_ev` を継ぎます。自分の `value` はその場の差分（樹冠・0）です。
- **横から継ぐ**（6節、まだ書けない）: 土地の `hand_ev` は自分の `sky_ev` を、キャラクタの `looking_ev` は
  自分の `hand_ev` を継ぎます。**同じ土地の中で、光源より前に樹冠が効き、反射より先に光源が効く**という
  順序は、この継ぐ向きだけで決まります。評価順序という概念は要りません。

土地は `looking_ev` を持ちません。見回すのはキャラクタだけで、しかも持っている光源を勘定に入れた後の値
だからです。

## 3. 各項は、それを持っている物が書く

**時刻と天気は world、樹冠と反射は土地、明るさは光源自身が書きます。** どの項も、その項の持ち主が
`value` か `modify` を1箇所書くだけで、受け取る側は何も知りません。

| 項 | 書く場所 | 書き方 |
| --- | --- | --- |
| 時刻 | world の `hour` の `stages` | `modify` で `sky_ev` へ（正午 +16 など） |
| 天気 | world の `weather` の `stages` | `modify` で `sky_ev` へ（曇り −5 など） |
| 樹冠 | 土地の `sky_ev` | `value`（森 −4・密林 −7） |
| 地面の反射 | 土地の `passives` | `modify` で `child` の `looking_ev` へ（砂浜 +1・密林 −2） |
| 光源 | 光源自身の `passives` | `modify` で `parent` の `hand_ev` へ（松明 +4・焚き火 +6） |

```yaml
# core.yaml — 世界（開けた土地の水平面の明るさ）
world:
  props:
    sky_ev:
      value: 0        # hourのstagesが時刻を、weatherのstagesが天気をmodifyする（どちらも加算）

# locations.yaml — 密林
location_jungle:
  props:
    sky_ev: {value: -7, inherit: true}           # 樹冠。worldのsky_evへ自分の分を足して継ぐ
    hand_ev:
      value: 0
      inherit: {subject: self, prop: sky_ev}     # 横から継ぐ（6節）
      modify_combine: max                        # 光源は大きいほうを採る（5節）
  passives:
    - modify: {child: {looking_ev: -2}}          # 地面の反射。見回す側にだけ効く

# キャラクタ
character:
  props:
    hand_ev: {value: 0, inherit: true, modify_combine: max}
    looking_ev: {value: 0, inherit: {subject: self, prop: hand_ev}}

# 松明（火の状態の持ち方はFireSystem.md）
torch:
  passives:
    - conditions: [{prop: lit, eq: 1}]
      modify: {parent: {hand_ev: 4}}
```

**光源が「携行か固定か」を区別する必要はありません。** どの光源も同じ1行（`parent` の `hand_ev` へ
`modify`）を書くだけで、置かれた場所によって届く先が変わります——地面や炉に据えれば親は土地、手に持てば
親はキャラクタです。**親がその値を持っていなければ届かない**ので、袋の中へしまった光が土地を照らすことも
ありません（袋は `hand_ev` を持たないため、`modify` は黙って無視されます）。

**夜の空は満月の値ひとつです。** 月齢を入れない（`ContentSkeleton.md` 8.1.1節）ので、夜の段が与えるのは
満月の −3 で、星明かりの −10 は月齢を入れたときに要る値です。**今の `hour` の4段
（`core.yaml` の night/morning/day/evening）では太陽高度の刻みが粗すぎる**ので、段の切り直しが要ります
（9節）。

## 4. 行動ごとの要求は、操作の `conditions` に1行書く

**行動は3つのクラスに分かれ、それぞれが見る値としきい値が決まっています。** 満たさなければその行動は
できません——遅くなるのではなく、線を引きます（[`DesignPrinciples.md`](../concept/DesignPrinciples.md) の
「悪条件は、効率を下げるのではなく、できる／できないの線で効かせる」節）。

| 行動のクラス | 見る値 | しきい値 | 書く場所 |
| --- | --- | --: | --- |
| 土地の間を移動する | `looking_ev` | −5 | `path` の `travel`（`ExplorationSystem.md` 3節） |
| 屋外で採る・探索する | `looking_ev` | +3 | 土地の `explore` と、各採取の操作 |
| 手元の細かい作業 | `hand_ev` | +5 | 製作を進める操作（[`RecipeSystem.md`](./RecipeSystem.md)） |

```yaml
path:
  interactions:
    travel:
      conditions:
        - {in_slot: fixtures}
        - reason: too_dark
          subject: actor
          prop: looking_ev
          gte: -5
```

- **主語は `actor` です。** 3つの値のうち行動が見るのはキャラクタ側の2つで、キャラクタは操作を実行して
  いる本人だからです（`GameElementDefinition.md` 14.1節）。
- **`reason` を添えます**（同 14.6節）。暗くてできないことは、ボタンが押せないだけでは伝わりません。
- **明るさの条件を書かない操作は、暗さに依らずできる**という意味になります（食べる・飲む・眠る・火を
  くべる）。書き忘れと見分けが付かないので、見張り方を未決事項に挙げています。

**移動できるかは、出発する土地の明るさで決めます。** 道は自分の明るさを持ちません——道の型が持って
いるのは行き先の識別子だけで（`ExplorationSystem.md` 3節）、条件から行き先の土地のプロパティは辿れない
ためです。`ContentSkeleton.md` 8.1.2節が未決としていた「道がどちらの明るさを採るか」への、本書側の答えが
これです。

## 5. 足りない文法(1): 寄与の合成に「大きいほうを採る」が要る

**同じプロパティへの複数の `modify` を、加算ではなく大きいほうを採る形で合成できる必要があります。**
今は単純加算だけです（`GameElementDefinition.md` 8.3節）。合成方法を選ぶのはプロパティ自身なので、
書く場所は各 `modify` ではなくプロパティの宣言です（3節の `modify_combine: max`。名前は仮のものです）。
実効値は「実体値＋`inherit`」と各 `modify` を候補にして、いちばん大きいものになります。

**条件の側の選言では消えません。** 「空か光源かのどちらかがしきい値以上」と書けば空と光源の1回は
消せますが、**光源同士が残ります**。焚き火（150 lx・+6）のそばで松明（30 lx・+4）を持つと、実際は
180 lx（+6.3）で、大きいほうを採れば +6（誤差0.3段）、加算にすると **+10＝約2,600 lx**——曇りの正午の
半分の明るさになります。しかも選言にすると値が3つでは足りなくなり（空由来と光源由来で別々に反射を
足した4つが要る）、「見回す＝手元＋反射」という1本の関係が2本に割れます。

**明るさだけの話ではありません。** 加算でよいのは実体が線形に足される量（気温・重さ・負荷）で、
**対数で持つ量は加算では合成できません**。空の明るさ自体も太陽・月・星という3つの光源の「大きいほう」で、
今は満月固定なので夜の段の値ひとつで足りているだけです。月齢を入れれば、そこでも同じ合成が要ります。

**大きいほうを採るのは近似です。** 実際の光は線形に足されるのでEVでは和が表せません。誤差は2つが
ちょうど等しいときの1段（2倍）が最大で、昼は太陽が夜は焚き火が他を圧倒するため、ほとんどの場面で
ほぼゼロです（`ContentSkeleton.md` 8.1.2.1節）。

## 6. 足りない文法(2): 値は、自分の別のプロパティからも継げる必要がある

**`inherit` の継ぎ元を明示できる必要があります**——既定は今と同じ「祖先の同名プロパティ」、
明示すれば「自分の別のプロパティ」も指せる形です（3節の `inherit: {subject: self, prop: sky_ev}`。
`inherit: true` はその省略形として残ります）。同じオブジェクトの中で、1つの値からもう1つの値を
「定数を足しただけの別の値」として作れないと、2節の3つの値が繋がりません。

土地と world の間だけなら今の `inherit` で足ります。詰まるのは、**1つの世界の値から、土地ごとに違う
2つの組み合わせ（樹冠だけ／樹冠と反射の両方）を作る**ところです。継ぎ元が「祖先の同名」に固定されて
いる限り、2つ目の組み合わせには2本目の継承の道が要ります。

却下した案は2つです。

- **世界の側に2系統持たせる**（world が `sky_ev` と `looking_ev` を両方持ち、土地が別々に継ぐ）。時刻と
  天気の寄与が全部2箇所に書かれ、**暗黙に一致すべき数が11個増えます**。
- **見回す明るさを持たず、行動ごとの「必要な明るさ」を土地が持つ**（しきい値 − 反射を土地のプロパティに
  し、条件を `{prop: hand_ev, gte: {subject: ancestor, prop: ...}}` と書く）。**今の文法だけで書けます**が、
  反射が土地ごとに行動クラスの数だけ複製され、見回す行動を1つ増やすたびに全土地へ1行増えます。加えて
  「砂浜では移動に要る明るさが低い」という、現実には無い意味の値になります——明るいのは地面であって、
  必要な明るさが変わるわけではありません。

循環（`a` が `b` を継ぎ、`b` が `a` を継ぐ）は同じオブジェクトの中で閉じるので、ロード時に検出できます。

## 7. 空を継がない場所は、光源だけで決まる

**洞窟は `sky_ev` に `inherit` を書きません。** 樹冠を −∞ にするのではなく、空から光が来ないことを
「継がない」で表します。値は仮に −20 とします——移動のしきい値（−5）より十分低ければ、そこから先の
差はどの行動にも現れません。

これで**洞窟は昼でも真っ暗**になり、探索には必ず光源が要ります。地面の反射は基準の地面と同じ 0 を
仮置きします。屋根を持つ建物を作ったときも同じ形になります。

## 8. 段（`stages`）は空の明るさにだけ置く

**段を持つのは `sky_ev` だけで、行動の可否は段では判定しません。** 段は「今どのくらい明るいか」を
他の値や画面へ渡すための粗い区分（`pitch_dark`・`moonlight`・`overcast`・`daylight`・`full_sun`、
境目は `ContentSkeleton.md` 8.1.1節）で、行動の可否は4節のしきい値との比較で決まります。

境目をしきい値に合わせてあるのは、**プレイヤーの目に見える変化と、できることの変化が同じ瞬間に
起きるため**です。段の側を細かくしても、できることは変わりません。

## 9. `sunlight` を読んでいる3箇所は、移し替えが要る

**今の `sunlight`（抽象値0〜20）を消すと、それを読んでいる3箇所が同時に動きます。** どれも本書の
担当外なので、ここでは移し先だけを挙げます（実際の書き換えは別タスク）。

| 今の読み手 | 移し先 |
| --- | --- |
| 気温への寄与（`core.yaml` の `sunlight` の `stages`） | `sky_ev` の段（8節） |
| 空の色（`src/game/looks/skyTint.ts`） | `sky_ev`。夜が0へクランプされる前提も併せて要見直し |
| 水の蒸発（`liquid_containers.yaml`、[`LiquidContainerSystem.md`](./LiquidContainerSystem.md)） | `sky_ev`。日射なので、光源ではなく空の側を見る |

時刻の段（3節）も、太陽高度に合わせて切り直す必要があります。

## 未決事項・今後の検討課題

- **明るさの条件の書き忘れをどう見張るか。** 書かなければ「暗くてもできる」になり、書き忘れと区別が
  付きません（4節）。操作の一覧を出して、明るさの条件を持たないものを並べる検査が要ります。
- **風雨で行動が止まることを、どの値で表すか**（`ContentSkeleton.md` 8.1節）。明るさとは別の値です。
- **月齢を入れるか。** 入れると夜の空が「月と星の大きいほう」になり、5節の合成が空の側でも要ります。
- **暗くて何もできない時間の見せ方。** 押せないボタンと `reason` だけで足りるか、日が暮れる前に
  気付ける形が要るかは、[`Windows.md`](../ui/Windows.md) 側の話として未検討です。
- **移動の途中で暗くなる扱い。** いまは出発時の1回しか見ません（4節）。長い道を歩いている間に日が
  暮れる場合をどうするかは決めていません。
