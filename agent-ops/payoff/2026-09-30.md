## どこが費やしているか

**割（1オブジェクトあたりPR）は落ちていない。名指しできるのは、止まったことが誰にも届かない経路のほう。**

- **決めてある届け先は、どちらも動いていた。** 値の見回りは停止の翌日に
  [#2434](https://github.com/gooyyu1/UnmappedIsland/issues/2434) を立て、**直し方（「このPCで
  Claude Code を起動し直して、トークンを貼り直させる」）まで本文に書いていた**。常設の盤
  [#1714](https://github.com/gooyyu1/UnmappedIsland/issues/1714) も `PUBLISH_INTERVAL`（300秒）ごとに
  書き換わり続け、本文は引けていないことを告げていた（書き出しに失敗したのは9日間で1周だけ）。
- **それでも9日14時間読まれなかった。** #2434 は今も開いていて、コメントは0。issue もPRも同じ
  アカウントで立つので GitHub の通知は鳴らず（`agent-ops/board-design.md` 2.20）、**題名は止まっても
  変わらない**ので、一覧を開いても目に入らない。
- **`board-design.md` 2.3.1 の前提が破れている。** あそこは「アクセストークンは数時間で切れるが、
  貼り直すのは Claude Code 本体なので、放っておけば直る」と書いている。**貼り直す本体が起動して
  いなければ直らない**——今回はそれが9日続いた。
- **2.3.3【確定】「落ちたことを検知して知らせる仕組みは置かない」の根拠も、この形には効かない。**
  置かない理由は「走っているセッションが増えないことで、盤面の側から見える」ことだが、**盤面そのものを
  引けない状態では、盤面の側から見る手が無い。**

**供給の側も枠を割っているが、今回は名指ししない。** 配れる `goal:game` は1件で `ACTIVE_WORKERS` を
下回り、掘り起こす係の出力は `判断待ち` のまま止まっている（前の回の手4番目が効いて係は立ったが、
供給は増えていない）。ただし**測定区間の87%が停止だったので、配分の問題が割にどう効いたかは、この
区間からは読めない。** 次の回が、回り続けた区間で見る。
