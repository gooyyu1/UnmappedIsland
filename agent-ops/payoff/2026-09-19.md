## 測った値

### 測り方

**`npm run stats:payoff` も、それが呼ぶはずのスクリプトも存在しない。** git と `gh` から手で測った。
次の回が同じ値を出せるように、数え方を残す。

- **オブジェクト定義** … 世界の定義を YAML として読み、`object_defs` 配下の鍵を数えた合計。
  **置き場は 2026-08-16 に `public/` の下から `src/assets/world-codex/` へ移っている**ので、
  それより前を数えるときは両方を見る（移る前も同じ `world-codex` の名前）。
- **週の値** … **その週に `main` へ入った最後のコミットの時点**で数えた数。増分は前の週の同じ点との差。
- **週の区切り** … コミットが `main` へ入った時刻（committer date）の月曜始まり。**作業ツリーで書いた
  時刻（author date）で割ると、別の週へ落ちるコミットが出る。**
- **PR** … 件名が `(#<番号>)` で終わるコミット（squash merge の跡）。終わらないものは `main` への
  直接 push。**この2つで `main` の全コミットを分けている**ので、和は `git rev-list --count HEAD`
  と並ぶ（測った時点で 3185）。
- **どちらも触らず** … そのPRが `src/` を1ファイルも触っていないこと。世界の定義は `src/` の下に
  在るので、この1つで両方を見たことになる。
- **在庫** … `gh issue list --state open --limit 600 --json number,title,labels,blockedBy`。
  **配れる数は `board-move.mjs` の `readyTasks` と同じ条件で絞る**——`kind:task` ∧ `判断待ち` 無し ∧
  `blockedBy` に開いているものが無い ∧ 開いているPRが `Closes` していない ∧
  **`task-<番号>` タグを持つセッションが抱えていない**（`~/.claude/board-state/live-sessions.tsv`）。
  **後ろの2つを落とすと、既に手が動いている issue を「配れる」と数える。**

## 前の回との差

**比べる先が無い。** `agent-ops/payoff/` はこの回が最初で、`npm run stats:payoff` も無い。

**1オブジェクトあたりPRについては、週ごとの推移で見るかぎり割は落ちていない**（16.1 → 21.9 →

**組成だけは、同じ条件で比べられる数が1つ残っている。** `agent-ops/board-design.md` 2.18.1 が
2026-09-11 時点の実測を持つ——**配れる `kind:task` 46件のうち、完成の定義へ向かうものは7件**（15%）。
今日は配れる81件のうち0件。**在庫は1.8倍になり、そのうちゲームの仕事は尽きている。**

## どこが費やしているか

**ゲームの仕事の供給。** 配れる `goal:game` が0で、作業者の枠（3）を埋めるものが無い。

掘り起こす係（`dig`）の `due`（配れる `goal:game` が0）は**今まさに真**だが、**間隔（`hours: 24`）で
立てない**——前に立ったのが 2026-09-18T16:26Z なので、あと8.9時間は立たない。その間、枠は整備の
81件から埋まる。

**捌く側は両方とも動いている**（ゲーム87%・整備49%）。足りないのは生まれる速さのほうで、
**ゲームの仕事は1日6.7件、作業者が出すPRは1日15〜28本。** 差は整備で埋まり、週ごとの
「どちらも触らず 40〜53%」として出ている。
