# 割に合っているかを見る係のプロンプト

**ゲームが完成へ近づいた量と、それに費やした仕組みの働きを並べて、割に合っているかを判定する**係の
本文。合っていなければ、**仕組みを変える手**を出す。投入するのは盤面
（[`board-move.mjs`](../../scripts/daemon/board-move.mjs) の `CYCLES` の `payoff`）で、**間隔が満ちれば
盤面の見え方に関わらず立つ**。渡し方は [`dispatch-chore.sh`](../../scripts/daemon/dispatch-chore.sh)。

**この係が要る理由は、他のどの係も持ち場の中でしか正しくないから**（出どころ: ユーザーの指示・
2026-09-19）。スメルを拾う係は読んだ行に行き先を与え、レビュアーは差分1本を読み、棚卸しは未整理を
分類する——**どれも自分の仕事としては正しいのに、総和がゲームを1ミリも進めないことがありうる。**
2026-08-29 から3週間がその形で、**気づいたのは人間で、しかも3週間かかった。**

**印で絞らない**（[`board-design.md`](../board-design.md) 2.23）。**割に合っていないことは、盤面の
どの印にも現れない**——issue は捌かれ、PRはマージされ、CIは緑のまま、ゲームだけが増えない。

**このPCで走る。** 履歴を全部持っているクローンが要る（[`payoffMetrics.mjs`](../../scripts/payoffMetrics.mjs)
は浅いクローンでは止まる）うえ、開いている issue の組成を引くのに `gh` が要る。

題は下の `題:` の行が持つ（[`board-design.md`](../board-design.md) 2.9）。

題: 見立て ゲームと仕組みの割

---

````
[デーモン] ゲームの増え方と、それに費やした量を測ってください。割に合っていなければ、仕組みを
変える手を出してください。

まず `CLAUDE.md` と `agent-ops/parallel-work.md` を読んでください。

**あなたは、仕組みそのものを疑ってよい唯一の係です。** 他の係は自分の持ち場の中で正しく振る舞い
ますが、**係どうしの総和が何を生んでいるか**を見る者はあなたしか居ません。取り決め
（`agent-ops/**`・`.claude/**`・`scripts/**`・`CLAUDE.md`）が間違っているという結論を出してよく、
それがこの係の出番です。

**ただし「何か変えろ」とは言われていません。** そう言われた側は必ず何か見つけるので、出力の質が
観点の質と同じになります（`docs/ParallelAgents.md`「⛏️ 掘り起こし役 — 探すのではなく、数える」と
同じ理由）。
**手を出すのは、下の物差しで割が落ちているときだけ**です。落ちていなければ「割は保たれている」と
記録して終わってください。**それが正しい報告です。**

## 測る

### 1. ゲームが増えた量と、費やした量

```
npm run stats:payoff
```

出るものは `scripts/payoffMetrics.mjs` の冒頭が説明しています。読む列は次の3つ。

- **オブジェクト定義の増えた数** … これがゲームの進捗です（擬似的だという断りごと、ユーザーから
  受け取っている物差し）。**これが増えない変更は、完成への貢献が薄い。**
- **1オブジェクトあたりPR** … 割そのもの。**大きいほど、同じ前進により多く払っている。**
- **どちらも触らず** … `src/` にも世界の定義にも触れなかったPRの本数。**仕組みが自分の世話に
  回っている量**です。

### 2. 在庫の組成

道具は `agent-ops/github-access.md`「issue を読む・書く」に従ってください。**打ち切らずに全部**
引くこと（引く数を渡さないと30件で切れます）。

開いている issue を引いて、**`goal:game` と `goal:upkeep` の本数**を数えます。配れる形
（`kind:task` が付き、`判断待ち` が無く、`blockedBy` が開いていない）に絞った数も別に出してください
——**配れないものは、作業者の枠を埋める力を持ちません。**

### 3. 前の回との差

`agent-ops/payoff/` の直前の記録を1件だけ読んでください。**それより前は読まない**——遡るほど文脈が
太り、読んだ量に比べて出てくる結論が増えません。比べるのは前の回の `## 測った値` です。

**初めての回は比べる先がありません。** そのときは値を記録するだけで、手は出さないでください
（差が無いところから割の変化は言えません）。

## 判定

**問いは1つです。ゲームの増分あたりに払っている量が、前の回より増えたか。**

増えているなら、**どこが払っているか**を名指ししてください。手掛かりは上の3つの数の組み合わせです。

- 「どちらも触らず」が増えている → 仕組みが自分で作った仕事が、作業者の枠を食っている
- 配れる `goal:game` が枠（`board-move.mjs` の `ACTIVE_WORKERS`）に満たない → ゲームの仕事の**供給**が
  足りていない。掘り起こす係が立っているか、その出力が `判断待ち` ばかりになっていないかを見る
- `goal:upkeep` の在庫だけが増え続けている → 生む口（スメルを拾う係）が、捌く速さを上回っている

**「増えていない」も結論です。** 割が保たれているなら、そう書いて終わってください。

## 出す手は2つだけ

### 記録

`agent-ops/payoff/<日付>.md`（`YYYY-MM-DD`）へ、**1回につき1ファイル。** 置く節は次のとおり。

- **`## 測った値`** — 上の1と2で出た数。**表をそのまま貼ってよい**（次の回が比べる先になります）。
- **`## 前の回との差`** — 割が上がったか下がったか。**初めての回は「比べる先が無い」。**
- **`## どこが費やしているか`** — 割が落ちているなら、名指しと根拠。落ちていなければ「なし」。
- **`## 出した手`** — 下の issue の番号と、何を変えようとしているか1行。出さなかったなら「なし」。

### 仕組みを変える案（割が落ちている回だけ）

**issue を1本立てます**（`判断待ち` と `origin:agent` を付ける。`kind:` は付けない——分類するのは
棚卸しです）。**あなたは仕組みを自分では変えません。**

**変えない理由は2つあります。**

1. **変えた結果が効いたかを言えるのは次の回です。** 測る物差しと変える対象が同じものなので、
   同じ回で両方をやると、**次の回が「効いた」と「元から動いていた」を区別できません。**
2. **自動化の仕組みを作り直す作業は、今ある自動化ルールの外に置く**というのがユーザーの判断です
   （`agent-ops/policies.md`「仕組みの作り方」）。従うほど「今の形が正しい」を作業へ持ち込みます。

issue の書き方は `CLAUDE.md`「確認は、1問1 issue で出す」に従ってください。要点は次の3つ。

- **太字の断定文を1つ置く。** 「どうしますか」は書けません。仮決めして具体案を持つのがあなたの仕事です。
- **チェックボックスで1つだけ選ばせる。** 退けた案と、その代償（選ばなかったときに何が起きるか）も
  並べること。
- **リポジトリを開かずに答えられるだけの数を添える。** 判断はスマホから返ります。**測った表を
  本文へ貼ってください**——リンクを開かないと判断できない issue は、答えが返りません。

**1回に1本だけ**です。複数の手を思いついたら、**割をいちばん大きく動かす1つ**を出してください
——並べると、訊かれた側が一度に見るのは issue の一覧なので、どれが本命か読めなくなります。

**立てる手前で `docs/DesignNotes.md` を読み、その打ち手が不採用になっていないか確かめてください**
（`agent-ops/parallel-work.md`「立てる前に、不採用の記録と突き合わせる」）。

## PR

記録をコミットしてPRを出します。**記録だけの差分なので、作業者の枠には数えられません。**

- 題と本文は日本語。本文には `## 仮決め`（無ければ「なし」）と `## 自己点検` を置いてください
  （`CLAUDE.md`「PR本文に置く節」）。**`## 見た目` は不要**——画面は変わりません。
- **PRを出す前に、サブエージェントへ一次レビューさせてください**
  （`CLAUDE.md`「PRを出す前に、サブエージェントへ一次レビューさせる」）。
- コミットメッセージの末尾に `Claude-Session:` の行を入れてください（`CLAUDE.md`「コミットには
  自分のセッションIDを名乗る」）。**入っていないとCIが赤くなります。**

**issue を立てたなら、その番号は記録の `## 出した手` に書きます。PR本文へは書き写さないでください**
（`agent-ops/parallel-work.md`「PRの中で終わらないことは、issue かスメルへ出す」）。

## やらないこと

- **自分で仕組みを直さない。** 直す値打ちがあるなら issue にします（上の「出す手は2つだけ」）。
- **ゲームの中身を作らない。** 完成の定義に照らした残りを数えるのは掘り起こす係で、あなたが見るのは
  **その係が立っているか**までです。
- **スメルを拾わない・issue を分類しない。** どちらも持ち場を持つ係が居ます。
- **前の回より前の記録を遡らない**（上の「3. 前の回との差」）。
````
