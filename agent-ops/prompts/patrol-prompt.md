# 盤面を見回る係のプロンプト

**デーモンは生きている。その盤面が健全かを、毎回確かめる係**の本文。投入するのは盤面
（[`board-move.mjs`](../../scripts/daemon/board-move.mjs) の `CYCLES` の `patrol`）で、**間隔が満ちれば
盤面の見え方に関わらず立つ**。渡し方は [`dispatch-chore.sh`](../../scripts/daemon/dispatch-chore.sh)。

**印で絞らないのは、印に掛からない壊れ方を拾うため**（[`board-design.md`](../board-design.md) 2.21.2節）。
**大半の回は「異常なし」で終わる。** それでよい——**走ったことが残らないと、異常が無かったのか
係が立たなかったのかを誰も区別できない。**

**このPCで走る。** 何が転んだかが残っているのは `~/daemon.log` と `~/.claude/board-state` で、
どちらもクラウドの箱には無い。

**デーモンが落ちているときは立たない。** 落ちた跡から起こすのは起こす係（2.19）で、**この係を
立てるのはデーモン自身**——立っていること自体が「デーモンは生きている」の証拠になっている。
二重に手を出す形にならないのは、この背反による。

題は下の `題:` の行が持つ（[`board-design.md`](../board-design.md) 2.9節）。

題: 点検 盤面の見回り

---

````
[デーモン] 盤面を見回ってください。健全なら「異常なし」を記録して終わりです。

まず `CLAUDE.md` と `agent-ops/board-design.md` を読んでください。

**あなたが立っているということは、デーモンは生きています。** 落ちていれば、あなたを立てる者が
居ません。だから「デーモンが**今**止まっていないか」は調べる必要がありません。

**ただし、それが言えるのは「今」だけです。** 落ちたデーモンを立て直す役は盤面の外に居る（毎時の
起こし直し）ので、**あなたが時刻どおりに立っていても、その手前の区間はずっと止まっていた**ことが
ありえます。自分の間隔で測るかぎり、その区間は埋まって見えます——下の「盤面は、間隔ごとに1周して
いる」で別に測ってください。

**あなたは詰まりが起きたから立ったのではありません。** この係は間隔ごとに必ず立ちます
（`agent-ops/board-design.md` 2.21.2節）。**盤面が健全であることを確かめるのが仕事**で、壊れていない
ことを確かめて終わる回のほうが多いはずです。

## 正常の定義

健全に回っている盤面では、次が成り立っています。**あなたの仕事は、毎回「どれが成り立って
いないか・なぜか・自分で直せるか」を答えること**です。

- **この係自身が、間隔どおりに立っている。** 測るのは**立った時刻どうし**——台帳の `cycle:patrol` と、
  `~/daemon.log` の `打つ: CHORE patrol` の行です。**記録の `at` の差で測らないこと**——あれは
  書き終わりの時刻なので、**その回の所要時間がそのまま差に乗り**、立ちがきっちり間隔どおりの周でも
  差は前後に振れます（所要は数十秒のこともあれば数十分のこともある）。**下の「短い側」が拾うのは
  盤面の詰まりなので、所要時間の揺れで振れる物差しに掛けると、健全な周を異常だと読みます。**
  立った時刻との間が間隔より大きく空いていたら、**その
  空白はこの係が立たなかった時間**——投入するのは盤面なので、**盤面を引けない間はこの係も立たない**
  （資格情報が切れている周がこれ。2.22.2）。**空白の間に起きたことは、誰も見ていない**ので、
  そこで壊れたものは無いとは言えない。空白の区間の `~/daemon.log` を端から読むまで、この回の
  「異常なし」は空白の手前までしか掛からない。**間隔より短いのも、同じだけ異常**——刻を進めるのは
  投入が「打てた」ことなので、**前の回の投入が転んだ周は刻が止まったまま間隔が満ち、次の周でもう1本
  立つ**。**短い側は「立ちすぎた」のではなく「盤面が刻を進め損ねた」**ので、前の回の `打てなかった:`
  と台帳の `cycle:patrol` を引くまで、その周に何が起きたかは言えない
- **盤面は、間隔ごとに1周している。** 測るのはこの係の間隔ではなく**周の間隔**で、物差しは
  `~/daemon.log` の**時刻を持つ行どうしの空き**（下の「調べる先」に引き方がある）。**この係が時刻
  どおりに立っていることは、その手前ずっと回っていた証拠にはなりません**——立て直す役が盤面の外に
  居るので、落ちていた区間も時刻の上では埋まる。**空白の直後に並ぶ手は、空白の手前で打たれるはず
  だった手**なので、手が打たれていることも進んでいた証拠にならない。空白が在れば、上の「この係自身
  が…」と同じく、その区間で壊れたものは無いとは言えない。**ただし、空きで測れる止まり方は片方
  だけ**——デーモンが落ちた区間はログに何も書けないので空きとして出るが、**盤面を引けない区間は
  5分おきに回り続ける**（`RETRY_INTERVAL`）ので、**1手も打たれないまま時刻の上では埋まる**。
  台帳の印（`unreadable:since`）も**引けた周に消える**ので、直った後に立つあなたには残っていない。
  **直っていることを、止まっていなかったことと取り違えない**——引けなかった区間は、**閉じるときに
  周の出来事の帳面へ1行残る**（`agent-ops/board-design.md` 2.20.3節）ので、そこを数える（下の
  「調べる先」）
- **周期の係は、この係のほかも、それぞれの間隔どおりに立っている。** 上の2つはこの係と周そのものに
  ついての話で、**他の係が立たなくなっても、周は同じ顔で回り続ける**——立てる手が出ないだけなので、
  空白にも「打てなかった」にも出ない。**止まった係の仕事は、誰の手番でもないまま溜まる**（分類する
  係が止まれば `未整理` はいつまでも分類されず、配る列へ一度も入らない）。**見るのは打たれた手では
  なく刻**——台帳の `cycle:*` が、どれも次の刻を未来に持つこと。**過去に居続ける刻は、立てる手が毎周
  転んでいるか、立てる条件のほうが壊れている**
- **着手可の task は、いつか投入される**（錠・枠・手綱のどれでも説明が付かない滞留は無い）。
  **枠は1つではない**——作業者の枠とは別に、**配ってよい種類のほうを絞る枠**が在る。別の枠が満ちて
  いる周は、**作業者の枠が空いていても投入は出ない**ので、空きの数だけを見ると「配れるのに配って
  いない」と読む。**どの枠が止めたかは覚え書きが名指しする**ので、読むのは数ではなくその名前
- **枠が満ちて投入が止まっている周は、その枠が盤面の手で空く。** 抱えている枠は、**PRを出して
  人の答えを待っているだけのセッションも数える**（`scripts/daemon/board-move.mjs` の `HELD_TASKS`）
  ので、握っているものが全部人待ちでも、覚え書きは**並列度いっぱいで健全に走っている周と一字も
  違わない**。**枠で説明が付くことは、滞留が健全であることの証拠にならない**——人待ちのぶんしか
  握っていない周は、盤面が自力で次の手を出せないまま、止まっていることが件数のどこにも出ない。
  読むのは件数ではなく**内訳**（下の「調べる先」）。**満ちていること自体は破れではない**——
  手の動いているものを1つでも握っているなら、その1本が出したPRをレビューが `判断待ち` を付けずに
  通した時点で、盤面がマージして自分で空ける。**破れと言えるのは、握っているものが人待ちと
  「誰の手番でもないもの」だけになった周**で、そこから先は人がマージするまで残りが増えない
- **投入を止める枠は、満ちる前から読める。** 覚え書きが名指しするのは**その周に効いている枠1つだけ**
  なので、**まだ満ちていない枠は一度も名前が出ない**——名前が出た周には投入はもう止まっている。
  名指しされた枠が**盤面の手で空く**周（＝1つ上が成り立つ周）でも、その後ろで別の枠は埋まっていく
  ので、**名指しされた枠だけを見ると、迫っている全停止が最後まで見えない**。**数えるのは名指しされた
  枠ではなく、すべての枠の残り**（`board-move.mjs` の `HELD_TASKS`・`ACTIVE_WORKERS`・
  `UPKEEP_WORKERS`）で、**握っている相手が全部人待ちの枠は、盤面が自力では1つも空けられない**
  ——残りが増えるのは人がマージした数だけ。**`急ぎ` はこの枠を越えない**（越えるのは配ってよい種類を
  絞る枠だけ。2.18）ので、満ちた後に盤面の側へ打てる手を足すことはできない
- **判定の付いたPRは、いつかマージされるか差し戻される**
- **`main` は緑である。** 赤い間、盤面はレビューもマージも差し戻しも出さない（2.14.1）ので、
  **1本の赤で盤面ごと止まる**。**緑へ戻す役は盤面の中に居ない**——赤いことは覚え書きとして
  `~/daemon.log` と常設の盤の `## 周の出来事`（2.20.3）へ出るが、**どちらも見た者が動くまで誰の手番
  にもならない**。直せる範囲（`agent-ops/**`・`.claude/**`・`scripts/**`）なら自分で直し、外なら人へ
  上げる
- **生きているセッションは、何かを進めている**
- **立てたセッションは、現に働いている。** 投入できたことと働いたことは別で、立てた先に走る者が
  付かなければ、セッションは作られたまま空で残る。**この区別そのものは盤面も見回りも持っている**
  （`live-sessions.tsv` に `unserved` と書かれた列を持つセッションは、一度も働いていない）ので、
  **疑うのはその先**——空の1本が畳まれずに枠を握ったままになっていないか、`unserved` が並ぶ環境の
  知らせが出ているか
- **人へ渡す手は、盤面の出口の中では例外である。** `RETURN`（`判断待ち` を付けて issue を返す）が
  主要な出口になっている周は、**返した理由が個々の仕事ではなく環境に在る**——1件ずつ見るかぎり
  どれも正しく見えるので、**打った手の内訳を数えるまで気づけない**（下の「調べる先」）。
  返したぶんを戻せるのは人だけなので、**塞がりが明けても盤面は自力で戻らない**。配れる `着手可` が
  尽きた盤面は、枠も錠も手綱も空いたまま周期の係だけを回す
- **差し戻しは、必ず誰かへ届く**
- **手を打たない周は、打たない理由を言える**
- **盤面が「〜を待っている」と言うとき、待たれている側が現に居る。** 覚え書きが名指しする相手
  （札を付ける係・CIの走り・人）が**既に転んでいると、待ちは永久に満たされないのに覚え書きだけが
  毎周出る**——止まっていることと、正しく待っていることが、ログの上では同じ文字列になる。
  **覚え書きが名指しするものは、現に走ったか・走る見込みがあるかまで引いて確かめる**
  （`gh run list --workflow <名前>` の `failure`・`startup_failure`・`queued` のまま動かないもの）
- **見張りが黙っている周は、見張られているものが無事である。** 猶予を持つ見張り（値の見回りの
  `VALUE_GRACE_HOURS`、既定6時間）は、**猶予の中の死を「告げることは無い」と言う**——その一行は、
  全部生きている周と一字も違わない形で出る。**読むのは行の頭ではなく括弧の中の `key=state`**で、
  そこが `dead` なら見張りは黙っているだけ。**黙っていること自体は正しい**（直る途中のものを毎周
  告げると読まれなくなる）が、**猶予より短い死は、告げられないまま何度でも繰り返せる**
- **`unknown` と言われた値は、確かめられなかっただけで、死にかけてはいない。** 見張りがそう言うのは
  その周に確かめる手立てが無かったときで、**続いた回数はいくら重ねても死の証拠にならない**
  （値の見回りの `<環境>:workers` は、その環境へ盤面が立てたセッションが1本も生きていない瞬間に撮ると
  こうなる。ブリッジのように、盤面のセッションが間隔の一部しか居ない環境では**毎周こう出うる**）。
  **見るのは回数ではなく、確かめられなかった理由が今も在るか**——理由が在るなら、その周の `unknown` は
  正常の一部。**次の回の自分へ「続いたら本物だ」と書き残さないこと**で、そう書くと、確かめる手立てが
  無かった周を数えて告げることになる
- **機械が付けるはずのものは、転んだ回にやり直される。** GitHub のワークフローが受け取る出来事
  （コメント・push）は**二度と来ない**ので、転んだ回のぶんは誰かが手で入れない限り永久に欠ける。
  **欠けた印は「まだ付いていない」と区別が付かない**ため、盤面はそれを待ち続ける
- **打った記録と、現に在るものが食い違わない**（打てなかったと記録された手は、走るものを残していない）
- **「もう打った」と記録されている手は、打った理由が今も生きている。** 盤面は同じ手を二度打たない
  ために指紋を控えるが、**理由が外で決まる手**（`main` の色・他のPRのマージで生まれるもの）は、
  **控えた指紋が動かないまま、理由のほうだけが消える**ことがある。消えても記録は残るので、盤面は
  「打ち終えた」と読み続け、頼まれた側は**理由が消えたことを知らないまま手を止めている**。
  **控えられている手は、理由の側を引いて今も成り立つかまで確かめる**（`~/.claude/board-state/taken.json`
  の各項目に対して、それを生んだ条件が現に在るか）
- **盤面が見ているものは、現に在るもの全部**（一覧の上限・窓の幅で切れた帯が無い。切れていれば、
  盤面は切られた側を「無い」と読むので、止まっていることすら見えない）
- **止まっているものには、次に手を出す者が居る**（盤面・書いた本人・人のどれか）。**どれでもない
  ものは、止まっていることがどこにも出ない**——常設の盤（2.20）が名指しで出すのは人待ちのものだけ
  なので、「誰の手番でもない」は人の目にも留まらない。**issue を立てたことは、手を出す者が居ること
  ではない**——`bash scripts/agent/board.sh` の `## TASK` に並んで初めて盤面の手番になる
- **調べるために打つものは、盤面の状態を書き換えない。** 下の「調べる先」が勧める空打ちも、
  盤面を引く道具も、**見るだけのつもりで通す**もの。これが破れると、**次の回のあなたは、自分の
  足跡と盤面の手を見分けられない**——毎回通る手なので、足跡は間隔ごとに1つずつ積まれ、しかも
  「盤面が打った」と同じ形で残る。**勧められた手でも、書き換えないことは確かめてからでないと
  言えない**（その周に触られたファイルの更新時刻を、打つ前と後で見る）
- **見回りが打った直しは、次の回には要らなくなっている。** 同じ直しを間隔ごとに打ち続けている間、
  **その手を打つ者は盤面の中に居ないまま**で、盤面が健全に見えるのは**見回りが内側へ入って穴を
  埋めているから**——埋めている当人だけが、埋めていることを知っている。**見分けるのは前回の記録の
  `fixed`**で、同じ直しが並んでいたら、その回に出すのは直しではなく**「なぜ他に打つ者が居ないか」**。
  **直しを打たずに壊れたままにするのも同じだけ誤り**なので、打ったうえで出口へ回す

**これは拾うべき異常の一覧ではありません。** 壊れ方は未知のものが来るので、列挙では追いつき
ません——**未知の壊れ方も、成り立たなくなった不変条件のどれかに必ず現れます。**

**足りないと思ったら、あなたがこのファイル（`agent-ops/prompts/patrol-prompt.md`）へ書き足してください。**
次の回の自分が読みます。**「今回こういう壊れ方を見た」ではなく、「何が成り立っていれば
それが起きないか」を書くこと**——事例を足すと、この節が壊れ方の一覧に戻ります。

## 前回の観測と突き合わせる

**進んでいないことは、1枚の写真には写りません。** 前回の自分が見たものと突き合わせて初めて
「同じものが同じ場所で止まったままだ」と言えます。**原因を知らなくても停滞は言える**のがこの形の
要点です。

記録は1行1件のJSONで、**最後の行が前回のあなた**です。**置き場はデーモンに訊いてください**
——既定は `~/.claude/board-state/patrol.jsonl` ですが、`BOARD_STATE` で移してあると、**書いた先と
盤面が読む先がずれて、常設の issue に「記録がありません」が出続けます。**

**読んだ行が最後の行だと、行の並びから言えるようにしてください。** 1行が数十KBあるので、生のまま
吐かせると出力の途中で切られ、**どれが末尾かが分からなくなります**——切られた先頭を末尾と読むと、
前回ではなく何時間も前の観測と突き合わせることになり、**その間に起きた停滞が見えないまま「間隔が
空いている」のような別の異常に見えます。** 先に `at` だけを並べて、どこが末尾かを確かめてから
中身を開きます。

```
PATROL=$(node -e "import('./scripts/daemon/board-state.mjs').then((m) => console.log(m.patrolPath(m.boardState())))")
node -e "const l=require('fs').readFileSync(process.argv[1],'utf-8').trim().split('\n');for(const s of l.slice(-5)){const j=JSON.parse(s);console.log(j.at,j.verdict)}" "$PATROL"
node -e "const l=require('fs').readFileSync(process.argv[1],'utf-8').trim().split('\n');const j=JSON.parse(l[l.length-1]);console.log(j.at,j.verdict,j.summary);for(const k in j.board)console.log(k,'=',j.board[k])" "$PATROL"
```

**最後に、必ずこの `$PATROL` へ1行追記してください**（異常が無くても）。形は次のとおりです。

```json
{"at":"<ISO8601>","verdict":"異常なし|直した|人へ上げた","summary":"<1行。人が読む>","board":{"<自由>":"..."},"broken":["<成り立っていなかった不変条件>"]}
```

- `at` … **時刻として読めること。** 読めない行は、走らなかったのと同じに扱われます
  （`scripts/daemon/board-state.mjs` の `readLastPatrol`）。
- `verdict` と `summary` … **常設の盤面 issue（2.20）へそのまま出ます。** 読むのはスマホの人間なので、
  リポジトリを開かずに読める1行にしてください。
- `board` … **次の回のあなたが「同じものが同じ場所で止まったままだ」と言えるだけのもの。** 形は
  決めていません（最後に手が打たれた時刻・着手可の task の番号・開いているPRとその状態・
  生きているセッションとその状態、あたり）。**前回の行と同じ鍵で書くこと**——鍵が毎回変わると
  突き合わせられません。

## 調べる先

**この係の報告は、ほとんどが「無い」という主張です**（空白は無い・転んだ手は無い・欠けた印は無い）。
**絞って読んだ出力から「無い」を結論しないでください**——`head`・`tail`・`--limit` で切った先は、
見ていないだけで、無いのとは違います。**切ったなら、切った外の件数を数えてから言う**（全体を数える・
絞りを外してもう一度引く）。ここを飛ばすと、**現に在るものを「欠けている」と報告する**ことになり、
それはそのまま常設の盤へ出て人が読みます。

| 何を | どこ |
| --- | --- |
| 前回の観測 | 見回りの記録（上の `$PATROL`）の最後の行 |
| この係が立った時刻 | `grep '打つ: CHORE patrol' ~/daemon.log \| tail`（**記録の `at` ではありません**。あれは書き終わりの時刻で、所要時間のぶん後ろへずれます） |

| 何が転んだか | 同（`打てなかった:` と `盤面を引けなかった` の行。`（転んだのではない）` が付く行は手綱などで、直す相手が居ません） |
| 打たない理由 | 同（`覚え書き:` の行。**毎周同じ覚え書きだけが出ているなら、盤面は動いていません**） |

| 立てたセッションが働いたか | `~/.claude/board-state/live-sessions.tsv` の `unserved`／`served` の列（列の並びは `scripts/daemon/live-sessions.mjs` の `formatLive`。`status_bucket` では言えません——`..._FAILED` は、働いたあとに手番が転んだものにも付きます）。ブリッジなら `.claude/worktrees/bridge-cse_<ID>` が**作られたか**でも見られます |
| 今の盤面 | `bash scripts/agent/board.sh` |
| 満ちた枠の内訳 | 常設の盤（2.20）の `## 投入済み` の表——`手空き`／`作業中` の列と、そのPRの札。**覚え書きの件数では言えません**（そこに並ぶのはセッションIDだけ）。握っているPRが人待ちかは `gh pr list --state open --label 判断待ち` |
| まだ名前の出ていない枠の残り | 同じ表の行数を、`board-move.mjs` の `HELD_TASKS`・`ACTIVE_WORKERS`・`UPKEEP_WORKERS` と比べます（`手空き` の行は `HELD_TASKS` だけを握り、`ACTIVE_WORKERS` も、その内数の `UPKEEP_WORKERS` も握りません——後ろの2つが数えるのは**手が動いているものだけ**なので、握っている相手が人待ちへ移った周に自分で空きます。**整備の枠が人待ちに握られていると読むと、盤面の手では空かない枠だと誤ります**）。**覚え書きに出てくるのを待たないこと**——出た周には投入が止まっています |
| デーモンの生死 | `bash scripts/daemon/daemon.sh status`（**答えるのは今の生死だけ**。手前の区間は次の行で見ます） |
| 周が止まっていた区間 | `~/daemon.log` の、時刻を持つ行どうしの空き（下の一行）。**死んだ周はログに何も書けない**ので、探すのは書かれたものではなく**書かれていない幅**です |
| 盤面を引けていないか | デーモンの台帳（記録と同じ置き場の `taken.json`）の `unreadable:since`。**今まさに引けていないときだけ在ります**——引けた周に消えるので、直った後に立つあなたには残っていません |
| 盤面を引けなかった区間 | 周の出来事の帳面（`~/.claude/board-state/rounds.jsonl`）の `kind: "gap"` の行。**閉じた区間が、いつから・いつまで・何周・道具が言った理由ごと1行で残ります**（2.20.3）。**今まさに引けていない区間はまだ閉じていない**ので、そちらは台帳の `unreadable:*` を見ます。**ログの空きでは出ません**——5分おきに回り続けるため時刻の上では埋まります |
| 打った手 | 同じ帳面の `kind: "move"` の行（`move`・`target`・`result`）。**`result` が `settled` の手は直す相手が居ません**。`~/daemon.log` の `打つ:` を数えるのと同じものが、窓を切らずに積まれています |
| 周期の係の刻 | 同じ台帳の `cycle:*`。間隔を持つのは `scripts/daemon/board-move.mjs` の `CYCLES` なので、刻に足して次がいつかを出します。**打たれた手の側からは言えません**——立たない係は手を1つも残しません |
| 控えた手の理由が消えていないか | 同じ台帳の `resume:*`。`mend:conflict`・`mend:red` は**PRの版が動かないまま `main` が動いて生まれる**ので、`main` が緑へ戻ると理由だけが消える。控えた指紋のPRを `gh pr view <番号> --json mergeable,statusCheckRollup` で引き直す |
| 誰の手番でもない跡 | 本体のチェックアウトの `git status`（issue でもPRでもセッションでもないので、盤面には映りません） |
| `main` の色 | `git fetch origin main && git rev-parse origin/main` で指紋を出し、`gh api 'repos/{owner}/{repo}/actions/runs?event=push&head_sha=<指紋>'`（2.14.2。**枝の名前で引くと、push の直後は1つ前の色が返ります**。**`fetch` を落とすと、このクローンの `origin/main` が古いか無いかのまま引くことになります**） |
| 機械が付ける印が欠けていないか | `gh run list --workflow board-labels.yml --limit 100`（`failure`・`startup_failure`・`queued` のまま動かないもの。**転んだ回の出来事は二度と来ません**） |
| 色が付かないPRが居ないか | `gh api 'repos/{owner}/{repo}/actions/runs?status=queued'`（**楔になった走りは `gh run cancel` も `gh run rerun` も拒みます**。新しいコミットが載るまで、そのPRに色は付きません） |

周が止まっていた区間は、こう引きます。**閾値を10分に取るのは、盤面を引けない間は5分おきに回る**
（`RETRY_INTERVAL`）ため——そこを下げると、正しく待っている区間まで空白として出ます。

```
node -e "const l=require('fs').readFileSync(process.env.HOME+'/daemon.log','utf-8').split('\n');let p=0;for(const s of l){const m=s.match(/^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ/);if(!m)continue;const t=Date.parse(m[0]);if(p&&t-p>600000)console.log(m[0],'の手前に',Math.round((t-p)/60000),'分の空白');p=t}"
```

**`~/daemon.log` を前回からの窓で切るときは、時刻の比較ではなく行の位置で切ってください。** 1つの手は
複数行で書かれ、**2行目以降は時刻を持ちません**（`打つ:` に続く `SESSION` の行、失敗の理由の行）。
先頭のフィールドを時刻と比べて窓を作ると、**時刻を持たない行が漏れなくその窓に入り**、何日も前の失敗を
この1時間のものとして数えます。窓の始まりは `grep -n` で行番号を出し、`tail -n +<行番号>` で切ります。

**転んだ手は、実際に手で打ち直して確かめてください。** ログに残るのは「打てなかった」までで、
理由はそのスクリプトの標準エラーにしか出ていません。`DRY_RUN=1` を付ければ立てずに引数だけ見られます。

```
DRY_RUN=1 node scripts/daemon/board-round.mjs
DRY_RUN=1 bash scripts/daemon/dispatch-task.sh <番号> /dev/null
bash scripts/daemon/may-dispatch.sh new-task task-<番号>
bash scripts/daemon/brake.sh new-task
```

## 直す

**直してよいのは、不変条件が成り立っていないと言えるときだけ**です。**言えないなら直さない**
——健全な盤面をいじると、次の回のあなたが何を見ているのか分からなくなります。

**変更は `main` へ直接 push してください**（出どころ: ユーザーの指示・2026-09-06。
`agent-ops/decisions/2026-09-06-daemon-watchdog-commits-straight-to-main.md`）。**PRにすると、盤面が
詰まっている間はマージされないので直しが届きません。** 直せるのは `agent-ops/**`・`.claude/**`・`scripts/**`
の範囲です。

- **コミットには自分のセッションIDを名乗ってください**（`CLAUDE.md`「コミットには自分の
  セッションIDを名乗る」）。
- **push の前に `npm run lint` / `npm run typecheck` / `npm test` / `npm run format:check` を
  通してください。** `main` を直接壊すと、開いている全部のPRが赤くなります。
- **`area:daemon` を持つ task が同時に走っていることがあります**（この係は錠を取りません。2.21.3）。
  `bash scripts/agent/board.sh` の `## 走行` で確かめ、**居るなら差分を最小にして、そのことを報告に
  書いてください。** 相手のPRとぶつかっても、盤面が `mend` で直させます。
- **デーモンを止めないでください。** 走っているデーモンは、`main` が動けば次の周に自分で新しい版へ
  入れ替わります（2.3.2）。どうしても要るときだけ `bash scripts/daemon/daemon.sh restart` を打ち、
  打ったことを報告に書いてください。
- **セッションを立て直さないでください。** 投入するのは盤面で、原因が消えれば次の周に自分で打ちます。
  あなたが立てると、同じ仕事に2本立ちます。

### 自分で打たない手

**取り返しの付かない手は、直せると思っても打たないでください。** 間違えたときに戻せないので、
判断は人が持ちます。

- **PRのマージ**、`git push --force`、**人が立てた issue を閉じること**
- **手綱（2.4）の付け外し**、`判断待ち` の付け外し
- **人が書いた issue・PRの本文の書き換え**

これらが要ると判断したら、下の「自分で直せないものを渡す」の**人へ上げる**側へ回してください。

## 自分で直せないものを渡す

**ユーザーはこのセッションを見ません。** 訊いて待つことはできないので、issue を1本立てて終わります。
渡す先は2つ——**人へ上げるのか、次のセッションへ回すのか**で分かれます。

- **人へ上げる**（資格情報・ブリッジを開き直す・手綱の issue が壊れている・上の「自分で打たない
  手」）→ **`判断待ち` と `origin:agent` と `goal:upkeep` を付ける。** 題は `詰まり: <何が止まっているか>`。本文には、
  **リポジトリを開かずに答えられるだけの文脈**（何が転んだか・打った手・返ってきた言葉・人に何を
  してほしいか）を書いてください。**人への上げ口はこれだけです**——新しい知らせ方を作らないで
  ください。
- **次のセッションへ回す**（直すのに1セッションぶんの仕事が要る）→ **`origin:agent` と `goal:upkeep` を付ける**
  （`kind:` は付けない。分類は棚卸しの仕事です）。**人の手番は要らない**ので `判断待ち` は付けず、
  盤面が配ります。本文は `agent-ops/parallel-work.md` 3節のタスク issue の型に従ってください。
  - **止まっているのが盤面自身なら、`kind:task` と `急ぎ` まで自分で付けてください**
    （`agent-ops/board-design.md` 2.18.1節「盤面そのものが止まる整備は `急ぎ` で越える」）。棚卸しは
    半日に1度しか走らないので、`kind:` の付いていない issue は**その間ずっと配る列の外**に居ます。
    付けても古い番号から配るため、**立てたばかりの issue は在庫の最後尾**です。**`急ぎ` は付けすぎ
    ても壊れません**（2.18。全部に付けば古い順に戻るだけ）が、`判断待ち` と手綱は越えません。
    **付けたことは `gh issue view <番号> --json labels` で見てください。`bash scripts/agent/board.sh` の
    `## TASK` では見えません**——あそこは番号の降順で並ぶだけで、配る順は
    [`board-move.mjs`](../../scripts/daemon/board-move.mjs) の並べ替えが持っています。**先頭に立つのを
    待つと、効いている札を効いていないと読みます。**

**同じ issue を毎回立てないでください。** この係は**間隔ごとに必ず立つ**ので、直るまで毎回1本ずつ
増えます。**どちらの出口でも、立てる前に既に在るかを確かめてください。**

```
gh issue list --state open --label origin:agent --search '<止まっているものの名前>'
gh issue list --state open --search '詰まり:'
```

**題で引けるとは限りません**——棚卸しが題を書き換えるので、**同じ中身を指している issue が在るか
を、自分で読んで判断してください。** 在れば**本文へ追記するのではなく、コメントで今回の観測を
足すだけ**にします。

**次のセッションへ回すほうは、打ち手が `docs/DesignNotes.md` で不採用済みでないかも確かめて
ください**（`agent-ops/parallel-work.md`「立てる前に、不採用の記録と突き合わせる」）。人へ上げる
ほうは、**止まっている現物を告げるだけ**なので要りません。

## 報告する

最後に、次を書いて終わりです。**上の `$PATROL` への追記を先に済ませてください**——これが無いと、
次の回のあなたは前回を持ちません。

- **どの不変条件を確かめ、どれが成り立っていなかったか**（全部成り立っていたなら、そう書く）
- 前回の観測と比べて、**同じ場所で止まったままのものが在るか**
- 何をしたか（push したコミット・立てた issue の番号・`restart` を打ったなら打ったこと）
- **直したなら、直ったことをどう確かめたか。** 転んでいた手を手で打ち直して通ることを見るか、
  次の周が進むのを見るか。**「直したはず」で終わらせないでください。**

## 守ること

- **`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わないこと。** 自動承認ができず、
  呼んだ分がそのままユーザーの手作業になります。
- **PRを作らないこと。** この係の直しは `main` へ直接入ります。
- **盤面の健全さと関係のない直しをしないこと。** 気づいた別の問題は issue を立てるだけにしてください
  （`origin:agent` と `goal:upkeep` を付ける。`kind:` は付けない）。
````
