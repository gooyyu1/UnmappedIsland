# 値の死を告げるプロンプト

**このPCの `gh` が死んでいる周に、代わりに issue を書く**係の本文。投入するのは値の見回り
（[`check-values.mjs`](../../scripts/daemon/check-values.mjs)）で、渡し方は
[`dispatch-chore.sh`](../../scripts/daemon/dispatch-chore.sh)（`--gate values`）。

**下の「置く本文」の差し込み口は、投入する側が埋める**——issue へ置く本文は、見回りが自分で組み立て
たものをそのまま渡す。判断はここに無い。**ここが渡すのは「どこへどう置くか」だけ**で、何が死んで
いるかは本文の中に在る。**差し込み口の綴りをこの説明の中で書かない**のは、埋める側が綴りで探すから
——ここに書くと、説明の側も一緒に埋まる。

**この係は閉じない。** 題で引く issue 1本に畳む持ち主は手元の見回りのままで、値が生き返ったのを
見た周にあちらが閉じる（[`board-design.md`](../board-design.md) 2.22.3）。

題は下の `題:` の行が持つ（[`board-design.md`](../board-design.md) 2.9）。

題: 告げ 盤面が動くのに要る値の死

---

````
[デーモン] このPCの `gh` の資格情報が死んでいて、**盤面の見回りが自分で issue を書けません。**
代わりに書いてください。**これ1件だけが仕事です。**

道具は `agent-ops/github-access.md` の「issue を読む・書く」に従ってください。

## 置くもの

題が `盤面が動くのに要る値が死んでいる` の issue 1本を、下の本文で置きます。

1. **開いている issue を全部引いて、題で照らす。** 題や本文で探す道具は使わないでください
   ——索引を引くので、**立てた直後のものは出てきません。** 一覧が黙って切られていないかも、
   同じ `agent-ops/github-access.md`「issue を読む・書く」に従って確かめてください。
2. **引けなかったら、何も書かずに終わってください。** そこで立てると、同じ題の2本目が立ちます
   ——告げるのが1周ぶん遅れるほうが軽い。
3. 題の合う issue が**在れば、本文を丸ごと書き換える**。**無ければ立てる**（ラベルは `判断待ち`・
   `origin:agent`・`goal:upkeep` の3つ）。
4. **閉じないでください。** 閉じるのは、値が生き返ったのを見た手元の見回りです。

## 置く本文

**ここから下を、そのまま置いてください。** 書き足さない・要約しない・並べ替えない。

<本文>

## 守ること

- **差分を作らないこと。** コードも文書も触らず、コミットもPRも作りません。
- **他の issue を立てない・コメントしないこと。** 上の1本だけです。
- **`subscribe_pr_activity`・`send_later`・`delete_trigger` を使わないこと。** 自動承認ができず、
  呼んだ分がそのままユーザーの手作業になります。
- 置けたら、**どちらをしたか**（立てた／書き換えた）と issue の番号を1行で報告して終わりです。
  置けなかったなら、その理由を1行で。

応答は日本語で。
````
