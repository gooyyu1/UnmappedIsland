### レビューが挙げたスメルは、同じPRの後の周で消えている

**読んだ100件のうち25件**（後の周のレビューか著者が「消えている」と書いているもの22件＋後の別のPRの
マージで現物ごと消えたもの3件）。PR #2120 の9件中6件、PR #2130 の8件中4件のように、**周を重ねたPRほど
割合が高い。**

コメントだけを読んで issue にすると、受け取った側は直っている箇所を探すことになる。この回は、issue へ
足す箇所と新しく切る箇所を**全部現物で確かめてから**書いた。

### 数値を書いた記述が、生成物・現物から手で引かれていて、印も検査も持たない

6本のPR（#2189・#2149・#2120・#2196・#2154・#2179）に出た。`<!-- stats: ... -->` の印を置けるのに
置いていない書き写しと、印の文法では表せない導出（比・差・掛け算）の両方がある。

**同じ周の中で片方を直しながら、もう片方を残した例がある**——PR #2120 は `ContentSkeleton.md:1009` の
手計算を「数を書くのをやめる」形へ直したが、**隣の `TerrainStats.md:212` に同じ形が残った**（同じPRの

### 人の判断へ回した問いが、何周も同じ内容で繰り返されている

5本のPR（#2195・#2151・#2130・#2177・#2178）で、レビューが毎周「まだ答えが付いていません」と書いて
**問いの全文を畳み直している。** #2195 と #2151 は3周、残りは2周。どれも答えが付かないまま最後は
マージされている。

問いはPRのコメントに在るので、**ユーザーが `判断待ち` の issue の一覧を見ても現れない。** 1問1 issue の
形（`CLAUDE.md`「確認は、1問1 issue で出す」）が効いているのは issue の側だけで、レビューが回す問いは
その外に居る。**この回は issue にしていない**——どこへ出すかは仕組みの側の設計で、レビューが人へ回す形
そのものを変える話になるため。
