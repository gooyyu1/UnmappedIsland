# 宣言の棚卸し

`src/` の宣言を機械で全部出し、**1件ずつ同じ問いで採点する**調査の、進め方と物差し。
次に同じことをするときは、ここから読む。

**日付の付いたフォルダは、その回限りの記録。** 採点の明細・打ち手の一覧・段ごとの作業記録が入って
いて、**当時のコードに対する答え**なので、今の `src/` とは食い違う。次の回が使うのは、既に挙がった
ものと直さないと決めたものを除外させる材料としてだけ（3節）。**この `README.md` だけが今の文書**で、
日付のフォルダは書き換えない——[`docs/DocumentStyle.md`](../docs/DocumentStyle.md) 10節が、そこへ
参照の規約を課さないと決めている（当時のコメントの字面を引いた箇所があり、直すと引用でなくなる）。

| 記録 | 何を問うた回か |
| ---- | -------------- |
| [`2026-08-22-placement/`](./2026-08-22-placement/) | その宣言は**そこに居てよいか** |
| [`2026-08-23-naming/`](./2026-08-23-naming/) | その宣言の**名前が責務を言い切っているか** |

## 1. 進め方

1. **一覧を機械で作る。** `node scripts/declarationInventory.mjs --json` が、名前・シグネチャ・
   可視性・付いているドキュメントコメントを全宣言ぶん出す。**探索ではなく、与えられた一覧の採点に
   する**——漏れが無くなり、担当を分けても出力が揃う。
2. **観点は1つずつ独立に通す。** 別の観点の明細表へ補足の列として混ぜると、その列の指摘は打ち手の
   一覧へ持ち上がらない。名前の妥当性を定義位置の調査の最終列に置いたところ、27件がどのレーンにも
   入らなかった。
3. **領域で割る。** 1人が読み切れる量で、互いの参照が跨がない単位。担当は採点を始める前に、母集団・
   判定基準・迷ったときの倒し方を自分の明細の冒頭へ書く——書かせないと領域ごとに基準がずれる。
4. **領域に閉じると見えないものは、親が全宣言の一覧に対して名前で束ねる。** テストからしか呼ばれない
   公開、どこからも輸入されない `export`、同名同値の定数、同名で別物。
5. **判定は名前とシグネチャだけで行う。** 本体を読むのは名前から中身が類推できないときだけ
   ——読んでから判定すると「読めば分かる」に引きずられる。読まないと分からなかったこと自体が指摘。

## 2. 物差し

問いごとに違う。**良い状態には印を付けず、指摘だけを挙げる**——大半は良い状態なので、そちらに印を
付けると印が背景になる。

### 2.1 そこに居てよいか（置き場）

| 判定 | 意味 |
| ---- | ---- |
| 1 | 一般概念として、そこにあるのが妥当（オブジェクトがプロパティを持つ、など） |
| 2 | 概念的に自明ではないが、プログラムである以上は必要（オブジェクトがIDを持つ、など） |
| 3 | 意味論的にはそこである必要はないが、利用者が近くにいるので置かれている |
| 4 | 意味論的には他所が自然だが、実装上の別の何かを守るためにそこに居る |
| 5 | 意味論的にも利用方法的にも、そこにあるのは不適切 |

**4 が最も価値のある発見。** 「何を守るために歪んでいるのか」が特定できれば、守っているものごと
直せる。判定4には**阻害要因**（何を守るためにそこに居るのか）を必ず添える。添えられないものは 4 では
なく 3 か 5 に倒す。テスト可能性のためだけの公開も 4——**倒す物差しと、今そうなっているものの一覧は
[`tests/architecture/readersOutsideSrc.test.ts`](../tests/architecture/readersOutsideSrc.test.ts)** が
持つ（この観点だけは、回ごとの調査ではなく常設の検査になっている）。

打ち手が違うので、指摘が**どの層の話か**を明示する——ディレクトリ／ファイルの**配置**、クラス／
モジュールへの**所属**、`public`・`export` である必要があるかの**可視性**。配置の判定は
[`docs/CodeStructure.md`](../docs/CodeStructure.md) 1節の層を基準にする。移動先の決め方は
[`docs/engine/DesignNotes.md`](../docs/engine/DesignNotes.md)「定義位置を動かすとき」。

**判定3は、5段階とは別にもう一段深い問いで見直す。** 「A の private ヘルパーだが、主語は実は B
（B の機能が足りないから A が代わりに書いている）」という形を、private ヘルパー全件へ問う。
`this` を参照しているかでは主語は分からない——自分の1フィールドだけ触って残りは全部 B の話、が本命。

### 2.2 名前が責務を言い切っているか

宣言1つにつき、責務を一言で書き、次のどれかに分ける。

| 判定 | 意味 | 打ち手 |
| ---- | ---- | ------ |
| **A** | 一言が名前をなぞるだけ | **何もしない。** これが良い状態——名前が責務を言い切っている証拠 |
| **B** | 一言が名前から読み取れない | **改名。** 名前にしてなお言い残す契約があるときだけコメントを足す |
| **C** | 名前が別のものを指している | 改名（Bより強い。読み手を誤った方向へ導く） |

**説明の無い宣言と、説明のある宣言では問いが違う。** 前者は「名前だけで足りているか」、後者は
「その説明は名前の言い換えか、それとも名前が言えていないことか」。

打ち手が改名でありコメントではないこと、`private` を基準にしないことは規約の側にある
（[`docs/CodingConventions.md`](../docs/CodingConventions.md)「ファイルと命名」「コメント」）。

### 2.3 兄弟が揃っているか

見つけ方は、**兄弟なのに名前・引数が揃っていない**／**存在意義の薄いラッパー**／**ドキュメント
コメントが現実とずれている**。

- **探す先は全体に均等ではなく、別々の系統が接する継ぎ目に固まる。** 定義と実行時状態の対、
  共有ヘルパー層の境界、組み立ての手続きが並ぶ所。
- **コメントが別ファイルを指して「〜と揃える」「〜と同じく」と書いている箇所は、そこが集約すべき
  場所。** 探すより先にこの相互参照を拾う。

## 3. 報告は鵜呑みにしない

- **上限を付けない。** 上限で打ち切ると、挙がった件数は上限そのものになる——担当が全員その数で
  止まった回があり、上限を外して同じ範囲を見直したら桁が変わった。
- **既出は除外させる。** 前の回で挙がったもの・直さないと決めたものを、指示に入れる。
- **呼び元は自分で数える**（`rg`）。報告の件数は食い違うし、誤検出も混じる。
- **着手前に、挙がった阻害要因をコードで反証しにいく。** 「これを守るためにそこに居る」は、確かめる
  と崩れることがある。
- **件数ではなく原因の数で読む。** 1つの原因を宣言ごとに数えた結果が混ざるので、件数は領域間で比較
  できない。集計では件数と原因の数を分けて出す。
- **数の多さそのものは指摘にしない。** 「ここにこれだけ集まっているのはおかしい」は、方針が何を
  禁じているかを読み直せば大半が消える。
- **「揃っていない」「薄い」「重複している」は指摘の入口であって、結論ではない。** 差に理由があるか
  を本体と呼び元で確かめてから挙げる。答えている問いが違うなら、揃えると差そのものが消える。

## 4. 段に割る

打ち手の優先は**「1つ直すと何件消えるか」**の一本で決める。並べる順は、その変更が他の指摘に何を
するかで分ける。

| 種類 | 順 |
| ---- | -- |
| 他の指摘の判定を動かさない | いつでもよい。並列に流せる |
| 他の指摘を丸ごと消す | 先。消える分を後続から外せる |
| 他の指摘の**前提**を変える | **実装より先に決定が要る。** コードを書かない段として独立させる |

- **移動先が書けない指摘は、別種の発見。** 「Aにも B にも置けない」はそこに概念が無いということなので、
  作るべきものを名前で書いて決定の段へ回す。
- **各段の後にインベントリを再生成して差分を見る。** 位置がずれただけのものと、判定が変わったものを
  分けて読み、再採点は阻害要因を外した箇所だけに絞る。
- **事前に書いた「これを直すと何件消える」と、実際に消えた件数を突き合わせる。** 消えなかったものは
  新しい発見として扱う。

## 5. 終わったら

**その回の明細は、日付を頭に付けたフォルダへ畳む。** 次の回が読むのはこの `README.md` だけで、
記録は当時の答えとして残す。方針として次も使うものが出たなら、責務を持つ文書
（`docs/CodingConventions.md`・`docs/CodeStructure.md`・`docs/engine/DesignNotes.md`）か、
この `README.md` へ移してから畳む。

**その回の中では終わらないと書いて先送りしたものは、畳む前に issue にする。** 次の回が記録を開くのは
既出を除外させるためだけ（3節）なので、**先送りを拾いに来る者は居ない。** issue にするのは**現物へ
当て直して生きていたものだけ**——記録は当時の答えなので、そのまま信じると既に消えたものまで
issue になる。
