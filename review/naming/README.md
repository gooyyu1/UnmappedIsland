# 名前の検査

`src` 配下の全宣言について、**その宣言の責務を一言で言い、その一言が名前から読み取れるか**を見る。
[`review/placement/`](../placement/) が定義の**置き場**を見たのに対し、こちらは**名前**だけを見る。

## なぜ独立の観点にしたか

定義位置レビューでは、名前の妥当性を各明細表の**最終列（「名前不一致」）**に添えていた。結果、
**27件の指摘が打ち手の一覧（Candidates.md）へ持ち上がらず、段0〜段4のどのレーンにも入らなかった。**
補足の列に置いた指摘は拾われない。

## 判定

宣言1つにつき、責務を一言で書き、次のどれかに分ける。

| 判定 | 意味 | 打ち手 |
| ---- | ---- | ------ |
| **A** | 一言が名前をなぞるだけ | **何もしない。** これが良い状態——名前が責務を言い切っている証拠 |
| **B** | 一言が名前から読み取れない | **まず改名。** 名前にしてなお言い残す契約があるときだけコメントを足す |
| **C** | 名前が別のものを指している | 改名（Bより強い。読み手を誤った方向へ導く） |

**コメントが無いことは、それだけでは指摘にしない。** Aならコメントは要らない。指摘になるのは
B・Cで、そのときも第一手はコメントではなく改名。

**`private` かどうかは判定に使わない。** 外から呼ばれないぶん壊れる範囲は狭いが、読む人を誤解させる
量は変わらない（[`.claude/policies.md`](../../.claude/policies.md)「名前の付け方」）。

**名前に書くのは呼び手への契約だけ**で、隠している実装の中身は書かない。

## 進め方

1. `node scripts/declarationInventory.mjs --json` で全宣言を出す。`doc` フィールドが、その宣言に
   付いているドキュメントコメント（直前の `/** */` 1つ）。
2. **判定は名前とシグネチャだけで行う。** 本体を読むのは、名前から中身が類推できないときだけ
   ——読んでから判定すると「読めば分かる」に引きずられて、B・Cを見落とす。
3. 説明の無い宣言（1,437件）と、説明のある宣言（2,748件）は別の見え方をする。前者は「名前だけで
   足りているか」、後者は「その説明は名前の言い換えか、それとも名前が言えていないことか」。

そちら側から出ていたので、**残りのほうが収穫は大きい見込み**。
